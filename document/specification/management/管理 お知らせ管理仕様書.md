## 1. 概要

運営（オーナー・運営者）が1件のお知らせを書き、**どこに・どれくらい強く届けるか**を選んで公開する。

| 届け方 | 選び方 | 対象 | 今回 |
|---|---|---|:---:|
| TOP の「運営からのお知らせ」欄と、お知らせ一覧ページ | 公開したものは必ず載る | 全員（未ログインも） | ○ |
| ベル（通知）の未読に数える | チェック「ベルで通知する」 | 公開した時点の会員 | ○ |
| TOP の一番上の「重要なお知らせ」エリア | チェック「重要なお知らせとして出す」（終わり日時は任意） | 全員 | ○ |
| メールで送る | チェック「メールでも送る」 | 有効な会員 | 後日 |

### 1.1 今回作らないもの（後日）

送信元ドメイン（puremite.net）の DNS 設定と Resend の準備ができてから、次をまとめて足す。

- メール送信、「メールでも送る」チェック、自分宛てのテスト送信
- 配信停止（お知らせメールを受け取らない設定・メール内の配信停止リンク）
- メールを送る「有効な会員」の決め方（退会機能がまだ無いため）

今回は**メールのプレビュー（見え方）だけ**作る。メールの文面を作る処理も今回作り、後日の送信でそのまま使う。

あわせて今回作らないもの: 予約公開（決定3）、プッシュ通知（FCM 未実装）。

## 3. 管理者（オーナー・運営者）向け通知（ヘッダーベルアイコン）

### 3.1 概要

管理画面のヘッダーに常駐するベルアイコンを通じて、システムが自動生成した通知を管理者（オーナー・運営者）に届ける機能。

通知レコードは各機能のCloud FunctionsがFirestoreの`admin_notifications`コレクションに自動生成する。生成条件の詳細は各仕様書を参照すること。また、一般ユーザー向けのお知らせ公開時には、サイト内通知およびプッシュ通知が発行される（詳細は [/document/specification/page/ページ ユーザー通知機能仕様書.md](/document/specification/page/ページ ユーザー通知機能仕様書.md) を参照）。

| 通知種別 | 生成主体 | 通知対象 | 参照先 |
|---------|---------|---------|-------|
| 審査提出（Lv1） | Cloud Functions | アサインされた運営者 | /document/specification/構想/審査ワークフロー 二段階審査とAI運営者 構想.md 第12章（未実装。管理者向けの審査の通知は作っていない。管理 審査ワークフロー仕様書 §7） |
| 審査Lv2移行 | Cloud Functions | オーナー | /document/specification/構想/審査ワークフロー 二段階審査とAI運営者 構想.md 第12章（未実装。管理者向けの審査の通知は作っていない。管理 審査ワークフロー仕様書 §7） |
| クォータ超過 | Cloud Functions（動画更新バッチ） | **オーナーのみ** | /document/specification/management/管理 モニタリング・不正監視仕様書.md 第5章 |
| 不正レビュー検知 | Cloud Functions（Firestoreトリガー） | **オーナーのみ** | /document/specification/management/管理 モニタリング・不正監視仕様書.md 第5章 |
| 新規お問い合わせ | ユーザーの送信 | オーナー・運営者全員 | /document/specification/management/管理 お問い合わせ管理仕様書.md 第5章 |
| お問い合わせ返信 | ユーザーの返信 | オーナー・運営者全員 | /document/specification/management/管理 お問い合わせ管理仕様書.md 第5章 |
| お問い合わせ再オープン | ユーザーの再オープン | オーナー・運営者全員 | /document/specification/management/管理 お問い合わせ管理仕様書.md 第5章 |

### 3.2 ベルアイコンの表示仕様

管理画面の全画面共通ヘッダーにベルアイコンを配置する。

| 状態 | 表示 |
|------|------|
| 未読通知あり | ベルアイコン＋未読件数バッジ（赤丸）を表示 |
| 未読通知なし | ベルアイコンのみ表示（バッジなし） |

- 未読件数バッジは99件を上限とし、100件以上の場合は「99+」と表示する。
- ベルアイコンをクリックすると通知ドロップダウンを展開する。

### 3.3 通知ドロップダウン

#### 表示件数

未読通知のみを最大10件表示する。10件を超える場合は「すべて見る」リンクを表示し、通知一覧ページへ遷移する。

#### ドロップダウンの構成

```
┌────────────────────────────────────┐
│ 通知                  すべて既読にする │
├────────────────────────────────────┤
│ 🔴 不正レビュー検知                  │
│    ユーザー〇〇が異常な投稿を行いました │
│    3分前                            │
├────────────────────────────────────┤
│ 🔴 審査提出（Lv1）                   │
│    再生リスト登録提案が提出されました   │
│    1時間前                          │
├────────────────────────────────────┤
│ ...                                │
├────────────────────────────────────┤
│         すべて見る →               │
└────────────────────────────────────┘
```

#### 通知1件あたりの表示要素

| 要素 | 内容 |
|------|------|
| 未読インジケーター | 未読の場合は赤丸を表示。既読の場合は非表示 |
| 通知種別 | 通知の種別名（例：不正レビュー検知・審査提出） |
| 通知内容 | 通知の概要テキスト。最大2行、超過時は省略記号（…）で切り詰め |
| 経過時間 | 通知生成からの経過時間（例：3分前・1時間前・2日前） |

#### クリック時の動作

| 操作対象 | 動作 |
|---------|------|
| 通知1件をクリック | 個別既読にし、関連画面へ遷移する |
| 「すべて既読にする」をクリック | ドロップダウン内の全件を既読にする |
| 「すべて見る」をクリック | 通知一覧ページへ遷移する |
| ドロップダウン外をクリック | ドロップダウンを閉じる |

#### 通知種別ごとの遷移先

| 通知種別 | 遷移先 |
|---------|-------|
| 審査提出（Lv1） | 該当ワークフロー詳細画面 |
| 審査Lv2移行 | 該当ワークフロー詳細画面 |
| クォータ超過 | モニタリング画面（YouTube APIクォータモニター） |
| 不正レビュー検知 | 不正監視画面（異常検知一覧） |
| 新規お問い合わせ | 該当お問い合わせ詳細画面 |
| お問い合わせ返信 | 該当お問い合わせ詳細画面 |
| お問い合わせ再オープン | 該当お問い合わせ詳細画面 |

### 3.4 通知一覧ページ

「すべて見る」から遷移する、管理者（オーナー・運営者）向け通知の全件一覧ページ。

#### 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ 通知一覧                          [ すべて既読にする ]        │
│                                                             │
│ [ 通知種別 ▼ ]  [ 既読状態 ▼ ]                              │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ ● 不正レビュー検知  ユーザー〇〇が…  2026-03-08 14:32   │ │
│ │ ● 審査提出（Lv1）  再生リスト登録提案が…  1時間前        │ │
│ │   クォータ超過      クォータ超過が発生…  2026-03-07      │ │
│ │ ...                                                     │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ 20件表示 ▼                    ← 1 2 3 ... →               │
└─────────────────────────────────────────────────────────────┘
```

#### 絞り込み条件

| 条件 | 種別 |
|------|------|
| 通知種別 | ドロップダウン（審査提出・審査Lv2移行・クォータ超過・不正レビュー検知・新規お問い合わせ・お問い合わせ返信・お問い合わせ再オープン） |
| 既読状態 | ドロップダウン（すべて・未読のみ・既読のみ） |

- 複数条件を指定した場合はAND条件で絞り込む。

#### 一覧テーブルの表示項目

| 列 | 内容 |
|----|------|
| 未読インジケーター | 未読の場合は●を表示 |
| 通知種別 | 通知の種別名 |
| 通知内容 | 通知の概要テキスト（1行、超過時は省略記号で切り詰め） |
| 通知日時 | 通知が生成された日時 |

- 行をクリックすると個別既読にし、関連画面へ遷移する。
- デフォルトのソート順は通知日時の降順（新しい順）。

#### ページネーション

| 項目 | 仕様 |
|------|------|
| デフォルト表示件数 | 20件 |
| 切り替え可能な表示件数 | 20 / 50 / 100件 |
| 切り替えUI | リスト右上にセレクトボックスで配置（例：「20件表示 ▼」） |
| ページ送りUI | リスト下部にページ番号リンク形式で配置 |

### 3.5 既読管理の仕様

| 操作 | 対象 | 動作 |
|------|------|------|
| 個別既読 | ドロップダウンまたは一覧の1件をクリック | 該当通知の既読フラグをONにする |
| 一括既読 | 「すべて既読にする」ボタンをクリック | 自分宛ての未読通知をすべて既読にする |

- 既読にした通知は取り消し（未読に戻す）できない。
- 既読状態は管理者（オーナー・運営者）アカウントごとに独立して管理する（Aさんが既読にしてもBさんの未読状態には影響しない）。

## 4. データ

### 4.1 `notices/{noticeId}`

| フィールド | 型 | 説明 |
|---|---|---|
| `title` | string | タイトル（必須、最大50文字） |
| `body` | string | 本文（必須、最大2,000文字、改行そのまま） |
| `attachmentType` | string | `none`（添付なし）/ `link`（テキストリンクのみ）/ `image_link`（画像付きテキストリンク）/ `youtube`（YouTube 動画） |
| `linkLabel` | string? | リンクの文言（`link`・`image_link` で必須、最大30文字） |
| `linkUrl` | string? | リンク先（`link`・`image_link` で必須。`https://` か、サイト内の `/` で始まるパス） |
| `imageFileName` | string? | 画像のファイル名（`image_link` で必須）。Cloud Storage `notices/{20文字}.webp`。配信は `/api/notices/image/{ファイル名}` |
| `youtubeVideoId` | string? | YouTube 動画ID（`youtube` で必須。貼られた URL から取り出す） |
| `youtubeUrl` | string | 貼られた YouTube の URL（編集画面にそのまま戻すため） |
| `notifyBell` | boolean | ベルで通知する |
| `important` | boolean | 重要なお知らせとして出す |
| `importantUntil` | Timestamp? | 重要エリアに出す終わり日時（任意。空ならチェックを外すまで） |
| `memo` | string | 備考（運用メモ、最大1,000文字。管理画面でだけ見える） |
| `status` | string | `draft`（下書き）/ `published`（公開中）/ `unpublished`（非公開） |
| `publishedAt` | Timestamp? | 最初に公開した日時。表示日・並び順に使う。非公開→再公開でも変えない |
| `bellSentAt` | Timestamp? | ベル通知を作った日時（1回だけ作るための印） |
| `bellSentCount` | number? | ベル通知を作った人数 |
| `createdBy` / `updatedBy` | string | 作成者・最終更新者の userId |
| `createdAt` / `updatedAt` | Timestamp | 作成・最終更新日時 |

- 添付の種類を切り替えて保存したら、使わない項目は空にする（画像を外したら Storage の画像も消す）。
- 旧フィールド（`targetPages`・`startAt`・`endAt`・`sendPushNotification`・`scheduled`・`archived`）は使わない。今はデータが無いので移行は要らない。

### 4.2 読み書きの経路

- Firestore ルールの `notices` は「管理者だけ読める・クライアントからは書けない」（v1.4 までは公開中なら誰でも読めたが、備考を見せないため）。
- 利用者側は API（`/api/notices/*`）から読む。公開中のものだけを、備考・作成者などを除いて返す（`lib/notice-server.ts`）。
- 管理画面の読み込みはクライアント SDK（`lib/notice-admin.ts`）、書き込みは管理 API（`/api/admin/notices/*`）。
- 画像は Storage に置き、クライアントからは直接読ませない。配信は `GET /api/notices/image/{fileName}`。ファイル名は推測できない20文字なので、ファイルがあれば返す（下書きのプレビューやメールソフトからも同じ URL で見られるように）。画像を差し替え・外して保存したら前の画像を消す。選んだだけで保存しなかった画像は残る（どこからも参照されない）。

### 4.3 ベル通知 `notifications`

公開したとき `notifyBell` が ON で、まだ `bellSentAt` が無ければ、その時点の `users` 全員に1件ずつ作る（決定6）。

| フィールド | 値 |
|---|---|
| `userId` | 会員の uid |
| `type` | `notice` |
| `noticeId` | お知らせの ID |
| `title` | 公開した時点のタイトル |
| `isRead` | false |
| `createdAt` | 公開日時 |

- 1件につき1回だけ。公開後に直しても、非公開→再公開しても作り直さない（決定2）。
- 通知のIDは `notice_{お知らせID}_{会員ID}` に決める。作る途中で失敗したら、お知らせを下書きに戻し（`publishedAt`・`bellSentAt` も空に戻す）、編集画面に「ベルの通知を作る途中で失敗したため、下書きに戻しました。もう一度「公開する」を押してください」を出す。やり直しても同じIDに書くので、同じ人に2通は届かない。
- 公開した後に「ベルで通知する」に変えても通知は作らない（編集画面で「公開後は変えられません」と出してチェックを無効にする）。

## 5. 状態と操作

```
[下書き] ──公開する──▶ [公開中] ──非公開にする──▶ [非公開]
   │                      ▲                          │
   └─削除                 └──────もう一度公開する───────┘
```

| 状態 | 押せるボタン | 補足 |
|---|---|---|
| 下書き | 下書き保存・公開する・削除 | 削除は確認ダイアログ「この下書きを削除しますか？」→ 物理削除（画像も消す） |
| 公開中 | 保存（変更を反映）・非公開にする | 保存すると TOP・一覧・詳細にすぐ反映。ベルは送り直さない |
| 非公開 | 保存・もう一度公開する | 利用者からは見えない（TOP・一覧・詳細とも）。ベルは送らない |

- 公開したもの（公開中・非公開）は削除できない（履歴として残す）。
- 「公開する」は確認ダイアログを出す: 「このお知らせを公開します。TOPの運営からのお知らせ欄に載ります。」に、ON の項目だけ「ベルで N 人に通知します」「TOP の一番上に重要なお知らせとして出します（{終わり日時}まで）」を足す。ボタン「公開する」「キャンセル」。
- 「非公開にする」も確認ダイアログ: 「非公開にすると、TOPとお知らせ一覧から消えます。届いたベルの通知は残りますが、開くと『このお知らせは公開を終了しました』と出ます。」

## 6. 管理画面

### 6.1 ナビ

管理画面ヘッダーのナビに「お知らせ」（`/admin/notices`）を足す（お問い合わせの後）。

### 6.2 お知らせ一覧 `/admin/notices`

```
お知らせ                                         [ ＋ 新規作成 ]
[ すべて 3 | 下書き 1 | 公開中 1 | 非公開 1 ]
┌────────────────────────────────────────────────┐
│ 公開中  🔔 12人  重要                 公開日 2026/11/20 │
│ メンテナンスのお知らせ                                  │
│ 更新 2026/11/20（運営A）                                │
└────────────────────────────────────────────────┘
```

PC・スマートフォンとも1件1カード（お問い合わせ一覧など管理画面の他の一覧と同じ形）。

| 項目 | 内容 |
|---|---|
| 状態 | 下書き・公開中・非公開のバッジ |
| タイトル | 押すと編集画面へ |
| 届け方 | ベル（送った人数も。例「🔔 12人」）・重要（終わり日時を過ぎていれば「重要（終了）」） |
| 公開日 | `publishedAt`。下書きは「—」 |
| 更新日 | `updatedAt`（更新者の表示名も小さく） |

- 並びは更新日の新しい順。状態のタブ（件数つき）で絞り込み。20件ずつページ送り。カードを押すと編集画面へ。

### 6.3 作成・編集 `/admin/notices/new`・`/admin/notices/[noticeId]`

PC は左に入力欄、右にプレビュー。スマートフォンは入力欄の下にプレビュー。

**入力欄（上から順に）**

| 項目 | 種類 | 必須 | 仕様 |
|---|---|:---:|---|
| タイトル | 1行 | ○ | 50文字まで。残り文字数を出す |
| 本文 | 複数行 | ○ | 2,000文字まで |
| 添付の種類 | ラジオ | ○ | 添付なし / テキストリンクのみ / 画像付きテキストリンク / YouTube 動画（既定: 添付なし） |
| リンクの文言・URL | 1行×2 | ○ | テキストリンク・画像付きのときだけ出す |
| 画像 | ファイル選択 | ○ | 画像付きのときだけ出す。PNG・JPEG・WebP、5MB まで、1枚（決定7）。描き直して横幅最大1200px の WebP で保存 |
| YouTube 動画の URL | 1行 | ○ | YouTube のときだけ出す。`youtube.com/watch?v=`・`youtu.be/`・`youtube.com/shorts/` を受け付け、動画IDを取り出す。どの動画でもよい（決定7） |
| 届け方 | チェック | — | 「ベルで通知する（会員のベルの未読に数えます）」「重要なお知らせとして出す（TOPの一番上に目立つ枠で出します）」 |
| 重要の終わり日時 | 日時 | — | 「重要」に ON のときだけ出す。空なら「チェックを外すまで出します」と添える（決定4） |
| 備考 | 複数行 | — | 1,000文字まで。「運用メモ。利用者には見えません」 |

- 「メールでも送る」は今回は出さない（決定1）。
- 下部に状態ごとのボタン（第5章）。編集中に離れようとしたら「保存していない変更があります」の確認を出す。

**バリデーション**

| チェック | メッセージ |
|---|---|
| タイトルが空 | 「タイトルを入力してください」 |
| タイトルが50文字超 | 「50文字以内で入力してください」 |
| 本文が空 | 「本文を入力してください」 |
| 本文が2,000文字超 | 「2,000文字以内で入力してください」 |

| 画像が無い | 「画像を選んでください」 |

### 6.4 プレビュー（2種類）

タブ「TOPでの見え方」「メールでの見え方」で切り替える。入力に合わせてその場で変わる。

- **TOPでの見え方**: ①TOP の「運営からのお知らせ」欄の1行、②「重要」ON なら重要エリアの枠、③お知らせ詳細ページ（本文と添付）。実際の部品をそのまま使って描く。
- **メールでの見え方**: 件名「{タイトル} | プレミテ」、差出人「プレミテ」、本文（第9章の文面）。上に「メール送信は準備中です。見え方の確認だけできます」と出す。

## 7. 利用者側の表示

### 7.1 TOP の重要なお知らせエリア（決定4・5）

- 場所: TOP の一番上（未ログインはヒーローの上、ログイン中はマイリストの上）。
- 出すもの: 公開中で `important` が ON、かつ終わり日時が無いか今より後のもの。新しい順に全部（ふつうは1件）。
- 見た目: 目立つ色の枠（注意の黄色系。デザイントークンに足す）に「重要」ラベル・タイトル・本文の先頭2行・「詳しく見る」→ お知らせ詳細。右上に閉じる（×）。
- ×で閉じたら、その端末（ブラウザの localStorage）にお知らせ ID を覚え、次から出さない。ベルの既読とは別。

### 7.2 TOP の「運営からのお知らせ」欄（決定5）

- 場所: TOP の一番下（タグピックアップの後）。ログイン・未ログインとも。
- 見出し「運営からのお知らせ」＋右に「すべて見る」→ `/notices`。
- 最新3件（公開日の新しい順）を「日付（2026/11/20）＋タイトル」の行で。重要なものは行の頭に「重要」ラベル。押すとお知らせ詳細。
- 公開中が0件ならセクションごと出さない。

### 7.3 お知らせ一覧 `/notices`

- 見出し「運営からのお知らせ」。公開中を公開日の新しい順に、TOP 欄と同じ行の形で20件ずつ、下に「もっと見る」。
- 0件: 「お知らせはまだありません」。
- フッター（PC）とハンバーガーメニュー（スマートフォン）の「サポート」に「お知らせ」リンクを足す。

### 7.4 お知らせ詳細 `/notices/[noticeId]`

- 日付・（重要なら）「重要」ラベル・タイトル・本文（改行そのまま、URL は自動でリンクにしない）。
- 添付:
  - テキストリンク: 本文の下にボタン風のリンク「{リンクの文言}」。外部 URL は新しいタブで開く。
  - 画像付きテキストリンク: 画像（押すとリンク先へ）＋その下にリンク。
  - YouTube: 16:9 の埋め込みプレーヤー（youtube-nocookie.com）。
- 下に「お知らせ一覧へ戻る」。
- 非公開・存在しない ID: 「このお知らせは公開を終了しました」＋「お知らせ一覧へ」（ベルから開いた人向け）。
- ページの title は「{タイトル} | プレミテ」。

### 7.5 ベルと通知一覧（決定6）

- ベルの件数・通知一覧に `type: notice` を出す（ページ ユーザー通知機能仕様書 §2.1 お知らせ通知を実装）。
- 通知一覧に「お知らせ」タブを出す（同 §5）。カードは種別ラベル「お知らせ」＋タイトル。押すと既読にしてお知らせ詳細へ。
- 遷移先は v1.8 の「トップページ」から「お知らせ詳細」に変える。

## 8. API

| API | 誰が | 内容 |
|---|---|---|
| `GET /api/notices?limit=&before=` | 誰でも | 公開中の一覧（公開日の新しい順、最大20件）。TOP は `limit=3`。`before` は前のページの最後の公開日 |
| `GET /api/notices/important` | 誰でも | 重要エリアに今出すもの |
| `GET /api/notices/{id}` | 誰でも | 公開中の1件（非公開・下書き・無しは 404） |
| `GET /api/notices/image/{fileName}` | 誰でも | 画像の配信 |
| `POST /api/admin/notices` | 管理者 | 下書きで作る |
| `PATCH /api/admin/notices/{id}` | 管理者 | `action`: `save`（保存）／`publish`（今の入力を保存して公開する・もう一度公開する。初回で `notifyBell` ならベル通知を作り、作った人数を返す）／`unpublish`（非公開にする） |
| `DELETE /api/admin/notices/{id}` | 管理者 | 下書きの削除（公開したものは 409） |
| `POST /api/admin/notices/images` | 管理者 | 画像を置いてファイル名を返す（紐づけは保存・公開のとき） |

- 管理画面の一覧・1件の読み込みはクライアント SDK で行う（§4.2）。メールの文面は画面の中で作って見せる（`lib/notice-email.ts`、送信はしない）。

- TOP の重要エリア・お知らせ欄は、TOP の再生リストと同じ応答（`/api/catalog/top`）に含めず、別の API で取る（お知らせを直したらすぐ反映させたいので、カタログのキャッシュと分ける）。
- 操作ログ（`operation_logs`）は他の管理機能でもまだ作っていないので、今回は残さない。誰がいつ直したかは `updatedBy`・`updatedAt` で見る。
