## 1. 概要

> **v3.0（2026-11-01）リブランディング**: 収集の品質の関門を「再生リスト1件ずつの承認」から「チャンネルを認定するかどうか」に移した（コンテンツ収集機能仕様書 v4.0 第10章）。これに合わせ、段階4の実装で次のように画面を変える。
> - 「収集候補」（第3〜5章の承認画面）→ **「自動掲載の確認」**（第8章）。認定チャンネルの巡回で取り込んだ再生リストを、掲載状態ごとに確認・切り替える。
> - 「探索対象チャンネル」（第6章）→ **「認定チャンネル」**（第9章）。掲載方法（自動／確認）・認定を外す・掲載を止めるを足す。
> - 「ゲーム未設定」の画面（PR #14 v2.5 §6.5）はそのまま使う。
> 第3〜6章は段階4の実装までの現行仕様として残す。

本仕様書は、コンテンツ収集（管理_Ai運営者 コンテンツ収集機能仕様書）が `collection_candidates` に保存した再生リスト候補を、管理者が確認・承認・却下する管理画面と、探索の起点となる「探索対象チャンネル」を管理する画面を定義する。

v2.0（2026-10-26）で、チャンネル起点の探索（コンテンツ収集機能仕様書 v3.0 §3）に合わせて全面改訂した。候補が数百〜数千件になるため、**チャンネル単位でまとめて承認する**操作を主とする。AI判定（フラグ・コメント）は Gemini 導入後に追加する（将来）。

### 1.1 画面の位置

管理画面のヘッダーナビゲーションに「コンテンツ収集」を追加する。

| 画面 | パス |
|------|------|
| 収集候補 | `/admin/collection` |
| 探索対象チャンネル | `/admin/collection/channels` |

| 操作 | オーナー | 運営者 |
|------|:---:|:---:|
| 収集候補の閲覧・承認・却下 | ○ | ○ |
| 探索の実行 | ○ | ○ |
| 探索対象チャンネルの登録・確定・除外 | ○ | ○ |

> v1.x ではオーナー専用としていたが、管理画面の他機能と同じく管理者（オーナー・運営者）に開く。現状の管理者はオーナー1名のため実質の差はない。オーナー限定に戻すかはコンテンツ収集機能仕様書 §9 の検討事項とする。

### 3.2 タブ

| タブ | 表示対象 |
|------|---------|
| 未処理 | `status: pending`（既定） |
| 登録済み | `status: registered` |
| 却下済み | `status: rejected` |

### 3.3 絞り込み

| 条件 | 種別 |
|------|------|
| チャンネル | ドロップダウン（候補のあるチャンネル） |
| ゲーム推定 | すべて／推定あり／推定なし |

### 3.4 一覧の表示

候補を**チャンネルごとにまとめて**表示する。チャンネル内は再生リストの作成日時の新しい順。

| 表示項目 | 内容 |
|---------|------|
| チェックボックス | 未処理・却下済みタブ。承認・却下（却下済みタブでは未処理に戻す）の対象を選ぶ |
| サムネイル | 再生リストのサムネイル（16:9）。クリックで YouTube の再生リストを別タブで開く |
| 再生リストタイトル | — |
| 動画数 | `N本` |
| ゲーム | 推定・選択済みのゲームタイトル名。無ければ「新規」の印と、承認時に登録するゲーム名の入力欄（初期値は `gameQuery`）、「既存から選ぶ」ボタン（§3.5） |
| タグ | 承認時に付けるタグ（チャンネル単位タグ＋タイトル由来タグ）。×で外せる |

- チャンネル見出しに「全選択」チェックボックスを置く。v2.1 から推定なしの候補もまとめて選べる（ゲーム名の入力欄が空のものだけ選べない）。
- 一覧の上に「ゲームが推定できなかった候補は『新規』の欄の名前でゲームタイトルを登録してから承認する。ゲームではない再生リストはチェックを外すか却下する」旨の案内を出す。
- 一覧は1チャンネルずつ折りたたみ可能とし、ページネーションは行わない（チャンネル単位で処理する前提）。

### 3.5 ゲームの選択（推定なし・推定の変更）

推定なしの候補には、承認時に登録するゲーム名の入力欄を出す。初期値は候補の `gameQuery`（コンテンツ収集機能仕様書 §3.4）で、その場で書き換えられる。承認時の扱いは §4.3。

> v2.0 では推定なしの候補は1件ずつゲームを選ぶ（または登録する）まで承認できなかった。stg の試運転で、有名チャンネル3つの候補441件がすべて推定なし（stg のゲームタイトルが21件しかなく照合先が無い）になり、1件ずつの操作で承認しきれなかったため、v2.1 で名前のままのまとめて承認を主にした。再生リスト名はほとんどがゲーム名そのものなので、`gameQuery` をそのまま使えることが多い。

既存のゲームに結び付けたいとき・楽天ブックスの商品を自分で選びたいときは、「既存から選ぶ」（推定ありの場合はゲーム名のクリック）で、管理者用の再生リスト登録と同じゲームタイトル選択モーダル（GameSelectModal）を開く。

- 見つからない場合は、フッターの導線からゲームタイトル新規登録モーダル（GameCreateModal）を開く。このとき候補の `gameQuery`（コンテンツ収集機能仕様書 §3.4）を**楽天ブックス検索欄に入れた状態で開き、自動で検索する**。タイトル名欄にも同じ語句を入れておく。
- 楽天ブックスに無いゲームは、検索結果を使わずタイトル名だけで登録できる（パッケージ画像は後でゲームタイトル詳細から足す）。
- 選んだ・登録したゲームはその候補に保持され、チェックが自動で入る。

### 3.6 探索を実行

「探索を実行」ボタンで、`status: active` の探索対象チャンネル全件を探索する（コンテンツ収集機能仕様書 §3.2）。実行中はボタンをローディング表示にし、完了後に「チャンネルN件を探索し、新しい候補をM件追加しました」をトーストで表示して一覧を再読み込みする。クォータの1日上限を超える場合はエラーを表示する。

## 4. まとめて承認

### 4.1 フロー

```
候補にチェックを入れる（ゲームが決まっているもの、または新規のゲーム名があるもの）
    ↓
下部バーの「選択を承認して登録」
    ↓
確認ダイアログ「N件を登録します。（新規のゲーム名があれば）次のゲーム名は、同じ名前のゲームタイトルが無ければ新しく登録します（M件）: ・名前…（10件まで、残りは「ほかK件」） よろしいですか？」
    ↓
1件ずつ順に登録（20件ずつ、新規のゲーム名を含む候補は5件ずつAPIに送り、進捗「12 / 30 件」を表示）
  ⓪ 新規のゲーム名なら、ゲームタイトルを用意する（§4.3）
  ① チャンネルが未登録なら channels を新規作成
  ② playlists・videos を登録（管理者用の再生リスト登録と同じ内容）
  ③ タグを固定タグとして付与し、usagePlaylistCount を加算
  ④ 候補を registered に更新（reviewedAt・reviewedBy・registeredPlaylistId）
    ↓
結果をトースト表示（成功N件・追加したゲームタイトルK件・失敗M件）。失敗した候補は未処理のまま残し、理由を行に表示する
```

### 4.2 ルール

- **ゲームタイトルは必須**。ゲームが決まっておらず、新規のゲーム名も空（または100文字超・記号だけ）の候補はチェックボックスを非活性にする。
- API は1回の呼び出しで最大50件まで受け付ける。画面からは20件ずつ送り、新規のゲーム名を含む候補は5件ずつにする。新規のゲームは楽天ブックスの検索とジャンルの解決に1件2秒ほどかかり、Firebase Hosting 経由のリクエストは60秒で打ち切られるため。楽天ブックスAPIの呼び出しは10秒で打ち切り、名前だけの登録に切り替える。
- 登録時に YouTube 側で非公開・削除になっていた場合は失敗として扱い、候補を `rejected`（`reviewComment: "not_public"` 等）にする。
- 既に `playlists` に存在した場合（別経路で登録済み）は、候補を `registered` にして成功扱いとする。

### 4.3 新規のゲーム名の扱い

承認API（`POST /api/admin/collection/candidates`、`action: approve`）の各項目は `gameId` か `newGameTitle` のどちらかを持つ。`newGameTitle` の項目は、登録の前に次の順でゲームタイトルを用意する。

1. 登録済みのゲームタイトルのタイトル（`games.title`）または別名（`games.aliases`）と、コンテンツ収集機能仕様書 §3.4 と同じ正規化（NFKC・小文字化・空白と記号の除去）で**完全一致**するものがあれば、それを使う（新規登録しない）。タイトルでの一致を別名での一致より優先する。
2. 無ければ楽天ブックスをその名前で検索し、商品名を正規化（ゲームタイトル新規登録の自動入力と同じく、限定版・機種名などの表記を除いたうえで上と同じ正規化）して**完全一致**する商品があれば、パッケージ画像・商品ページURL・機種（固定候補にあるもののみ）・ジャンル・テーマ（マスタと名前が一致するもののみ）を入れる。楽天ブックスAPIのレートリミット（1秒1回）に合わせて間隔をあける。
3. 一致する商品が無い・楽天の呼び出しに失敗した場合は、**名前だけで**登録する。パッケージ画像などは後でゲームタイトル詳細の編集から足す。
4. ゲーム名は入力欄の名前をそのまま使う（楽天の商品名には置き換えない）。同じ承認の中で同じ名前（正規化後）が複数あっても、登録は1回にして同じゲームに結び付ける。

- 新規登録したゲームタイトルは API の結果（`createdGame`）で画面に返し、残りの候補の推定（§3.4 の再推定）にすぐ使う。
- 新規登録したゲームタイトルに、同じ承認リクエストで再生リストが1件も登録できなかった場合（非公開・削除で却下、登録の失敗、別経路で登録済み）は、そのゲームタイトルを消す（ジャンル・テーマの件数も戻す）。再生リスト0件のゲームタイトルが一覧に残らないようにするため。
- 同じ名前を含む承認を、別のタブ・別の管理者が同時に送った場合の重複登録は防がない（管理者が1名の現状では起きにくい。起きたらゲームタイトルの編集・削除で直す）。

## 5. 却下

- 下部バーの「選択を却下」で、選択中の候補を `rejected` にする（確認ダイアログあり）。
- 却下済みタブから「未処理に戻す」ことができる（誤操作の復旧用）。
- 却下した候補は、次回以降の探索でも再び候補にならない（コンテンツ収集機能仕様書 §3.3）。

## 6. 探索対象チャンネル画面

### 6.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ ← 収集候補に戻る                                             │
│ 探索対象チャンネル                                           │
│                                                             │
│ ┌ チャンネルを追加 ─────────────────────────────────────┐   │
│ │ 名前（1行1件）、またはチャンネルURL・@ハンドル         │   │
│ │ [テキストエリア                                    ]   │   │
│ │                                        [追加する]      │   │
│ └───────────────────────────────────────────────────────┘   │
│                                                             │
│ [確認待ち 12] [未特定 40] [探索中 25] [除外 3]               │
│ 未特定タブ: [名前からまとめて特定（最大40件・約4,000ユニット）]│
│                                                             │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ キヨ（wiki）                                          │   │
│ │ 候補: ○[icon] キヨ。 登録者 300万人  [確定]           │   │
│ │       ○[icon] キヨ切り抜き  登録者 2万人             │   │
│ │ [URLで指定] [除外]                                    │   │
│ └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち | `pending_confirm` | 候補から1件を選んで「確定」／「URLで指定」／「除外」 |
| 未特定 | `unresolved` | 「名前からまとめて特定」（上限件数ずつ）／個別に「URLで指定」／「除外」 |
| 探索中 | `active` | チャンネル単位タグの編集／「このチャンネルだけ探索」／「除外」。最終探索日時・前回の新規候補数を表示 |
| 除外 | `excluded` | 「未特定に戻す」 |

### 6.3 チャンネルの追加

- テキストエリアに1行1件で入力する。行が YouTube のチャンネルURL・`@ハンドル`・`UC` で始まるチャンネルIDなら、その場で特定して `active` で追加する（1ユニット）。それ以外は名前として `unresolved` で追加する（クォータ消費なし）。
- 同じ名前・同じチャンネルIDが既にある行はスキップし、結果に「重複N件」と表示する。

### 6.4 チャンネル単位のタグ

`active` のチャンネルごとに「タグを設定」から、運営者タグ（`origin: operator`）をカテゴリ別（実況スタイル系・プレイスタイル系・編集スタイル系）のチップで選ぶ。ここで選んだタグは、そのチャンネルの候補の承認時に付与される（コンテンツ収集機能仕様書 §3.5）。既に保存済みの候補にも、一覧表示の時点で反映する。

## 8. 自動掲載の確認画面（段階4）

コンテンツ収集機能仕様書 §10.4 で判定した再生リストを、運営が確認・切り替える画面。今の「収集候補」画面（第3章）を置き換える。パスは `/admin/collection`（今の収集候補と同じ）。

### 8.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ コンテンツ収集                                               │
│ [ 自動掲載の確認 ] [ 認定チャンネル ] [ ゲーム未設定 ]  ← 大きなタブ │
│                                                             │
│ ┌ 巡回の状況 ───────────────────────────────┐             │
│ │ 最終巡回: 2026-11-10 04:00  新しい再生リスト 24件          │ │
│ │ 本日のAPI消費: 340 / 6,000 ユニット                        │ │
│ └───────────────────────────────────────────┘             │
│                                                             │
│ [確認待ち 18] [掲載中] [ゲームではない] [対象外] [10本未満] [チャンネル対象外] │
│ [ チャンネル ▼ ]  [ ゲーム: すべて／付いている／未設定 ▼ ]          │
│                                                             │
│ ━ キヨ。（確認待ち 6件・確認してから掲載） ━━━━━━━━━━━━━━━━━━ │
│ [□ 全選択]                                                    │
│ □ [サムネ] 【ゼルダ】初見で…  12本  ゲーム: ゼルダの伝説…  [動画一覧を見る] │
│            判定: ルールに当たらず確認待ち                     │
│ □ [サムネ] 【雑談】まったり…   30本  判定: 非ゲーム語「雑談」   │
│ …                                                           │
│ ┌ 下部固定バー ───────────────────────────────────────────┐ │
│ │ 選択中 6件  [掲載する] [ゲームではない] [対象外にする]       │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 タブ（掲載状態）

| タブ | 表示対象 | 主な操作 |
|------|---------|---------|
| 確認待ち（既定） | `unconfirmed` | 掲載する／ゲームではない／対象外にする |
| 掲載中 | `listed` | ゲームではない／対象外にする（掲載から外す） |
| ゲームではない | `non_game` | 掲載する（掲載に戻す）／対象外にする |
| 対象外 | `excluded` | 掲載する／ゲームではない |
| 10本未満 | `too_short` | 掲載する（10本未満でも出す）／対象外にする |
| チャンネル対象外 | `channel_off` | 操作なし（チャンネルを認定し直す・掲載停止を解くのは第9章） |

- 各タブの件数を出す。「確認待ち」の件数は管理画面ヘッダーのタブにもバッジで出す（気づかないまま溜めないため）。
- 一覧はチャンネルごとにまとめ、見出しにチャンネル名・件数・掲載方法（自動／確認）を出す。チャンネル内は再生リストの作成日時の新しい順。

### 8.3 行の表示と操作

| 項目 | 内容 |
|------|------|
| サムネイル・タイトル・動画数・作成日 | 第3章と同じ |
| 動画一覧を見る（YouTube） | YouTube の再生リストのページを別タブで開く（PR #14 v2.3 §3.8 と同じ） |
| 判定 | 判定の理由（`listingReason`）。例「非ゲーム語『雑談』」「10本未満（7本）」「ルールに当たらず確認待ち」。人が決めたものは「管理者が決定（日時）」 |
| ゲーム | 推定・紐づけ済みのゲーム名、または「ゲーム未設定（ヒント: ○○）」。押すとゲームを選ぶ／新規登録して付ける（PR #14 v2.5 §6.5 と同じ操作。楽天ブックスの商品選び（PR #14 v2.2 §3.7）もここで使える）。**ゲームを決めなくても掲載できる** |
| タグ | 掲載するときに付けるタグ（チャンネル単位タグ＋タイトル由来タグ）。×で外せる |

- チェックボックスで複数選び、下部バーでまとめて切り替える（確認ダイアログあり）。行ごとの操作ボタンも置く。
- 切り替えた再生リストは `listingSetBy: admin` になり、以後の自動の判定し直しで上書きされない。
- **掲載する**: `listed` にし、動画一覧（全件）と再生時間を取得し、タグを固定タグとして付け、件数（`games.playlistCount` など）を足す（今の承認の ②③ と同じ処理。クォータの扱いもコンテンツ収集機能仕様書 §4.2 と同じく小分けに送る）。YouTube 側で非公開・削除になっていたら失敗として行に理由を出す。
- **ゲームではない／対象外にする**: 掲載中だったものは検索面から外れ、件数を戻す。動画・レビュー・マイリストは消さない（マイリスト・視聴履歴からは開ける。コンテンツ収集機能仕様書 §10.7）。

### 8.4 判定の言葉の表

画面の右上に「判定の言葉」ボタンを置き、除外語・非ゲーム語・最小本数（`app_settings/listing_rules`、コンテンツ収集機能仕様書 §10.5）を編集するモーダルを開く。

- 言葉はチップで追加・削除する。保存すると次の巡回から新しく取り込む再生リストに使う。
- 「判定し直す」ボタンで、自動で決めた（`listingSetBy: auto`）再生リストすべてを新しい表で判定し直す。人が決めたものは変えない。結果（変わった件数を状態ごとに）をトーストで出す。

### 8.5 一般ユーザーの「ゲームじゃない」報告（将来）

掲載中の再生リストがゲーム実況でない場合の報告は、既存の再生リスト通報（審査ワークフロー仕様書 §3）の理由に「ゲーム実況ではない」を足す形で受ける。実装は段階4以降の検討とする。

## 9. 認定チャンネル画面（段階4・6）

今の「探索対象チャンネル」画面（第6章）を「認定チャンネル」画面に改める。パスは `/admin/collection/channels`（今と同じ）。第6章の追加・特定・確定・除外・チャンネル単位タグはそのまま使い、次を足す。

### 9.1 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち・未特定 | `pending_confirm`・`unresolved` | 第6章と同じ（確定すると認定になる） |
| 認定済み（旧: 探索中） | `active` | 掲載方法の切り替え／チャンネル単位タグ／表示順／このチャンネルだけ巡回／認定を外す／掲載を止める |
| 認定しない（旧: 除外） | `excluded` | 認定する（`active` に戻す。再生リストは元の掲載状態に戻る） |
| 掲載停止 | `opted_out`（v3.0） | 掲載を再開する（本人からの申し出があったときだけ） |

### 9.2 認定済みのチャンネルの行

| 項目 | 内容 |
|------|------|
| チャンネル | アイコン・名前・YouTube へのリンク |
| 認定の入口 | 運営の登録／本人・事務所の申請／視聴者の推薦／移行（`authorizedVia`）。申請からのものは申請（審査ワークフロー）へのリンク |
| 再生リスト | 掲載中 N件・確認待ち N件・非表示 N件（押すと第8章をこのチャンネルで絞り込んで開く） |
| 最終巡回 | 日時と、前回新しく取り込んだ件数 |
| 掲載方法 | 「確認してから掲載」（既定）／「自動で掲載」の切り替え。切り替えはこの先に取り込む再生リストに効く（今ある確認待ちは自動では掲載しない。「確認待ちをまとめて掲載する」は第8章で行う） |
| 表示順 | 「人気のチャンネル」（ページ top 仕様書 §6A）に出す順の数値。空欄なら出さない |

### 9.3 認定を外す・掲載を止める

- **認定を外す**: 確認ダイアログ「このチャンネルの再生リスト N件（掲載中 M件）を、すべて非表示にします。データは消しません。」。理由メモ（任意）を残す。
- **掲載を止める**（実況者・事務所からの申し出）: 確認ダイアログで、申し出のお問い合わせ（任意。お問い合わせ管理から選ぶかIDを貼る）と理由メモを入れる。実行すると**すぐ**そのチャンネルの再生リストをすべて `channel_off`（`opt_out`）にする（コンテンツ収集機能仕様書 §10.6）。お問い合わせへの返信は運営がお問い合わせ管理から行う。
- どちらも操作ログ（管理 操作ログ仕様書）に残す。

### 9.4 申請からの認定（段階6）

チャンネル申請（審査ワークフロー仕様書 §15）を承認すると、この画面の「認定済み」に `authorizedVia: creator_application`／`viewer_recommendation`、掲載方法 `confirm` で入り、その場で1回取り込む。
