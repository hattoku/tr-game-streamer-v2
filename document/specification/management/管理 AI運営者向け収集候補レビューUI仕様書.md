## 1. 概要

本仕様書は、コンテンツ収集（管理_Ai運営者 コンテンツ収集機能仕様書）が `collection_candidates` に保存した再生リスト候補を、管理者が確認・承認・却下する管理画面と、探索の起点となる「探索対象チャンネル」を管理する画面を定義する。

v2.0（2026-10-26）で、チャンネル起点の探索（コンテンツ収集機能仕様書 v3.0 §3）に合わせて全面改訂した。候補が数百〜数千件になるため、**チャンネル単位でまとめて承認する**操作を主とする。AI判定（フラグ・コメント）は Gemini 導入後に追加する（将来）。

### 1.1 画面の位置

管理画面のヘッダーナビゲーションに「コンテンツ収集」を追加する。

| 画面 | パス |
|------|------|
| 収集候補 | `/admin/collection` |
| 探索対象チャンネル | `/admin/collection/channels` |

2つの画面の上（見出し「コンテンツ収集」の下）に、「収集候補」「探索対象チャンネル」の大きなタブを常に出して切り替える（v2.2）。今いる画面は管理用の色で示す。マウスオーバーで開くメニューはタッチ端末で使えず、開くまで画面の存在が見えないため使わない。

## 2. アクセス権限

| 操作 | オーナー | 運営者 |
|------|:---:|:---:|
| 収集候補の閲覧・承認・却下 | ○ | ○ |
| 探索の実行 | ○ | ○ |
| 探索対象チャンネルの登録・確定・除外 | ○ | ○ |

> v1.x ではオーナー専用としていたが、管理画面の他機能と同じく管理者（オーナー・運営者）に開く。現状の管理者はオーナー1名のため実質の差はない。オーナー限定に戻すかはコンテンツ収集機能仕様書 §9 の検討事項とする。

### 3.2 タブ

| タブ | 表示対象 |
|------|---------|
| 未処理 | `status: pending`（既定） |
| 登録済み | `status: registered` |
| 却下済み | `status: rejected` |

### 3.3 絞り込み

| 条件 | 種別 |
|------|------|
| チャンネル | ドロップダウン（候補のあるチャンネル） |
| ゲーム | すべて／登録済みのゲームに付ける／新しく登録する（v2.3 で「推定あり／推定なし」から、カードの「ゲーム:」の表示と同じ文言に変更）。ゲーム推定は、再生リスト名に登録済みのゲームタイトル名か別名が含まれるかで決まる（コンテンツ収集機能仕様書 §3.4）。行でゲームを選んだ候補は「登録済みのゲームに付ける」に入る |
| 楽天（v2.2、未処理タブのみ） | すべて／商品あり／一致なし（候補あり）／楽天なし・見つからない／自動検索の順番待ち／要確認（名前変更・検索失敗）。§3.7 の状態で絞り込む（推定ありの候補は「すべて」でだけ出る） |

- 各選択肢に件数を「（N）」で添える（v2.2）。チャンネルはそのタブの件数、ゲーム推定・楽天は、ほかの絞り込みを当てたうえでの件数。

### 3.4 一覧の表示

候補を**チャンネルごとにまとめて**表示する。チャンネル内は再生リストの作成日時の新しい順。

| 表示項目 | 内容 |
|---------|------|
| チェックボックス | 未処理・却下済みタブ。承認・却下（却下済みタブでは未処理に戻す）の対象を選ぶ |
| サムネイル | 再生リストのサムネイル（16:9）。クリックで YouTube の再生リストを別タブで開く |
| 再生リストタイトル | — |
| 動画数 | `N本（日時 の探索時点）`。探索のたびに既存の候補の本数も更新する（v2.2）。承認時は YouTube から全動画を取り直すため、登録される本数は承認時点のもの |
| 再生リスト作成日 | 「再生リスト作成日 日時」（v2.2 で「作成」から言い換え） |
| ゲーム | 推定・選択済みのゲームタイトル名。無ければ「新規」の印と、承認時に登録するゲーム名の入力欄（初期値は `gameQuery`）、「既存から選ぶ」ボタン（§3.5） |
| タグ | 承認時に付けるタグ（チャンネル単位タグ＋タイトル由来タグ）。×で外せる |
| 動画一覧を見る（YouTube） | YouTube の再生リストのページを別タブで開くボタン（v2.3、§3.8） |

- チャンネル見出しに「全選択」チェックボックスを置く。v2.1 から推定なしの候補もまとめて選べる（ゲーム名の入力欄が空のものだけ選べない）。
- 一覧の上に「ゲームが推定できなかった候補は『新規』の欄の名前でゲームタイトルを登録してから承認する。ゲームではない再生リストはチェックを外すか却下する」旨の案内を出す。
- 一覧は1チャンネルずつ折りたたみ可能とし、ページネーションは行わない（チャンネル単位で処理する前提）。
- 管理画面は操作ミスを防ぐことを優先し、ユーザー向け画面の白黒基調にこだわらない（v2.2）。チャンネルごとに管理用の色（admin-accent）の枠で囲み、見出しにチャンネルのアイコン・名前・件数を出す。行の操作（ゲームを選ぶ・商品名をゲーム名にする・動画一覧を見る）は管理用の色、楽天の商品を選ぶ操作（候補から選ぶ・選び直す）は楽天の色のボタン、楽天の「探し直す」は検索アイコン付きのグレーのボタンにする（v2.3 で、隣り合うことのある「候補から選ぶ」と色を分けた）。
- 推定なしの候補の入力欄には「登録するゲームタイトル名（初期値は再生リスト名から推定）」の見出しを付ける。
- カードは、PC では左に再生リスト（サムネイル・タイトル・本数・作成日・タグ）、右にゲームの欄を並べ、スマホでは縦に積む（v2.2）。ゲームの欄には「ゲーム:」の後に、推定ありなら「登録済みのゲームに付ける」とゲーム名・パッケージ画像・「別のゲームを選ぶ」、推定なしなら「新しく登録する」とゲーム名の入力欄・楽天ブックスの商品（パッケージ画像を大きく表示、§3.7）を出す。
- タグの上に「承認時に付けるタグ（×で外せる）」の見出しを付ける。

### 3.5 ゲームの選択（推定なし・推定の変更）

推定なしの候補には、承認時に登録するゲーム名の入力欄を出す。初期値は候補の `gameQuery`（コンテンツ収集機能仕様書 §3.4）で、その場で書き換えられる。承認時の扱いは §4.3。

> v2.0 では推定なしの候補は1件ずつゲームを選ぶ（または登録する）まで承認できなかった。stg の試運転で、有名チャンネル3つの候補441件がすべて推定なし（stg のゲームタイトルが21件しかなく照合先が無い）になり、1件ずつの操作で承認しきれなかったため、v2.1 で名前のままのまとめて承認を主にした。再生リスト名はほとんどがゲーム名そのものなので、`gameQuery` をそのまま使えることが多い。

既存のゲームに結び付けたいとき・楽天ブックスの商品を自分で選びたいときは、「既存から選ぶ」（推定ありの場合はゲーム名のクリック）で、管理者用の再生リスト登録と同じゲームタイトル選択モーダル（GameSelectModal）を開く。

- 見つからない場合は、フッターの導線からゲームタイトル新規登録モーダル（GameCreateModal）を開く。このとき候補の `gameQuery`（コンテンツ収集機能仕様書 §3.4）を**楽天ブックス検索欄に入れた状態で開き、自動で検索する**。タイトル名欄にも同じ語句を入れておく。
- 楽天ブックスに無いゲームは、検索結果を使わずタイトル名だけで登録できる（パッケージ画像は後でゲームタイトル詳細から足す）。
- 選んだ・登録したゲームはその候補に保持され、チェックが自動で入る。

### 3.6 探索を実行

「最終探索」「本日のAPI消費」は状態の表示として「収集の状況」のカードにまとめ、「探索を実行」はボタンと説明だけの別のカードにする（v2.3。同じ欄に並べると、説明がどちらのものか分かりにくかったため）。

ボタンの横に、何をするかの説明（探索対象チャンネル（探索中）の再生リストを読み、コンテンツ収集機能仕様書 §3.3 のハードフィルタを通り、未登録・未候補のものを候補に追加する。既存の候補は本数だけ更新する。本番では週1回自動でも実行する）を出す（v2.2）。

「探索を実行」ボタンで、`status: active` の探索対象チャンネル全件を探索する（コンテンツ収集機能仕様書 §3.2）。実行中はボタンをローディング表示にし、完了後に「チャンネルN件を探索し、新しい候補をM件追加しました」をトーストで表示して一覧を再読み込みする。クォータの1日上限を超える場合はエラーを表示する。

### 3.7 楽天ブックスの商品を承認前に選ぶ（v2.2）

新規のゲーム名の候補は、承認前に、結び付ける楽天ブックスの商品を行で確認・選択できる。

- 探索（定期実行・「探索を実行」）の後に、サーバーが未検索の新規のゲーム名の候補を1件ずつ楽天ブックスで検索して保存しておく（v2.3。定期実行は開始から240秒まで、ボタンは45秒まで。コンテンツ収集機能仕様書 v3.3）。画面を開いて待たなくてよいようにするため。
- 一覧を開くと、サーバーで検索しきれなかった残りを、今の絞り込みで出ている候補の表示順に**1件ずつ自動で**楽天ブックス検索する（レートリミットに合わせて約1秒に1件。承認中・モーダルを開いている間は止める。承認は検索中の1件が終わるのを待ってから送る）。結果（最大10件。JAN の無い商品と、楽天ブックスの「ゲーム」の下でもゲームソフトではない「おもちゃ」（006510）・「その他」（006505）の商品は除く（v2.3。ジャンルが複数ある商品は、1つでも当てはまれば除く）。承認時の名前の完全一致の検索でも同じく除く）は候補の `rakutenSearch` に保存し、次に開いたときは検索しない。
- 検索語はゲーム名。0件（JAN のある商品が無い場合も含む）なら、末尾の英数字の略称を外した語（例: 「デッドライジングDR」→「デッドライジング」）、区切り（空白・コロン・中黒など）の前だけの語の順に探し直す。末尾が数字だけのとき（「バイオハザード RE:2」の「2」など）はシリーズの番号なので外さない（v2.3。外すと「RE:4」など別の作品に当たるため）。短くした語は、日本語を含み2文字以上のときだけ使う（「Pacific Drive」→「Pacific」のような別の語にしないため）。
- 行の「楽天:」の欄に、次のどれかを出す。

| 状態 | 表示 | 操作 |
|------|------|------|
| 自動検索の順番待ち・検索中 | 「自動検索の順番待ち」「検索中…」 | — |
| ゲーム名と一致する商品がある（§4.3-2 と同じ正規化） | 商品画像・商品名（機種） | 「選び直す」 |
| 一致は無いが候補がある | 「名前が一致する商品なし（候補N件。このままなら名前だけで登録）」 | 「候補から選ぶ」 |
| 検索した後にゲーム名を書き換えた | 「ゲーム名を変えました（承認時にこの名前で探します）」 | 「探し直す」 |
| 0件 | 「見つかりませんでした（名前だけで登録）」 | 「探し直す」 |
| 楽天なしを選んだ | 「使わない（名前だけで登録）」 | 「候補から選ぶ」 |
| 検索に失敗 | 「検索に失敗しました」 | 「探し直す」 |

- 商品が決まっている行では、パッケージ画像と商品名を、楽天ブックスの商品ページを別タブで開くリンクにする（v2.3。確認用）。保存する検索結果に商品ページの URL（`itemUrl`）を持たせ、それより前に保存した結果は JAN で楽天ブックスを検索するページを開く。
- 英数字・記号だけのゲーム名で0件のときは、「英語名は楽天ではカタカナのことが多い」旨を行とモーダルに添える（v2.3。楽天ブックスは Pacific Drive を「パシフィックドライブ」で登録しているなど、英語名では見つからないことが多いため）。
- 「候補から選ぶ」等で楽天ブックスの商品を選ぶモーダルを開く。保存済みの検索結果を画像・商品名・機種・発売日で並べ、検索語を変えて探し直せる（結果は保存し直す）。商品を押すとその商品に決まる。「楽天なしで登録する」で名前だけの登録に決まる。
- 選んだ商品の商品名から限定版・機種名などの表記を除いた名前（§4.3-2 と同じ）がゲーム名と違うときは、「『商品名』をゲーム名にする」ボタンを出す。押すとゲーム名の入力欄をその名前に置き換える。
- 承認の確認ダイアログでは、新しく登録するゲーム名の後に「（楽天: 商品名）」または「（楽天なし）」を添える。選んだ中に楽天の商品がまだ決まっていない候補（自動検索の順番待ち・名前変更・検索失敗）があれば、「楽天の商品がまだ決まっていない候補がN件あります（…承認時に名前が完全一致する商品だけを探します）」と件数を出す。まとめて承認する前に、楽天の絞り込みで順番待ちが0件になったかを確かめられる。
- 承認時は、決まった商品の JAN を承認APIに送る。楽天なしを選んだ候補と、一致する商品が無いまま（候補から選んでいない）の候補は `null`（名前だけで登録）。まだ検索していない候補と、検索した後にゲーム名を書き換えた候補（モーダルで選んでいないもの）は送らず、従来どおり承認APIがその名前の完全一致で探す（§4.3）。
- モーダルで検索語を変えて探し直した結果も、その候補のゲーム名の検索結果として保存する（`rakutenSearch.title` はゲーム名、`query` は検索語）。
- 名前が既存のゲームタイトルと一致した場合は、選んだ商品に関わらず既存のゲームを使う（§4.3-1）。

### 3.8 再生リストの確認（v2.3）

カードの「動画一覧を見る（YouTube）」で、YouTube の再生リストのページ（`https://www.youtube.com/playlist?list=<playlistId>`）を別タブで開く。サムネイルも同じページを開く。シリーズの途中に関係の無い動画（告知・雑談など）が多く挟まっている再生リストを、承認前に見つけて却下するためのもの。

- 画面内には表示しない。再生リストのページは YouTube が埋め込みを禁止している（`X-Frame-Options: SAMEORIGIN`）。プレイヤーの埋め込み（`embed/videoseries`）は動画の再生が主で、一覧をさっと見る用途に合わない。
- 一覧を自前で取得して並べる案は、開くたびに YouTube Data API のユニットを消費するため採らなかった。

## 4. まとめて承認

### 4.1 フロー

```
候補にチェックを入れる（ゲームが決まっているもの、または新規のゲーム名があるもの）
    ↓
下部バーの「選択を承認して登録」
    ↓
確認ダイアログ「N件を登録します。（新規のゲーム名があれば）次のゲーム名は、同じ名前のゲームタイトルが無ければ新しく登録します（M件）: ・名前…（10件まで、残りは「ほかK件」） よろしいですか？」
    ↓
1件ずつ順に登録（20件ずつ、新規のゲーム名を含む候補は5件ずつAPIに送り、進捗「12 / 30 件」を表示）
  ⓪ 新規のゲーム名なら、ゲームタイトルを用意する（§4.3）
  ① チャンネルが未登録なら channels を新規作成
  ② playlists・videos を登録（管理者用の再生リスト登録と同じ内容）
  ③ タグを固定タグとして付与し、usagePlaylistCount を加算
  ④ 候補を registered に更新（reviewedAt・reviewedBy・registeredPlaylistId）
    ↓
結果をトースト表示（成功N件・追加したゲームタイトルK件・失敗M件）。失敗した候補は未処理のまま残し、理由を行に表示する
```

### 4.2 ルール

- **ゲームタイトルは必須**。ゲームが決まっておらず、新規のゲーム名も空（または100文字超・記号だけ）の候補はチェックボックスを非活性にする。
- API は1回の呼び出しで最大50件まで受け付ける。画面からは20件ずつ送り、新規のゲーム名を含む候補は5件ずつにする。新規のゲームは楽天ブックスの検索とジャンルの解決に1件2秒ほどかかり、Firebase Hosting 経由のリクエストは60秒で打ち切られるため。楽天ブックスAPIの呼び出しは10秒で打ち切り、名前だけの登録に切り替える。
- 登録時に YouTube 側で非公開・削除になっていた場合は失敗として扱い、候補を `rejected`（`reviewComment: "not_public"` 等）にする。
- 既に `playlists` に存在した場合（別経路で登録済み）は、候補を `registered` にして成功扱いとする。

### 4.3 新規のゲーム名の扱い

承認API（`POST /api/admin/collection/candidates`、`action: approve`）の各項目は `gameId` か `newGameTitle` のどちらかを持つ。`newGameTitle` の項目は任意で `rakutenJan`（§3.7 で決まった楽天ブックスの商品の JAN。楽天なしは `null`）を持つ。`newGameTitle` の項目は、登録の前に次の順でゲームタイトルを用意する。

1. 登録済みのゲームタイトルのタイトル（`games.title`）または別名（`games.aliases`）と、コンテンツ収集機能仕様書 §3.4 と同じ正規化（NFKC・小文字化・空白と記号の除去）で**完全一致**するものがあれば、それを使う（新規登録しない）。タイトルでの一致を別名での一致より優先する。
2. 無ければ、`rakutenJan` が JAN ならその JAN で楽天ブックスを検索して商品を取り直す（同じ JAN の商品が見つからない・失敗したら名前だけで登録）。`null`、または JAN として読めない値（数字8〜14桁以外）なら楽天を検索せず名前だけで登録する。`rakutenJan` が無ければ楽天ブックスをその名前で検索し、商品名を正規化（ゲームタイトル新規登録の自動入力と同じく、限定版・機種名などの表記を除いたうえで上と同じ正規化）して**完全一致**する商品があれば、パッケージ画像・商品ページURL・機種（固定候補にあるもののみ）・ジャンル・テーマ（マスタと名前が一致するもののみ）を入れる。楽天ブックスAPIのレートリミット（1秒1回）に合わせて間隔をあける。
3. 一致する商品が無い・楽天の呼び出しに失敗した場合は、**名前だけで**登録する。パッケージ画像などは後でゲームタイトル詳細の編集から足す。
4. ゲーム名は入力欄の名前をそのまま使う（楽天の商品名には置き換えない）。同じ承認の中で同じ名前（正規化後）が複数あっても、登録は1回にして同じゲームに結び付ける。

- 新規登録したゲームタイトルは API の結果（`createdGame`）で画面に返し、残りの候補の推定（§3.4 の再推定）にすぐ使う。
- 新規登録したゲームタイトルに、同じ承認リクエストで再生リストが1件も登録できなかった場合（非公開・削除で却下、登録の失敗、別経路で登録済み）は、そのゲームタイトルを消す（ジャンル・テーマの件数も戻す）。再生リスト0件のゲームタイトルが一覧に残らないようにするため。
- 同じ名前を含む承認を、別のタブ・別の管理者が同時に送った場合の重複登録は防がない（管理者が1名の現状では起きにくい。起きたらゲームタイトルの編集・削除で直す）。

## 5. 却下

- 下部バーの「選択を却下」で、選択中の候補を `rejected` にする（確認ダイアログあり）。
- 却下済みタブから「未処理に戻す」ことができる（誤操作の復旧用）。
- 却下した候補は、次回以降の探索でも再び候補にならない（コンテンツ収集機能仕様書 §3.3）。

## 6. 探索対象チャンネル画面

### 6.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ ← 収集候補に戻る                                             │
│ 探索対象チャンネル                                           │
│                                                             │
│ ┌ チャンネルを追加 ─────────────────────────────────────┐   │
│ │ 名前（1行1件）、またはチャンネルURL・@ハンドル         │   │
│ │ [テキストエリア                                    ]   │   │
│ │                                        [追加する]      │   │
│ └───────────────────────────────────────────────────────┘   │
│                                                             │
│ [確認待ち 12] [未特定 40] [探索中 25] [除外 3]               │
│ 未特定タブ: [名前からまとめて特定（最大40件・約4,000ユニット）]│
│                                                             │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ キヨ（wiki）                                          │   │
│ │ 候補: ○[icon] キヨ。 登録者 300万人  [確定]           │   │
│ │       ○[icon] キヨ切り抜き  登録者 2万人             │   │
│ │ [URLで指定] [除外]                                    │   │
│ └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち | `pending_confirm` | 候補から1件を選んで「確定」／「URLで指定」／「除外」 |
| 未特定 | `unresolved` | 「名前からまとめて特定」（上限件数ずつ）／個別に「URLで指定」／「除外」 |
| 探索中 | `active` | チャンネル単位タグの編集／「このチャンネルだけ探索」／「除外」。最終探索日時・前回の新規候補数を表示 |
| 除外 | `excluded` | 「未特定に戻す」 |

### 6.3 チャンネルの追加

- テキストエリアに1行1件で入力する。行が YouTube のチャンネルURL・`@ハンドル`・`UC` で始まるチャンネルIDなら、その場で特定して `active` で追加する（1ユニット）。それ以外は名前として `unresolved` で追加する（クォータ消費なし）。
- 同じ名前・同じチャンネルIDが既にある行はスキップし、結果に「重複N件」と表示する。

### 6.4 チャンネル単位のタグ

`active` のチャンネルごとに「タグを設定」から、運営者タグ（`origin: operator`）をカテゴリ別（実況スタイル系・プレイスタイル系・編集スタイル系）のチップで選ぶ。ここで選んだタグは、そのチャンネルの候補の承認時に付与される（コンテンツ収集機能仕様書 §3.5）。既に保存済みの候補にも、一覧表示の時点で反映する。
