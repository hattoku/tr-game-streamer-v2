## 1. 概要

本仕様書は、コンテンツ収集（管理_Ai運営者 コンテンツ収集機能仕様書）が `collection_candidates` に保存した再生リスト候補を、管理者が確認・承認・却下する管理画面と、探索の起点となる「探索対象チャンネル」を管理する画面を定義する。

v2.0（2026-10-26）で、チャンネル起点の探索（コンテンツ収集機能仕様書 v3.0 §3）に合わせて全面改訂した。候補が数百〜数千件になるため、**チャンネル単位でまとめて承認する**操作を主とする。AI判定（フラグ・コメント）は Gemini 導入後に追加する（将来）。

### 1.1 画面の位置

管理画面のヘッダーナビゲーションに「コンテンツ収集」を追加する。

| 画面 | パス |
|------|------|
| 収集候補 | `/admin/collection` |
| 探索対象チャンネル | `/admin/collection/channels` |

## 2. アクセス権限

| 操作 | オーナー | 運営者 |
|------|:---:|:---:|
| 収集候補の閲覧・承認・却下 | ○ | ○ |
| 探索の実行 | ○ | ○ |
| 探索対象チャンネルの登録・確定・除外 | ○ | ○ |

> v1.x ではオーナー専用としていたが、管理画面の他機能と同じく管理者（オーナー・運営者）に開く。現状の管理者はオーナー1名のため実質の差はない。オーナー限定に戻すかはコンテンツ収集機能仕様書 §9 の検討事項とする。

## 3. 収集候補一覧画面

### 3.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ コンテンツ収集                     [探索対象チャンネル →]      │
│                                                             │
│ 最終探索: 2026-10-26 03:00（週1自動）  新規候補 120件         │
│ 本日のクォータ消費: 340 / 6,000                [探索を実行]    │
│                                                             │
│ [未処理] [登録済み] [却下済み]                                │
│ [ チャンネル ▼ ]  [ ゲーム推定: すべて／推定あり／推定なし ▼ ] │
│                                                             │
│ ━ キヨ。（未処理 34件） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ [□ このチャンネルの推定ありを全選択]                          │
│ □ [サムネ] 【ゼルダ】初見で… 　12本 ゲーム: ゼルダの伝説…  │
│            タグ: 生声 男性実況者 初見プレイ                   │
│ □ [サムネ] 【8番出口】…        5本 ゲーム: 推定なし [選ぶ]  │
│ …                                                           │
│                                                             │
│ ┌ 下部固定バー ───────────────────────────────────────────┐ │
│ │ 選択中 12件   [選択を却下]   [選択を承認して登録]        │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 タブ

| タブ | 表示対象 |
|------|---------|
| 未処理 | `status: pending`（既定） |
| 登録済み | `status: registered` |
| 却下済み | `status: rejected` |

### 3.3 絞り込み

| 条件 | 種別 |
|------|------|
| チャンネル | ドロップダウン（候補のあるチャンネル） |
| ゲーム推定 | すべて／推定あり／推定なし |

### 3.4 一覧の表示

候補を**チャンネルごとにまとめて**表示する。チャンネル内は再生リストの作成日時の新しい順。

| 表示項目 | 内容 |
|---------|------|
| チェックボックス | 未処理タブのみ。承認・却下の対象を選ぶ |
| サムネイル | 再生リストのサムネイル（16:9）。クリックで YouTube の再生リストを別タブで開く |
| 再生リストタイトル | — |
| 動画数 | `N本` |
| ゲーム | 推定・選択済みのゲームタイトル名。無ければ「推定なし」と「選ぶ」ボタン |
| タグ | 承認時に付けるタグ（チャンネル単位タグ＋タイトル由来タグ）。×で外せる |

- チャンネル見出しに「このチャンネルのゲーム推定ありを全選択」チェックボックスを置く。
- 一覧は1チャンネルずつ折りたたみ可能とし、ページネーションは行わない（チャンネル単位で処理する前提）。

### 3.5 ゲームの選択（推定なし・推定の変更）

「選ぶ」（推定ありの場合はゲーム名のクリック）で、管理者用の再生リスト登録と同じゲームタイトル選択モーダル（GameSelectModal）を開く。

- 見つからない場合は、フッターの導線からゲームタイトル新規登録モーダル（GameCreateModal）を開く。このとき候補の `gameQuery`（コンテンツ収集機能仕様書 §3.4）を**楽天ブックス検索欄に入れた状態で開き、自動で検索する**。タイトル名欄にも同じ語句を入れておく。
- 楽天ブックスに無いゲームは、検索結果を使わずタイトル名だけで登録できる（パッケージ画像は後でゲームタイトル詳細から足す）。
- 選んだ・登録したゲームはその候補に保持され、チェックが自動で入る。

### 3.6 探索を実行

「探索を実行」ボタンで、`status: active` の探索対象チャンネル全件を探索する（コンテンツ収集機能仕様書 §3.2）。実行中はボタンをローディング表示にし、完了後に「チャンネルN件を探索し、新しい候補をM件追加しました」をトーストで表示して一覧を再読み込みする。クォータの1日上限を超える場合はエラーを表示する。

## 4. まとめて承認

### 4.1 フロー

```
候補にチェックを入れる（ゲームが決まっているものだけ選択可）
    ↓
下部バーの「選択を承認して登録」
    ↓
確認ダイアログ「N件を登録します。よろしいですか？」
    ↓
1件ずつ順に登録（進捗「12 / 30 件」を表示）
  ① チャンネルが未登録なら channels を新規作成
  ② playlists・videos を登録（管理者用の再生リスト登録と同じ内容）
  ③ タグを固定タグとして付与し、usagePlaylistCount を加算
  ④ 候補を registered に更新（reviewedAt・reviewedBy・registeredPlaylistId）
    ↓
結果をトースト表示（成功N件・失敗M件）。失敗した候補は未処理のまま残し、理由を行に表示する
```

### 4.2 ルール

- **ゲームタイトルは必須**。ゲームが決まっていない候補はチェックボックスを非活性にする（「ゲームを選ぶと承認できます」）。
- 1回の承認は最大50件までとする（API の処理時間とクォータ消費を抑えるため）。
- 登録時に YouTube 側で非公開・削除になっていた場合は失敗として扱い、候補を `rejected`（`reviewComment: "not_public"` 等）にする。
- 既に `playlists` に存在した場合（別経路で登録済み）は、候補を `registered` にして成功扱いとする。

---

## 5. 却下

- 下部バーの「選択を却下」で、選択中の候補を `rejected` にする（確認ダイアログあり）。
- 却下済みタブから「未処理に戻す」ことができる（誤操作の復旧用）。
- 却下した候補は、次回以降の探索でも再び候補にならない（コンテンツ収集機能仕様書 §3.3）。

## 6. 探索対象チャンネル画面

### 6.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ ← 収集候補に戻る                                             │
│ 探索対象チャンネル                                           │
│                                                             │
│ ┌ チャンネルを追加 ─────────────────────────────────────┐   │
│ │ 名前（1行1件）、またはチャンネルURL・@ハンドル         │   │
│ │ [テキストエリア                                    ]   │   │
│ │                                        [追加する]      │   │
│ └───────────────────────────────────────────────────────┘   │
│                                                             │
│ [確認待ち 12] [未特定 40] [探索中 25] [除外 3]               │
│ 未特定タブ: [名前からまとめて特定（最大40件・約4,000ユニット）]│
│                                                             │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ キヨ（wiki）                                          │   │
│ │ 候補: ○[icon] キヨ。 登録者 300万人  [確定]           │   │
│ │       ○[icon] キヨ切り抜き  登録者 2万人             │   │
│ │ [URLで指定] [除外]                                    │   │
│ └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち | `pending_confirm` | 候補から1件を選んで「確定」／「URLで指定」／「除外」 |
| 未特定 | `unresolved` | 「名前からまとめて特定」（上限件数ずつ）／個別に「URLで指定」／「除外」 |
| 探索中 | `active` | チャンネル単位タグの編集／「このチャンネルだけ探索」／「除外」。最終探索日時・前回の新規候補数を表示 |
| 除外 | `excluded` | 「未特定に戻す」 |

### 6.3 チャンネルの追加

- テキストエリアに1行1件で入力する。行が YouTube のチャンネルURL・`@ハンドル`・`UC` で始まるチャンネルIDなら、その場で特定して `active` で追加する（1ユニット）。それ以外は名前として `unresolved` で追加する（クォータ消費なし）。
- 同じ名前・同じチャンネルIDが既にある行はスキップし、結果に「重複N件」と表示する。

### 6.4 チャンネル単位のタグ

`active` のチャンネルごとに「タグを設定」から、運営者タグ（`origin: operator`）をカテゴリ別（実況スタイル系・プレイスタイル系・編集スタイル系）のチップで選ぶ。ここで選んだタグは、そのチャンネルの候補の承認時に付与される（コンテンツ収集機能仕様書 §3.5）。既に保存済みの候補にも、一覧表示の時点で反映する。
