## 1. 概要

> **v3.0（2026-11-01）リブランディング**: 収集の品質の関門を「再生リスト1件ずつの承認」から「チャンネルを掲載するかどうか」に移した（コンテンツ収集機能仕様書 v4.0 第10章）。これに合わせ、段階4の実装で次のように画面を変える。
> - 「収集候補」（第3〜5章の承認画面）→ **「自動掲載の確認」**（第8章）。掲載チャンネルの巡回で取り込んだ再生リストを、掲載状態ごとに確認・切り替える。
> - 「探索対象チャンネル」（第6章）→ **「掲載チャンネル」**（第9章）。掲載方法（自動／確認）・掲載から外す・掲載を止めるを足す。
> - 「ゲーム未設定」の画面（PR #14 v2.5 §6.5）はそのまま使う。
> **段階4（v3.3、2026-11-04）で実装した。第3〜5章（収集候補の承認画面）は第8章に置き換わり、今は使っていない**（経緯として残す）。第6章は第9章の土台としてそのまま使う。実装の詳細は §8.6・§9.5。

本仕様書は、コンテンツ収集（管理_Ai運営者 コンテンツ収集機能仕様書 第10章）の管理画面を定義する。掲載チャンネルの巡回で取り込んだ再生リストを掲載状態ごとに確認・切り替える「自動掲載の確認」（第8章）、掲載チャンネルを管理する「掲載チャンネル」（第9章）、ゲーム未設定の再生リストにゲームを付ける「ゲーム未設定」（§6.5）の3画面。

> v2.0〜v3.2 は、収集候補（`collection_candidates`）を確認・承認・却下する画面を定義していた（第3〜5章。取り下げ/へ移した）。

### 1.1 画面の位置

管理画面のヘッダーナビゲーションに「コンテンツ収集」を追加する。

| 画面 | パス |
|------|------|
| 自動掲載の確認（v3.3。旧: 収集候補） | `/admin/collection` |
| 掲載チャンネル（v3.3。旧: 探索対象チャンネル） | `/admin/collection/channels` |
| ゲーム未設定 | `/admin/collection/unset`（§6.5。v2.5） |

3つの画面の上（見出し「コンテンツ収集」の下）に、「自動掲載の確認」「掲載チャンネル」「ゲーム未設定」の大きなタブを常に出して切り替える（v2.2。名前は v3.3）。今いる画面は管理用の色で示す。マウスオーバーで開くメニューはタッチ端末で使えず、開くまで画面の存在が見えないため使わない。

## 6. 探索対象チャンネル画面

### 6.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ ← 収集候補に戻る                                             │
│ 探索対象チャンネル                                           │
│                                                             │
│ ┌ チャンネルを追加 ─────────────────────────────────────┐   │
│ │ 名前（1行1件）、またはチャンネルURL・@ハンドル         │   │
│ │ [テキストエリア                                    ]   │   │
│ │                                        [追加する]      │   │
│ └───────────────────────────────────────────────────────┘   │
│                                                             │
│ [確認待ち 12] [未特定 40] [探索中 25] [除外 3]               │
│ 未特定タブ: [名前からまとめて特定（最大40件・約4,000ユニット）]│
│                                                             │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ キヨ（wiki）                                          │   │
│ │ 候補: ○[icon] キヨ。 登録者 300万人  [確定]           │   │
│ │       ○[icon] キヨ切り抜き  登録者 2万人             │   │
│ │ [URLで指定] [除外]                                    │   │
│ └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち | `pending_confirm` | 候補から1件を選んで「確定」／「URLで指定」／「除外」 |
| 未特定 | `unresolved` | 「名前からまとめて特定」（上限件数ずつ）／個別に「URLで指定」／「除外」 |
| 探索中 | `active` | チャンネル単位タグの編集／「このチャンネルだけ探索」／「除外」。最終探索日時・前回の新規候補数を表示 |
| 除外 | `excluded` | 「未特定に戻す」 |

### 6.3 チャンネルの追加

- テキストエリアに1行1件で入力する。行が YouTube のチャンネルURL・`@ハンドル`・`UC` で始まるチャンネルIDなら、その場で特定して `active` で追加する（1ユニット）。それ以外は名前として `unresolved` で追加する（クォータ消費なし）。
- 同じ名前・同じチャンネルIDが既にある行はスキップし、結果に「重複N件」と表示する。

### 6.4 チャンネル単位のタグ

`active` のチャンネルごとに「タグを設定」から、運営者タグ（`origin: operator`）をカテゴリ別（実況スタイル系・プレイスタイル系・編集スタイル系）のチップで選ぶ。ここで選んだタグは、そのチャンネルの候補の承認時に付与される（コンテンツ収集機能仕様書 §3.5）。既に保存済みの候補にも、一覧表示の時点で反映する。

---

### 6.5 ゲーム未設定の画面（v2.5）

`/admin/collection/unset`。`playlists.gameId` が null の再生リストを新しい順に並べる（サムネイル・再生リスト名・チャンネル・ヒント（`gameHint`）・登録日）。v3.3 から、掲載中（`listingStatus: listed`）のものだけを出す（巡回で取り込んだ確認待ち・非表示の再生リストは第8章の確認画面でゲームを付ける）。「いますぐ照合」は掲載状態を問わずゲーム未設定すべてを照合する。

- **ゲームを選ぶ**: 既存のゲームタイトル選択（`GameSelectModal`）で選ぶと、そのゲームを付ける。
- **新規登録して付ける**: ゲームタイトル登録（`GameCreateModal`）で作ったゲームを付ける。初期値はヒント（無ければ再生リスト名）。
- **いますぐ照合**: ゲーム未設定すべてを、登録済みのゲームのタイトル・別名と照合して付ける。結果は「N件を照合し、M件にゲームを付けました」。
- 照合の規則: ヒントがあれば、ヒントとゲームのタイトル・別名が**正規化して完全一致**したものだけ付ける。ヒントが無ければ、再生リスト名にゲームのタイトル（別名は使わない）が含まれるもの（正規化後3文字以上のうち最長一致）を付ける。タイトルの直後に数字・ローマ数字が続く（続編・番号違いの）ものは付けない。管理者が外したゲーム（`rejectedGameIds`）は自動では付けない。
- ゲームタイトルを登録したとき・タイトルか別名を編集したとき（管理者の登録・編集API）と、収集の承認で新規ゲームが作られたときにも、そのゲームを対象に同じ照合を自動で行う。
- 付けるときは `gameId`・`gameName`・`gameGenreIds`・`games.playlistCount` を一緒に更新し、`gameSetBy`（`admin`／`auto`）・`gameSetAt` を書き、履歴（`playlist_game_changes`）を残す。
- **ユーザーが登録したゲーム**（v3.2）: 一般ユーザーが再生リスト詳細から付けたゲーム（`gameSetBy: 'user'`。再生リスト詳細仕様書 v1.15）を同じ画面の下に並べ、運営が確認する。「戻す」で外して未設定に戻し、そのゲームは `rejectedGameIds` に入って、その再生リストにはもう選べない。
- API: `POST /api/admin/playlist-game`（`link`／`unlink`（外して未設定に戻し、そのゲームを `rejectedGameIds` に足す）／`relink`）。管理者専用。

## 8. 自動掲載の確認画面（段階4）

コンテンツ収集機能仕様書 §10.4 で判定した再生リストを、運営が確認・切り替える画面。今の「収集候補」画面（第3章）を置き換える。パスは `/admin/collection`（今の収集候補と同じ）。

### 8.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ コンテンツ収集                                               │
│ [ 自動掲載の確認 ] [ 掲載チャンネル ] [ ゲーム未設定 ]  ← 大きなタブ │
│                                                             │
│ ┌ 巡回の状況 ───────────────────────────────┐             │
│ │ 最終巡回: 2026-11-10 04:00  新しい再生リスト 24件          │ │
│ │ 本日のAPI消費: 340 / 6,000 ユニット                        │ │
│ └───────────────────────────────────────────┘             │
│                                                             │
│ [確認待ち 18] [掲載中] [ゲームではない] [対象外] [10本未満] [チャンネル対象外] │
│ [ チャンネル ▼ ]  [ ゲーム: すべて／付いている／未設定 ▼ ]          │
│                                                             │
│ ━ キヨ。（確認待ち 6件・確認してから掲載） ━━━━━━━━━━━━━━━━━━ │
│ [□ 全選択]                                                    │
│ □ [サムネ] 【ゼルダ】初見で…  12本  ゲーム: ゼルダの伝説…  [動画一覧を見る] │
│            判定: ルールに当たらず確認待ち                     │
│ □ [サムネ] 【雑談】まったり…   30本  判定: 非ゲーム語「雑談」   │
│ …                                                           │
│ ┌ 下部固定バー ───────────────────────────────────────────┐ │
│ │ 選択中 6件  [掲載する] [ゲームではない] [対象外にする]       │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 タブ（掲載状態）

| タブ | 表示対象 | 主な操作 |
|------|---------|---------|
| 確認待ち（既定） | `unconfirmed` | 掲載する／ゲームではない／対象外にする |
| 掲載中 | `listed` | ゲームではない／対象外にする（掲載から外す） |
| ゲームではない | `non_game` | 掲載する（掲載に戻す）／対象外にする |
| 対象外 | `excluded` | 掲載する／ゲームではない |
| 10本未満 | `too_short` | 掲載する（10本未満でも出す）／対象外にする |
| チャンネル対象外 | `channel_off` | 操作なし（チャンネルを掲載し直す・掲載停止を解くのは第9章） |

- 各タブの件数を出す。「確認待ち」の件数は管理画面ヘッダーのタブにもバッジで出す（気づかないまま溜めないため）。
- 一覧はチャンネルごとにまとめ、見出しにチャンネルのアイコン・チャンネル名・件数・掲載方法（自動／確認）を出す。見出しの右に、確認用にプレミテ内のチャンネルページ（`/channels/{youtubeChannelId}`）を別タブで開く「チャンネルページ」リンクを置く。チャンネルページは掲載した再生リストが1件以上あるとき（`channels` ドキュメントがあるとき）だけ出す（v3.5）。チャンネル内は再生リストの作成日時の新しい順。

### 8.3 行の表示と操作

| 項目 | 内容 |
|------|------|
| サムネイル・タイトル・動画数・作成日 | 第3章と同じ |
| 動画一覧を見る（YouTube） | YouTube の再生リストのページを別タブで開く（PR #14 v2.3 §3.8 と同じ） |
| 判定 | 判定の理由（`listingReason`）。例「非ゲーム語『雑談』」「10本未満（7本）」「ルールに当たらず確認待ち」。人が決めたものは「管理者が決定（日時）」 |
| ゲーム | 推定・紐づけ済みのゲームのパッケージ画像（v3.5。画像が無いゲームは名前だけ）とゲーム名、または「ゲーム未設定（ヒント: ○○）」。ゲームが付いているときは、画像・ゲーム名を押すと「付いているゲーム」モーダルを開き、ゲーム名・別名・機種・ジャンル・掲載中の件数と、楽天ブックスで選ばれている商品のページ（`games.rakutenUrl`、アフィリエイトを付けない元のURL）を別タブで開くリンク、ゲームタイトル詳細（編集はこちら）へのリンクを出す（v3.6。どの商品が選ばれているかを確認するため）。「ゲームを選ぶ」「新規登録して付ける」でゲームを選ぶ／新規登録して付ける（PR #14 v2.5 §6.5 と同じ操作。楽天ブックスの商品選び（PR #14 v2.2 §3.7）もここで使える）。**ゲームを決めなくても掲載できる**（この案内は各行ではなく、一覧の上（チャンネルの絞り込みの横）に1回だけ出す。v3.6） |
| タグ | 掲載するときに付けるタグ（チャンネル単位タグ＋タイトル由来タグ）。×で外せる |

- チェックボックスで複数選び、下部バーでまとめて切り替える（確認ダイアログあり）。行ごとの操作ボタンも置く。
- 切り替えた再生リストは `listingSetBy: admin` になり、以後の自動の判定し直しで上書きされない。
- **掲載する**: `listed` にし、動画一覧（全件）と再生時間を取得し、タグを固定タグとして付け、件数（`games.playlistCount` など）を足す（今の承認の ②③ と同じ処理。クォータの扱いもコンテンツ収集機能仕様書 §4.2 と同じく小分けに送る）。YouTube 側で非公開・削除になっていたら失敗として行に理由を出す。
- **ゲームではない／対象外にする**: 掲載中だったものは検索面から外れ、件数を戻す。動画・レビュー・マイリストは消さない（マイリスト・視聴履歴からは開ける。コンテンツ収集機能仕様書 §10.7）。

### 8.4 判定の言葉の表

画面の右上に「判定の言葉」ボタンを置き、除外語・非ゲーム語・最小本数（`app_settings/listing_rules`、コンテンツ収集機能仕様書 §10.5）を編集するモーダルを開く。

- 言葉はチップで追加・削除する。保存すると次の巡回から新しく取り込む再生リストに使う。
- 「判定し直す」ボタンで、自動で決めた（`listingSetBy: auto`）再生リストすべてを新しい表で判定し直す。人が決めたものは変えない。結果（変わった件数を状態ごとに）をトーストで出す。

### 8.5 一般ユーザーの「ゲームじゃない」報告（構想へ移した）

「/document/specification/構想/コンテンツ収集 これから足すかもしれない収集 構想.md」へ移した。詳細ページからの変更の提案（再生リストの「ゲーム実況の再生リストではない」、ページ 詳細ページからの変更提案 仕様書 §6）として作った。

### 8.6 実装（v3.3、2026-11-04）

- **読み込み**: 開いているタブの掲載状態の再生リストを `playlists` から読む（`listingStatus` の等価条件。チャンネルで絞ったときは `explorationChannelId` も等価条件で足す。1回に最大1,000件。並びは画面で整える）。各タブの件数は件数の集計（count）で出す。
- **巡回の状況**: 最終巡回（直近の `collection_batch_logs` と、`batch_logs` の `video_update` のうち新しい方）・本日のAPI消費（収集の枠）と、「巡回を実行」ボタン（全チャンネルを手動で巡回。コンテンツ収集機能仕様書 §10.11）。
- **判定**の表示: `word:雑談` → 「非ゲーム語『雑談』」（除外語なら「除外語『…』」）、`too_short` → 「10本未満（7本）」、`confirm` → 「ルールに当たらず確認待ち」、`auto_pending` → 「自動で掲載する予定（動画の取得待ち）」、`candidate_rejected` → 「収集候補で却下済み」、`listingSetBy: admin` は「管理者が決定（日時）」。
- **ゲーム**: 「ゲームを選ぶ」（`GameSelectModal`）・「新規登録して付ける」（`GameCreateModal`。楽天ブックスの検索はこのモーダルで行う）・「外す」。付け外しは「ゲーム未設定」画面と同じ API（`/api/admin/playlist-game`）。掲載していない再生リストに付けても件数（`games.playlistCount`）は増えない。収集候補にあった「楽天ブックスの自動検索・先読み」（§3.7）は、承認の前提が無くなったため使わない。
- **タグ**: チャンネル単位タグ＋タイトル由来のタグ（§3.5）を「掲載するときに付けるタグ」として出し、×で外せる（外したものは「掲載する」の送信に含めない）。既に掲載中の再生リストはタグを出さない。
- **まとめて操作**: 下部バーのボタンで、選んだ再生リストを20件ずつ API に送る（掲載するは動画一覧の取得があるため。Firebase Hosting 経由の60秒に収める）。送る前に確認ダイアログで件数を出す。失敗した行には理由（YouTube で見つからない・枠不足など）を出す。
- **バッジ**: 「確認待ち」の件数（`auto_pending` を含む）を、コンテンツ収集のタブ（「自動掲載の確認」）と管理画面ヘッダーの「コンテンツ収集」に出す。
- **判定の言葉**: モーダルで除外語・非ゲーム語をチップで追加・削除、最小本数を数値で入れて保存する。「判定し直す」は保存済みの表で、`listingSetBy: auto` の再生リスト（`channel_off` を除く）を判定し直す。判定し直して `listed` になるもの（自動で掲載のチャンネル）は `auto_pending` にして次の巡回で掲載し、`listed` だったものが外れるときは件数を戻す。結果は変わった件数を状態ごとにトーストで出す。

## 9. 掲載チャンネル画面（段階4・6）

今の「探索対象チャンネル」画面（第6章）を「掲載チャンネル」画面に改める。パスは `/admin/collection/channels`（今と同じ）。第6章の追加・特定・確定・除外・チャンネル単位タグはそのまま使い、次を足す。

### 9.1 タブ

| タブ | 表示対象 | 操作 |
|------|---------|------|
| 確認待ち・未特定 | `pending_confirm`・`unresolved` | 第6章と同じ（確定すると掲載チャンネルになる） |
| 登録済み（旧: 探索中） | `active` | 掲載方法の切り替え／チャンネル単位タグ／ピン留め（v3.4。旧: 表示順）／このチャンネルだけ巡回／掲載から外す／掲載を止める |
| 掲載しない（旧: 除外） | `excluded` | 掲載する（`active` に戻す。再生リストは元の掲載状態に戻る） |
| 掲載停止 | `opted_out`（v3.0） | 掲載を再開する（本人からの申し出があったときだけ） |

### 9.2 登録済みのチャンネルの行

| 項目 | 内容 |
|------|------|
| チャンネル | アイコン・名前・YouTube へのリンク |
| 掲載の入口 | 運営の登録／本人・事務所の申請／視聴者の推薦／移行（`authorizedVia`）。申請からのものは申請（審査ワークフロー）へのリンク |
| 再生リスト | 掲載中 N件・確認待ち N件・非表示 N件（押すと第8章をこのチャンネルで絞り込んで開く） |
| 最終巡回 | 日時と、前回新しく取り込んだ件数 |
| 掲載方法 | 「確認してから掲載」（既定）／「自動で掲載」の切り替え。切り替えはこの先に取り込む再生リストに効く（今ある確認待ちは自動では掲載しない。「確認待ちをまとめて掲載する」は第8章で行う） |
| ピン留め（v3.4。旧: 表示順） | 「人気のチャンネル」（ページ top 仕様書 §6A）とチャンネル一覧の人気順で、先頭に出す順の数値（`featuredOrder`。小さいほど先）。空欄ならピン留めしない（人気の点数で並ぶ）。数秒以内に画面に反映する。ラベルは「ピン留め（先頭に出す順）」、入力欄の説明は「空欄で外す」 |
| 人気の点数（v3.4） | 「人気 N点（マイリスト a人・レビュー b人・視聴 c人／直近30日 d・e・f人）」。点数の式は共通 人気のチャンネル 集計 仕様書 §2.2。一度も集計していない（最後に集計した日時が無い）ときは「人気 0点（未集計）」。集計後に数が0のチャンネルは「人気 0点」 |

画面の上（登録済みのタブ）に「人気の数字: 最後に集計 YYYY/MM/DD HH:mm」と「人気の数字を今すぐ集計する」ボタンを置く（v3.4）。押すと集計の API（共通 人気のチャンネル 集計 仕様書 §3）を呼び、終わったら「N チャンネルを集計しました」と出して一覧を読み直す。毎日 4:00 にも自動で集計する。

### 9.3 掲載から外す・掲載を止める

- **掲載から外す**: 確認ダイアログ「このチャンネルの再生リスト N件（掲載中 M件）を、すべて非表示にします。データは消しません。」。理由メモ（任意）を残す。
- **掲載を止める**（実況者・事務所からの申し出）: 確認ダイアログで、申し出のお問い合わせ（任意。お問い合わせ管理から選ぶかIDを貼る）と理由メモを入れる。実行すると**すぐ**そのチャンネルの再生リストをすべて `channel_off`（`opt_out`）にする（コンテンツ収集機能仕様書 §10.6）。お問い合わせへの返信は運営がお問い合わせ管理から行う。
- どちらも操作ログ（管理 操作ログ仕様書）に残す。

### 9.4 申請からの掲載（段階6）

チャンネル申請（審査ワークフロー仕様書 §4.4）を承認すると、この画面の「登録済み」に `authorizedVia: channel_application`（2026-11-15 までは `creator_application`／`viewer_recommendation`）、掲載方法 `confirm` で入り、その場で1回取り込む。

### 9.5 実装（v3.3、2026-11-04）

- タブは「確認待ち・未特定」「登録済み」「掲載しない」「掲載停止」の4つ。「確認待ち・未特定」は名前検索の確認待ちと未特定を同じタブに出す。
- チャンネルを登録済み（`active`）にした（URL・@ハンドルで追加・名前の候補から確定・URLで指定・掲載し直す・再開）ときは、`publishMode: confirm`（既にあればそのまま）・`authorizedVia: admin`（既にあればそのまま）・`authorizedAt` を書き、その場でそのチャンネルを1回巡回する（コンテンツ収集機能仕様書 §10.3）。まとめて追加したときは、URL指定の5件までをその場で巡回し、残りは毎日の巡回で取り込む。
- 「掲載から外す」（`active` → `excluded`）・「掲載を止める」（`active`／`excluded` → `opted_out`）は、そのチャンネルの再生リスト（`explorationChannelId` が一致するもの、または `channelId` がそのチャンネルのもの）をすべて `channel_off` にする。既に `channel_off` のもの（掲載から外したあとに止めた）は理由だけ `opt_out` に変え、`previousListingStatus` はそのまま残す。
- 「掲載する」（`excluded` → `active`）・「掲載を再開する」（`opted_out` → `active`）は、`channel_off` の再生リストを `previousListingStatus` に戻す。戻す先が `listed` のものは動画一覧があればそのまま掲載し、無ければ（30日の消し込みで消えたなど）`unconfirmed`（`confirm`）に戻す。そのあとチャンネルを1回巡回する。
- 掲載チャンネルではない（`unresolved`・`pending_confirm`）ものの「除外」は今までどおり（再生リストは無いので何もしない）。`excluded` で YouTube のチャンネルが決まっていないものは「未特定に戻す」を出す。
- 行には、掲載の入口・再生リストの件数（掲載中・確認待ち・非表示。件数の集計で出す）・最終巡回（日時と前回取り込んだ件数）・掲載方法の切り替え・表示順（v3.4 でピン留めに改名）・チャンネル単位タグを出す。掲載から外す・止めるの確認ダイアログでは件数と理由メモ（止めるはお問い合わせのIDも）を入れる。理由メモとお問い合わせのIDは `statusNote` に残す。
- 操作ログ（管理 操作ログ仕様書）は、まだ書き込みの仕組みが無いため、`statusNote`・`optedOutAt`・`updatedAt` で代える（操作ログの実装時に足す）。
