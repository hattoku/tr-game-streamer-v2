## 1. 概要

本仕様書は、プレミテ管理画面における以下の2機能を定義する。

- **ユーザー管理**：一般ユーザーのアカウント情報を閲覧・管理する機能
- **管理者アカウント管理**：運営者アカウントおよびAI運営者を管理する機能（オーナーのみ）

---

## 2. アクセス権限

| 機能 | オーナー | 運営者 |
|------|:---:|:---:|
| ユーザー管理（全操作） | ○ | ○ |
| 管理者アカウント管理 | ○ | × |
| 担当ジャンルの設定・変更 | ○（設定のみ） | ○（閲覧のみ） |

---

## 3. ユーザー管理

> **v3.0（2026-11-17）実装**: チケット「ユーザー一覧ページ作成」。画面は `/admin/users`（一覧・グラフ）と `/admin/users/[uid]`（詳細）。
> 管理画面のナビに「ユーザー」を追加。確認事項の答えは計画書（プロジェクトファイル `plans/ユーザー管理/ユーザー管理と退会-計画（案）.md`）。

### 3.0 退会の定義（v3.0。v3.1 で本人の退会を変更）

**管理者が退会させる＝アカウントとデータは残し、ログインできなくする**（ユーザー決定。旧版の「強制退会＝物理削除」と BAN はこれにまとめて廃止）。
**本人が退会する＝本人の作成データとアカウントを消去する**（v3.1、2026-11-19 ユーザー決定。ページ 設定 仕様書 §8）。

| 項目 | 本人が退会した | 管理者が退会させた（`withdrawnBy = admin`） |
|------|------|------|
| 入口 | 設定ページ §8（案内と確認の2段階。その場で消去） | ユーザー詳細の「退会させる」（3.4節） |
| データ | すべて消去し、元に戻せない（ページ 設定 仕様書 §8.3） | 残す |
| ログイン | アカウントが無いのでできない | できない（ページ ログイン 仕様書 §5.5） |
| 本人による再開 | 再開の仕組みは無い（消去済み。同じメールアドレスで新しく作り直す） | **できない**（「運営により退会の扱いになっています。お問い合わせください」） |
| 管理者による解除 | 解除するものが無い | できる（3.5節） |
| 他の人からの見え方 | 消えている | レビュー・公開プロフィール・アイコン・公開マイリストを隠す。レビューはスコア・件数からも外す。データは残し、解除で元に戻す |

- 判定は `users.accountStatus`（`active` / `withdrawn`）。管理者の退会は Firebase Auth のアカウントを無効化せず、トークンを失効させる。
- 退会中のアカウントは、ログインが必要な API（403 `account_withdrawn`）と Firestore への書き込み（ルールの `isActiveAccount()`）を使えない。
- メールアドレスの重複は許さない。管理者が退会させたアドレスでは新しいアカウントは作れないが、本人が退会して消去したアドレスは作れる（ページ ログイン 仕様書 §5.6）。
- 2026-11-19 より前に本人が退会したアカウント（`withdrawnBy = self`、データは残っている）は、管理者の退会と同じ扱いで、一覧に「退会済み（本人）」と出る。管理者が解除できる。
- 本人の退会は `users` ごと消えるので、一覧には出ない。操作ログにも残さない（UID を残さないため）。

------|------|------|
| 入口 | 設定ページ §8（その場で退会） | ユーザー詳細の「退会させる」（3.4節） |
| ログイン | できない（ページ ログイン 仕様書 §5.5） | できない |
| 本人による再開 | **できる**（同じメールアドレス・パスワードでログイン →「利用を再開しますか？」） | **できない**（「運営により退会の扱いになっています。お問い合わせください」） |
| 管理者による解除 | できる（3.5節） | できる（3.5節） |
| 他の人からの見え方 | レビュー・公開プロフィール・アイコン・公開マイリストを隠す。レビューはスコア・件数からも外す。データは残し、再開・解除で元に戻す | 同左 |

- 判定は `users.accountStatus`（`active` / `withdrawn`）。Firebase Auth のアカウントは無効化しない（本人の再開でパスワードを確かめるため）。退会時はトークンを失効させる。
- 退会中のアカウントは、ログインが必要な API（403 `account_withdrawn`）と Firestore への書き込み（ルールの `isActiveAccount()`）を使えない。
- メールアドレスの重複は許さない。退会済みのアドレスで新しいアカウントは作れない（ページ ログイン 仕様書 §5.6）。

### 3.1 ユーザー一覧・検索

一般ユーザー・管理者（オーナー・運営者）の一覧を表示し、条件で絞り込む画面（`/admin/users`）。管理者も「オーナー」「運営者」の印を付けて載せる（v3.0 ユーザー決定）。AI運営者は載せない。

#### 表示項目

| 項目 | 内容 |
|------|------|
| 状態 | 利用中／退会済み（退会済みは「（本人）」「（運営）」を添える） |
| ユーザー名 | 管理者・テスト用会員は印を付ける |
| メールアドレス | Firebase Auth のアドレス（正）。無ければ `users.email` |
| レビュー数 | `users.reviewCount` |
| 登録日時 | Firebase Auth の作成日時（無ければ `users.accountCreatedAt`） |
| 最終ログイン日時 | Firebase Auth の最後のトークン更新日時（ログインしたままの利用も含む。無ければ最後のサインイン日時）。`users.lastLoginAt` は使わない |

日時は日本時間で表示する。20件ずつページ送りする。

#### 検索・絞り込み条件（すべて AND）

| 条件 | 種別 |
|------|------|
| キーワード | ユーザー名・メールアドレスの部分一致（大文字小文字を区別しない） |
| 状態 | すべて／利用中／退会済み |
| 種別 | すべて／一般ユーザー／管理者 |
| 登録日 | 日付範囲（日本時間、両端を含む） |
| 最終ログイン日 | 日付範囲（未ログインは範囲指定時に外す） |
| 並び順 | 登録が新しい順（既定）／古い順／最終ログインが新しい順／古い順／ユーザー名順 |

> **実装注記**: 件数が少ないうちは、管理 API（`GET /api/admin/users`）が Firebase Auth と `users` を全件読んで返し、絞り込み・並び替え・ページ送り・グラフは画面側で行う（/admin/inquiries と同じ簡易実装）。数千件を超えたらサーバー側の絞り込みに切り替える。旧版の「メール認証状態」は、メール認証を使っていないため載せない。

### 3.2 ユーザー詳細

個別ユーザーの詳細情報を閲覧・操作する画面（`/admin/users/[uid]`）。

| カテゴリ | 項目 |
|---------|------|
| 見出し | ユーザー名・状態・管理者／テスト用会員の印 |
| 基本情報 | メールアドレス（表示のみ。「メールアドレスは管理画面からは変更できません」）・登録日時・最終ログイン日時・レビュー数・マイリスト数・ユーザーID。利用中なら「公開プロフィールを開く」 |
| 登録情報の編集 | 3.3節 |
| 備考 | 3.6節 |
| 退会 | 退会中は退会日時・退会させた人・理由（本人の理由／運営の理由）。操作は3.4節・3.5節 |

---

### 3.3 登録情報の編集（v3.0）

不適切な内容を運営が直すための編集。**編集できるのはユーザー名・自己紹介・アイコンの削除だけ**（ユーザー決定）。

| 項目 | 仕様 |
|------|------|
| ユーザー名 | 1〜30文字（プロフィール編集と同じ） |
| 自己紹介 | 200文字以内・空欄可 |
| アイコン | 削除のみ（確認モーダル「アイコンを削除しますか？」）。差し替えは本人だけ |
| メールアドレス | **変更不可**（ユーザー決定） |
| 公開設定・連続再生などの本人の設定 | 変更不可 |

- ユーザー名・アイコンを変えたら、本人のレビューの非正規化コピー（`userDisplayName`・`userProfileImageUrl`）も揃える（本人の編集と同じ）。
- API: `PATCH /api/admin/users/[uid]`（ユーザー名・自己紹介）、`DELETE /api/admin/users/[uid]/avatar`。

### 3.4 退会させる（v3.0）

旧版の「BAN」「強制退会（物理削除）」を置き換える操作。

```
ユーザー詳細の「退会させる」をクリック
    ↓
確認モーダル「このユーザーを退会させますか？」
    ├─ 本文「ログインできなくなり、本人では再開できません。あとから「退会を解除する」で戻せます。」
    ├─ 退会の理由（任意。500文字以内。管理者だけが見られる）
    └─ 「退会させる」（赤系） / 「キャンセル」
    ↓
退会（`POST /api/admin/users/[uid]/withdraw`）→ 詳細に反映
```

| 項目 | 仕様 |
|------|------|
| 対象外 | 管理者（オーナー・運営者）・AI運営者・テスト用会員。ボタンの代わりに「管理者・テスト用会員は退会させられません」を出す |
| 書き込み | `users` に `accountStatus: "withdrawn"`・`withdrawnAt`・`withdrawnBy: "admin"`。理由は `admin_user_records/{uid}.adminWithdrawReason`（本人には読ませない） |
| その他の処理 | 本人の退会と同じ（トークン失効・レビューに `isAuthorWithdrawn` を付けてスコアを計算し直す。ページ 設定 仕様書 §8.3） |

---

### 3.5 退会を解除する（v3.0）

本人が退会した場合も、管理者が退会させた場合も解除できる。

```
ユーザー詳細の「退会を解除する」をクリック
    ↓
確認モーダル「退会を解除しますか？」
    └─ 「解除する」 / 「キャンセル」
    ↓
解除（`POST /api/admin/users/[uid]/restore`）→ 詳細に反映
```

解除すると `accountStatus: "active"` に戻し、`withdrawnAt`・`withdrawnBy`・`withdrawReason`・`adminWithdrawReason` を消し、`restoredAt` を書く。レビューの `isAuthorWithdrawn` を外してスコアを計算し直す（本人の再開と同じ処理）。

---

### 3.6 備考（運営用メモ）（v3.0）

ユーザーごとに運営上のメモを残す欄。

| 項目 | 仕様 |
|------|------|
| 入力 | テキストエリア。2000文字以内 |
| 保存 | 「保存する」（`POST /api/admin/users/[uid]/note`）。最終更新日時と更新した管理者名を表示 |
| 保存先 | `admin_user_records/{uid}`（`note`・`noteUpdatedAt`・`noteUpdatedBy`・`noteUpdatedByName`）。`users` は本人が読めるため使わない。管理者だけが読める |

---

### 3.7 新規登録の推移グラフ（v3.0）

いつごろユーザーが入ってきたかを見るための棒グラフ。一覧の上に置く。

| 項目 | 仕様 |
|------|------|
| 単位 | 日別（直近30日）／週別（直近12週・月曜始まり）／月別（直近12か月）をタブで切り替え。既定は日別 |
| 数える人 | 一般ユーザーだけ（管理者・テスト用会員は除く。ユーザー決定）。退会済みも登録した人として数える |
| 基準の日時 | 登録日時（3.1節）。日本時間で区切る |
| 表示 | 1系列なので凡例は置かず、見出し「新規登録の推移」と期間の合計人数を出す。棒にカーソルを当てる・タップすると期間と人数を表示。「表で見る」で同じ数字を表で出す |

## 4. 管理者アカウント管理（オーナーのみ）

### 4.1 管理者一覧

管理者アカウント（オーナー・運営者）およびAI運営者の一覧を表示する画面。

#### 表示項目

| 項目 | 人間（オーナー・運営者） | AI運営者 |
|------|:---:|:---:|
| 表示名 | ○ | ○（`[AI]` バッジ付き） |
| メールアドレス | ○ | —（設定不要につき表示しない） |
| ロール | ○（オーナー／運営者） | ○（AI運営者） |
| 担当ジャンル | ○（オーナーは表示しない） | —（設定不要につき表示しない）※3 |
| 有効・無効 | ○ | ○ |
| 追加日 | ○（運営者ロールが付与された日付） | ○（作成日） |

- AI運営者は `[AI]` バッジを表示名の前に付与して表示する。
- AI運営者は1体固定のため、担当ジャンルの概念を持たない（※3）。
- オーナーには有効・無効の概念を適用しない。

※3: AI運営者の1体統合に伴い、属性としての担当ジャンル設定は廃止された。

---

### 4.2 運営者の追加

既存ユーザーへのロール付与、またはアカウント未作成者への招待メール送信により運営者を追加する。

#### 追加フロー

```
「運営者を追加する」ボタンをクリック
    ↓
メールアドレスを入力して検索
    ↓
    ├─ プレミテのアカウントが存在する場合
    │      └─ 対象ユーザーの情報を表示
    │             ↓
    │          確認ダイアログ表示
    │             ├─ 担当ジャンル選択（複数選択可・任意）
    │             └─ 「運営者ロールを付与する」ボタン / 「キャンセル」ボタン
    │             ↓
    │          運営者ロール付与完了 → 管理者一覧に追加
    │
    └─ プレミテのアカウントが存在しない場合
           └─ 「このメールアドレスにはアカウントが存在しません。招待メールを送信しますか？」を表示
                  ↓
               「招待メールを送信する」ボタンをクリック
                  ↓
               招待メール送信完了
```

> **補足**: 招待メール経由でアカウント登録が完了した場合、担当ジャンルは未設定の状態で運営者ロールが付与される。担当ジャンルはロール付与後に別途設定する。

#### 招待メールの仕様

| 項目 | 仕様 |
|------|------|
| 招待リンクの有効期限 | 24時間（アカウント登録時の確認メールと同様） |
| 有効期限切れ時 | リンクをクリックした際に「リンクの有効期限が切れています」の旨を表示 |
| 受け取り側のフロー | リンクをクリック → アカウント登録フォームへ遷移 → 登録完了後に運営者ロールを付与 |

---

### 4.3 運営者の削除

運営者ロールを剥奪する操作。プレミテの一般ユーザーアカウント自体は削除されない。

#### 削除フロー

```
管理者一覧の対象運営者の「ロールを剥奪する」ボタンをクリック
    ↓
確認ダイアログ表示
    └─ 「ロールを剥奪する」ボタン / 「キャンセル」ボタン
    ↓
運営者ロール剥奪完了 → 管理者一覧から削除
```

> **注意**: オーナーのロールは剥奪・変更できない。

---

### 4.4 担当ジャンルの設定・変更（運営者）

運営者ごとに担当するゲームジャンルを設定する。担当ジャンルはマスタ管理における運営者の編集権限範囲と、審査ワークフローにおける審査者アサインの対象範囲を決定する。

#### 権限

| 操作 | オーナー | 運営者 |
|------|:---:|:---:|
| 担当ジャンルの設定・変更 | ○ | × |
| 担当ジャンルの閲覧 | ○ | ○ |

#### 設定フロー

```
管理者一覧の対象運営者の「担当ジャンルを設定する」ボタンをクリック
    ↓
担当ジャンル設定モーダルを表示
    ├─ 現在の担当ジャンルを表示（未設定の場合は「未設定」と表示）
    └─ ゲームジャンルを複数選択（チェックボックス形式）
    ↓
「保存する」ボタンをクリック
    ↓
担当ジャンル更新完了 → 管理者一覧に反映
```

#### 仕様

| 項目 | 仕様 |
|------|------|
| 選択形式 | チェックボックスによる複数選択 |
| 選択数 | 0件以上（未設定も許容） |
| 選択肢 | DBのゲームジャンルマスタに登録されている全ジャンル |
| 運営者自身による変更 | 不可（閲覧専用） |

> **補足**: 担当ジャンルが未設定の運営者は、マスタ管理において編集可能な対象が存在せず、審査ワークフローの審査者アサイン対象にもならない。

---

### 4.5 有効・無効の切り替え

管理者アカウント（運営者）およびAI運営者を一時的に審査から外す操作。無効化しても権限やデータは保持される。

#### 有効・無効の定義

| 状態 | 審査アサイン | 管理画面へのログイン（運営者のみ） |
|------|:---:|:---:|
| 有効 | 対象 | 可 |
| 無効 | 対象外 | 不可 |

- 無効化時点ですでにアサイン済みのワークフローは、アサインをそのまま維持する。
- オーナーには有効・無効の切り替えを適用しない。

#### 切り替えフロー

```
管理者一覧の対象の「無効にする」ボタンをクリック
    ↓
確認ダイアログ表示
    └─ 「無効にする」ボタン / 「キャンセル」ボタン
    ↓
無効化完了 → 管理者一覧のステータスに反映
```

```
管理者一覧の対象の「有効にする」ボタンをクリック
    ↓
確認ダイアログ表示
    └─ 「有効にする」ボタン / 「キャンセル」ボタン
    ↓
有効化完了 → 管理者一覧のステータスに反映
```

### 4.6 AI運営者管理

審査ワークフローのSTEP 1で審査者として機能するAI運営者を管理する。AI運営者の審査動作仕様は /document/specification/構想/管理 Ai運営者 審査機能仕様書.md を参照（未実装の構想。2026-11-17 時点で AI運営者による審査は作っていない）。

#### 配置

AI運営者はプラットフォーム全体で**1体固定**（`プレミテ審査AI`）。ジャンルごとに分割せず、すべての審査ワークフローのSTEP 1に共通してアサインされる。

| 項目 | 仕様 |
|------|------|
| 体数 | 1体固定 |
| 初期表示名 | `プレミテ審査AI` |
| 担当ジャンル | なし（全ジャンル共通） |
| 生成タイミング | システム初期構築時に1体のみ作成。ジャンル追加による自動生成はしない |
| 削除 | 不可（審査履歴の保持のため。無効化で対応） |

> **補足**: 削除を不可とするのは、AI運営者が審査ワークフローの審査者として記録された履歴（審査コメント等）を保持するためである。

#### 編集

オーナーはAI運営者の以下の項目を編集できる。

| 編集項目 | 内容 |
|------|------|
| 表示名 | 任意の名称に変更可 |

#### 編集フロー

```
管理者一覧のAI運営者の「編集する」ボタンをクリック
    ↓
編集モーダルを表示
    └─ 表示名入力欄（現在の名称を初期値として表示）
    ↓
「保存する」ボタンをクリック
    ↓
更新完了 → 管理者一覧に反映
```

## 5. テストモード用会員

### 5.1 概要

フロントのテストモードウィジェット（プレミテ_共通UIコンポーネント_フロント_仕様書 第7章）において、ログイン状態に切り替える際に使用するテスト専用の一般ユーザーアカウント。開発・動作確認時のみ使用する。

### 5.2 アカウントの定義

| 項目 | 仕様 |
|------|------|
| アカウント種別 | 一般ユーザー（ロールは通常の一般ユーザーと同一） |
| 用意方法 | オーナーが管理画面の設定からテストモード用会員を指定する |
| 指定可能数 | 1件 |
| アカウントの実体 | 通常のアカウント登録フローで作成した一般ユーザーアカウントをテスト用に充てる |

### 5.3 権限・制約

| 項目 | 仕様 |
|------|------|
| 機能権限 | 通常の一般ユーザーと同一 |
| 退会（管理者・本人） | 対象外（v3.0。旧版の BAN・強制退会） |

テストモード用会員に指定されている間は、ユーザー詳細画面の「退会させる」を出さず、設定ページの「退会する」を非活性（disabled）にする。

> **実装注記（v3.0）**: テスト用会員は `users.isTestUser == true` のアカウント（app/api/test/sign-in が作る2件）。5.4節の設定ページは未実装。

### 5.4 管理画面での設定フロー

オーナーのみアクセス可能な設定ページから指定する。

```
管理画面の設定ページ（オーナーのみアクセス可）
    ↓
「テストモード用会員」セクションを表示
    ├─ 現在の指定状況（ユーザー名・メールアドレス）を表示
    │     未指定の場合は「未指定」と表示
    └─ 「変更する」ボタンをクリック
         ↓
      ユーザー検索モーダルを表示
         ├─ メールアドレスまたはユーザー名で検索
         └─ 対象ユーザーを選択して「指定する」ボタンをクリック
              ↓
           確認ダイアログ表示
              └─ 「指定する」ボタン / 「キャンセル」ボタン
                   ↓
                指定完了 → 設定ページに反映
```

### 5.5 指定解除

| 項目 | 仕様 |
|------|------|
| 解除操作 | 設定ページの「テストモード用会員」セクションの「指定を解除する」ボタンから解除 |
| 解除後の挙動 | テストモードウィジェットでのログイン切り替えボタンが非活性になる |
| アカウントへの影響 | 指定解除してもアカウント自体は削除されない |

### 5.6 操作ログ

| 操作 | 記録内容 |
|------|---------|
| テストモード用会員の指定 | 操作日時・操作者・指定したユーザーID |
| テストモード用会員の指定解除 | 操作日時・操作者・解除したユーザーID |

## 6. 操作ログ

本仕様書が対象とする機能における操作ログの記録対象を定義する。操作ログの閲覧仕様はプレミテ_管理画面_機能一覧_仕様書 3.9節を参照。

### 6.1 記録対象操作

| 操作 | 記録内容 |
|------|---------|
| 退会させる（`user_withdraw`） | 操作日時・操作者・対象ユーザーID・退会理由（入力された場合） |
| 退会を解除する（`user_restore`） | 操作日時・操作者・対象ユーザーID・解除前の退会させた者 |
| 登録情報の編集（`user_profile_edit`） | 操作日時・操作者・対象ユーザーID・変更前後のユーザー名・自己紹介 |
| アイコンの削除（`user_avatar_delete`） | 操作日時・操作者・対象ユーザーID |
| 運営者ロール付与 | 操作日時・操作者・対象ユーザーID |
| 運営者ロール剥奪 | 操作日時・操作者・対象ユーザーID |
| 担当ジャンル変更（運営者） | 操作日時・操作者・対象運営者ID・変更前ジャンル・変更後ジャンル |
| 有効・無効切り替え（運営者） | 操作日時・操作者・対象運営者ID・変更後ステータス |
| AI運営者表示名変更 | 操作日時・操作者・変更前名称・変更後名称 |
| AI運営者有効・無効切り替え | 操作日時・操作者・変更後ステータス |
| テストモード用会員の指定 | 操作日時・操作者・指定したユーザーID |
| テストモード用会員の指定解除 | 操作日時・操作者・解除したユーザーID |

> 操作ログは管理者による編集・削除を不可とする。閲覧専用。

> **実装注記（v3.0）**: 第3章の4操作は `operation_logs` に記録する（括弧内は `action`）。備考の保存は記録しない（備考自体に最終更新者・日時を持つ）。操作ログの閲覧画面は未実装。

## 7. 削除ポリシー

> **v3.0（2026-11-17）**: 管理者による退会は物理削除しない（3.0節）。管理画面からアカウントを物理削除する操作は置かない（本人の退会だけが消去する。v3.1）。
> 退会中・解除後のデータの扱いはページ 設定 仕様書 §8.3、Firestore データモデル設計書 §7.1 を正とする。

| 操作 | データの扱い |
|------|---------|
| 退会（管理者） | アカウント・レビュー・マイリスト・視聴履歴・「参考になった」をすべて残す。他の人からはレビュー・プロフィール・アイコン・公開マイリストを隠す |
| 退会（本人。v3.1） | 本人の作成データとアカウントをすべて消去する（ページ 設定 仕様書 §8.3） |
| 再開・解除 | 隠していたものを元に戻す |
