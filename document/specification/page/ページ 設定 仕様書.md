## 1. 概要

### 1.1 機能概要

設定ページは、ログイン済みユーザーが自分のアカウントに関する各種設定を管理するページである。

メールアドレス・パスワード・パスキーなどの認証情報の変更、プロフィールの公開設定、ログアウト・退会といった操作を1ページに集約して提供する。

### 1.2 非スコープ

- プロフィール情報（ユーザー名・アイコン・自己紹介文）の編集（プロフィールページのインライン編集機能を使用する）

> **2026-09-20実装（フェーズ4.5ステップ6）**（表示名欄・第5章・自己紹介の扱いは下の2026-10-12更新で変わった）: 本仕様書が定義するフル版は未実装。ドッグフーディング
> （自分ひとりが本番URLで毎日使い続けられる状態）に必要な最小限の項目のみを暫定実装した
> （`app/(main)/settings/page.tsx`）。
> - **実装した項目**（いずれも本仕様書には無い、プロフィール仕様書・DB設計書からの前倒し）:
>   表示名変更（プロフィール仕様書§9.2・§9.4のバリデーション＝1〜30文字・空欄不可を流用。
>   本仕様書の非スコープ節と矛盾するが、プロフィールページ自体が未実装のため暫定的にここに置く）／
>   連続再生設定（`isContinuousPlayEnabled`、動画プレーヤーの同項目とフィールドを共有）／
>   先の話のサムネイルを隠す（`hideUpcomingThumbnails`、既定OFF、2026-09-26追加。「動画再生」カード内。
>   動画プレーヤー仕様書「先の話のサムネイルを隠す（ユーザー設定）」参照）／
>   ネタバレレビュー非表示（`hideSpoilerReviews`、レビュー一覧の同項目とフィールドを共有）／
>   マイリスト新着通知（`showNewArrivalNotification`）／ログアウト（第7章準拠）。

## 4. アカウント情報セクション

### 4.1 概要

認証に関する情報（メールアドレス・パスワード・パスキー）を管理するセクション。各項目は現在の設定状態を表示し、変更操作はモーダルで行う。

### 4.2 セクションレイアウト

```
┌─────────────────────────────────────────────────┐
│ アカウント情報                                    │
│                                                 │
│  メールアドレス                                   │
│  example@email.com          [変更する]           │
│ ─────────────────────────────────────────────── │
│  パスワード                                      │
│  ••••••••                   [変更する]           │
│ ─────────────────────────────────────────────── │
│  パスキー                                        │
│  未登録                     [設定する]           │
│  ※登録済みの場合：登録済み  [削除する]           │
└─────────────────────────────────────────────────┘
```

### 4.3 メールアドレス変更

#### 表示

| 項目 | 仕様 |
|------|------|
| 現在のメールアドレス | マスクせず全文を表示する |
| ボタン文言 | 「変更する」 |

#### モーダル仕様

| 項目 | 仕様 |
|------|------|
| モーダルタイトル | 「メールアドレスを変更する」 |
| 変更の流れ | モーダル上部に3段のステップ表示「① 申し込む → ② メールのリンクを開く → ③ ログインし直す」（提案のステップ表示と同じ部品）。入力中は①、送信後は②を今の段にする。その下に「新しいメールアドレスに確認メールが届きます。メールのリンクを開くと変更が完了するので、新しいメールアドレスでログインし直してください。」（2026-11-17 追加） |
| 表示 | 現在のメールアドレス（入力欄の上に小さく） |
| 入力フィールド | 新しいメールアドレス（テキスト入力） |
| 確認フィールド | 新しいメールアドレス（確認用・再入力） |
| 本人確認フィールド | 現在のパスワード（補足「本人確認のため、いまのパスワードを入力してください」）。Firebase Auth はメールアドレス変更の直前に本人確認（直近のログイン）を求めるため、ここで再認証する（2026-11-17 追加） |
| 送信ボタン | 「変更メールを送信する」 |
| キャンセルボタン | 「キャンセル」。クリックでモーダルを閉じる |

#### 変更フロー

```
[変更する] をクリック
    ↓
モーダルを表示
    ↓
新しいメールアドレスを入力・送信
    ↓
新しいメールアドレス宛に確認メールを送信
    ↓
モーダルに「確認メールを送信しました」と表示
    ↓
ユーザーがメール内のリンクをクリック
    ↓
/auth/action で「メールアドレスの変更が完了しました」を表示（ログアウトされる）
    ↓
新しいメールアドレスでログインし直す
```

#### 実装メモ（2026-11-17）

- 送信時の順番: 入力チェック → 現在のパスワードで再認証 → 「すでに使われていないか」をサーバーで確認
  （`POST /api/account/email/check`） → Firebase の `verifyBeforeUpdateEmail` で新しいアドレスに確認メールを送る。
- stg・本番の Firebase Auth は「メールアドレス列挙保護」が有効で、使用中のアドレスでも送信がエラーにならない
  （リンクを開いた時点で失敗する）。そのため使用中かどうかは Admin SDK で先に確かめる。登録有無を調べる窓口に
  ならないよう、ログイン必須・10分以内に再認証したトークンのみ・1人あたり10分で10回までに絞る。回数はサーバーの
  インスタンスごとのメモリで数える簡易な制限（インスタンスが増えればその分通る）で、「ログイン済み＋直前の再認証」を
  主な歯止めとする。
- 本人確認はパスワードで行うため、パスワードでログインするアカウントが前提（現状のログイン手段はメール＋パスワードのみ）。
  パスキー（§4.5）やソーシャルログインを入れるときは、その手段での再認証に対応させる。
- 送信後のモーダル表示: 「確認メールを送信しました」＋送信先アドレス＋「リンクを開くと変更が完了します。完了すると
  ログアウトされるので、新しいメールアドレスでログインし直してください。届かない場合は迷惑メールフォルダも確認」。「閉じる」ボタン。
- リンク先の画面は自前の `/auth/action`（ログイン仕様書 §9.4。2026-11-17 に Firebase 標準の白い画面から切り替え）。メール文面は Firebase のテンプレート設定（ログイン仕様書 §9.5）。送信時に言語を日本語（`languageCode = 'ja'`）にする。
  変更が完了すると、Firebase の仕様で旧アドレスにも変更の通知（元に戻すリンク付き）が届き、ログイン中の端末はログアウトされる。
- `users/{uid}.email`（登録時に書くミラー）は、設定ページを開いたときに Auth のアドレスとずれていれば
  `POST /api/account/email/sync` で合わせる（値は Auth から取る。本人は firestore.rules で email を直接書けない）。

#### バリデーション

| チェック内容 | エラーメッセージ |
|------------|---------------|
| 入力値がメールアドレスの形式であること | 「正しいメールアドレスを入力してください」 |
| 確認フィールドと一致すること | 「メールアドレスが一致しません」 |
| 現在のメールアドレスと異なること | 「現在のメールアドレスと同じです」 |
| すでに他のアカウントで使用されていないこと | 「このメールアドレスはすでに使用されています」 |
| 空欄でないこと | 「メールアドレスを入力してください」 |
| 現在のパスワードが空欄でないこと（2026-11-17 追加） | 「パスワードを入力してください」 |
| 現在のパスワードが正しいこと（2026-11-17 追加） | 「現在のパスワードが正しくありません」 |

### 4.4 パスワード変更

#### 表示

| 項目 | 仕様 |
|------|------|
| パスワード表示 | 「••••••••」（固定マスク表示）|
| ボタン文言 | 「変更する」 |
| 表示条件 | パスキーのみで登録しているユーザー（パスワード未設定）にも表示する。パスワードを新たに設定するための入口として機能する |

#### モーダル仕様

| 項目 | 仕様 |
|------|------|
| モーダルタイトル | 「パスワードを変更する」 |
| 入力フィールド① | 現在のパスワード（パスワード未設定ユーザーの場合は非表示） |
| 入力フィールド② | 新しいパスワード |
| 入力フィールド③ | 新しいパスワード（確認用・再入力） |
| 保存ボタン | 「変更する」 |
| キャンセルボタン | 「キャンセル」。クリックでモーダルを閉じる |

#### バリデーション

| チェック内容 | エラーメッセージ |
|------------|---------------|
| 現在のパスワードが正しいこと（パスワード設定済みの場合） | 「現在のパスワードが正しくありません」 |
| 新しいパスワードが8文字以上であること | 「パスワードは8文字以上で入力してください」 |
| 確認フィールドと一致すること | 「パスワードが一致しません」 |
| 空欄でないこと | 「パスワードを入力してください」 |

### 4.5 パスキー設定

パスキーはメールアドレス＋パスワードの代替認証手段として機能する。

#### 表示

| 状態 | 表示内容 | ボタン文言 |
|------|---------|----------|
| 未登録 | 「未登録」 | 「設定する」 |
| 登録済み | 「登録済み」 | 「削除する」 |

#### 登録モーダル仕様

| 項目 | 仕様 |
|------|------|
| モーダルタイトル | 「パスキーを設定する」 |
| 説明文 | 「パスキーを設定すると、パスワードの代わりに顔認証・指紋認証・PINなどでログインできます。」 |
| 登録ボタン | 「パスキーを登録する」。クリックでブラウザのパスキー登録フローを起動する |
| キャンセルボタン | 「キャンセル」。クリックでモーダルを閉じる |

#### 削除モーダル仕様

| 項目 | 仕様 |
|------|------|
| モーダルタイトル | 「パスキーを削除する」 |
| 注意書き | パスワードが未設定の場合：「パスキーを削除すると、ログインできなくなります。削除前にパスワードを設定してください。」を表示し、削除ボタンを非活性にする |
| 削除ボタン | 「削除する」（パスワード設定済みの場合のみ活性） |
| キャンセルボタン | 「キャンセル」。クリックでモーダルを閉じる |

> **設計思想**: パスキーとパスワードの両方が未設定になるとログイン不能になるため、パスキー削除はパスワード設定済みの場合のみ許可する。

## 5. プライバシー設定セクション

### 5.1 概要

プロフィールページで他のユーザーに公開する情報の範囲を設定するセクション。設定はトグルスイッチで操作する。

各設定の初期値はアカウント作成時の初期設定フロー（プロフィール設定ステップ）でユーザーが選択した値が反映される（2026-10-12時点では初期設定フローが無いため、既定はON。`init-user` が `true` で作成する）。変更はリアルタイムで保存され、保存ボタンは不要とする。

### 5.2 セクションレイアウト

```
┌─────────────────────────────────────────────────┐
│ プライバシー設定                                  │
│                                                 │
│  マイリストを公開する                 [●────]ON  │
│  他のユーザーにマイリストを公開します             │
│ ─────────────────────────────────────────────── │
│  レビュー履歴を公開する               [●────]ON  │
│  他のユーザーにレビュー履歴を公開します           │
└─────────────────────────────────────────────────┘
```

> 2026-10-12実装では、トグルスイッチの部品が無いため他の設定項目と同じチェックボックスで表示している。

### 5.3 設定項目

| 設定項目 | デフォルト | 説明文 | OFF時の挙動 |
|---------|----------|--------|-----------|
| マイリストを公開する | アカウント作成時にユーザーが選択した値（現状はON） | 「他のユーザーにマイリストを公開します」 | 自分のプロフィールページのマイリストセクションが他のユーザーから非表示になる |
| レビュー履歴を公開する | アカウント作成時にユーザーが選択した値（現状はON） | 「他のユーザーにレビュー履歴を公開します」 | 自分のプロフィールページのレビュー履歴セクションが他のユーザーから非表示になる |

> 公開設定の詳細な挙動はプロフィールページ仕様書 第2.3節を参照。

### 5.4 保存仕様

| 項目 | 仕様 |
|------|------|
| 保存タイミング | トグル操作と同時にリアルタイム保存 |
| 保存先 | Firestore の `users/{userId}` ドキュメント |
| フィードバック | 保存完了時にトースト通知「設定を保存しました」を表示 |

## 6. 通知設定セクション

### 6.1 概要

プッシュ通知の許可状態と通知種別のON/OFFを管理するセクション。
ログイン済みユーザーのみが対象であり、このページ自体がログイン必須のため全ユーザーに表示される。

### 6.2 セクションレイアウト

以下の3パターンをASCIIアートで表現すること。

**パターンA：未許可（default）状態**

```
┌─────────────────────────────────────────────────┐
│ 通知設定                                        │
│                                                 │
│  プッシュ通知を許可すると、マイリスト登録中の         │
│  シリーズに新着動画が追加されたときなどに           │
│  お知らせします。                                 │
│                                                 │
│  [通知を許可する]                                │
└─────────────────────────────────────────────────┘
```

**パターンB：許可済み（granted）状態**

```
┌─────────────────────────────────────────────────┐
│ 通知設定                                        │
│                                                 │
│  ✅ 通知が有効です                               │
│ ─────────────────────────────────────────────── │
│  再生リスト新着通知                     [●────]ON  │
│  マイリスト登録中のシリーズに新着動画が             │
│  追加されたとき                                   │
│ ─────────────────────────────────────────────── │
│  お知らせ通知                         [●────]ON  │
│  プレミテからのお知らせがあるとき                 │
└─────────────────────────────────────────────────┘
```

**パターンC：拒否済み（denied）状態**

```
┌─────────────────────────────────────────────────┐
│ 通知設定                                        │
│                                                 │
│  🚫 通知がブロックされています                   │
│                                                 │
│  ブラウザの設定から、このサイトの通知をONに         │
│  してください。                                   │
└─────────────────────────────────────────────────┘
```

### 6.3 許可状態の種別と表示

| 状態 | 条件 | 表示内容 |
|------|------|---------|
| 未許可（default） | まだ許可を求めていない | 説明文＋「通知を許可する」ボタン |
| 許可済み（granted） | ブラウザで通知を許可している | 許可済みバッジ＋通知種別トグル |
| 拒否済み（denied） | ブラウザで通知を拒否している | 拒否中バッジ＋ブラウザ設定変更の案内テキスト（ボタンなし） |

拒否済みの場合、アプリ側から再度許可を求めることはできない。ブラウザの設定からONにするよう案内するテキストを表示するにとどめる。

### 6.4 通知種別トグル

許可済み（granted）状態のときのみ表示する。

| 通知種別 | デフォルト | 説明文 |
|---------|----------|-------|
| 再生リスト新着通知 | ON | マイリスト登録中のシリーズに新着動画が追加されたとき |
| お知らせ通知 | ON | プレミテからのお知らせがあるとき |

- トグルの変更は即時反映する（保存ボタン不要）
- 設定はFirestoreのユーザードキュメントに保存する

### 6.5 「通知を許可する」ボタンの動作フロー

以下の流れをASCIIフローチャートで記述すること。

```
「通知を許可する」ボタンをクリック
    ↓
ブラウザの許可ダイアログを表示
    ↓
├── 許可の場合 ── FCMトークンを取得しFirestoreに保存 ──> 許可済み状態の表示に切り替え
└── 拒否の場合 ──> 拒否済み状態の表示に切り替え
```

詳細仕様は/document/specification/management/プレミテ FCMプッシュ通知基盤仕様書.mdの第4章を参照すること。

## 8. 退会

> **v1.11（2026-11-17）変更**: 退会は「アカウントとデータを残し、ログインできなくする」方式に変えた（チケット「ユーザー一覧ページ作成」、ユーザー決定）。
> 旧版の「すべてのデータを物理削除する」は廃止。退会はその場で行い、運営の承認は待たない（ユーザー決定）。

### 8.1 表示

```
┌─────────────────────────────────────────────────┐
│ 退会                                            │
│                                                 │
│  退会すると、このアカウントではログインできなく   │
│  なります。データは消えないので、同じメール       │
│  アドレスとパスワードでログインすれば利用を       │
│  再開できます                                    │
│                                                 │
│  [退会する]                                      │
└─────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
|------|------|
| 表示する人 | 一般ユーザーだけ（管理者は表示しない。管理画面が使えなくなるため） |
| ボタン文言 | 「退会する」（セカンダリ。確認モーダルの実行ボタンを赤系にする） |
| テスト用会員 | ボタンを非活性にし、「テスト用会員は退会できません」を添える（管理 ユーザー管理仕様書 §5.3） |

### 8.2 確認モーダル仕様

| 項目 | 仕様 |
|------|------|
| モーダルタイトル | 「退会しますか？」 |
| 本文 | 「退会すると、このアカウントではログインできなくなります。」「投稿したレビュー・マイリスト・プロフィールは他の人から見えなくなります。データは消えないので、同じメールアドレスとパスワードでログインすれば、いつでも利用を再開できます。」 |
| 退会の理由（任意） | ラジオボタン（使わなくなった／見たい再生リストが見つからない／使い方がわかりにくい／別のアカウントを使う／その他）と自由記述（任意）。合わせて500文字以内。`users.withdrawReason` に「選択肢：自由記述」で保存し、管理画面で見られる |
| 実行ボタン | 「退会する」（赤系スタイル） |
| キャンセルボタン | 「キャンセル」。クリックでモーダルを閉じる |

### 8.3 退会処理（`POST /api/account/withdraw`）

| 対象 | 処理 |
|------|------|
| ユーザードキュメント | `users/{userId}` に `accountStatus: "withdrawn"`・`withdrawnAt`・`withdrawnBy: "self"`・`withdrawReason` を書く。ドキュメントは消さない |
| Firebase Auth | アカウントは消さず、無効化もしない（再開時にパスワードを確かめるため）。ログイン中の端末のトークンを失効させる |
| レビュー | 消さない。`reviews.isAuthorWithdrawn: true` を付けて他の人から隠し、再生リストのスコア・件数から外す（関係する再生リストのスコアを計算し直す） |
| プロフィール・アイコン・公開マイリスト | 消さない。公開プロフィール（`/api/users/{uid}/profile`）とアイコンの配信を 404 にする |
| マイリスト・視聴履歴・視聴位置・「参考になった」 | 消さない（本人しか見ないため、そのまま残す。押した「参考になった」のカウントも残す） |

> 退会中はログインできない（ページ ログイン 仕様書 §5.5）。本人が退会した場合は、同じメールアドレス・パスワードでログインして「利用を再開する」を選ぶと、上表の印をすべて外して元どおりになる。

### 8.4 退会後の遷移

| 項目 | 仕様 |
|------|------|
| 処理 | ログアウトし、「退会しました」のトーストを出す |
| 遷移先 | トップページ（`/`） |
