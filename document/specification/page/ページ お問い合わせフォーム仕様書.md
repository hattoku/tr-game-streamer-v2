## 1. 概要

本仕様書は、プレミテのお問い合わせフォームページ（`/contact`）の仕様を定義する。

ログイン・未ログインを問わず全ユーザーがお問い合わせを送信できる。ログイン済みユーザーはスレッド形式でやり取りを継続できる。未ログインユーザーへはメール折り返しのみで対応する。

> **実装状況（2026-10-14、フェーズ7ステップ7-3-1）**: 本仕様のフォーム・バリデーション・送信完了画面を実装済み
> （`app/(main)/contact`、`components/contact/ContactForm.tsx`、送信は `POST /api/inquiries`）。
> - 入力チェックは `lib/inquiry-shared.ts` をフォームと API で共有し、§6 の文言をそのまま使う。
> - ログイン済みのメールアドレス・表示名は、クライアントの値ではなくサーバー側でアカウントから取る（§3 の「返信先を確実に確保する」ため）。
> - 送信完了画面の `/contact/history` へのリンク（§7）は、2026-10-24（ステップ7-3-2）に追加した。ログイン済みのときだけ表示する。
> - アカウントにメールアドレスが無いログイン済みユーザー（メールアドレスを返さないソーシャルログイン等）は、未ログインと同じくメールアドレス欄を入力してもらい、その値を返信先にする（§3 では想定していなかったケース）。
> - 管理者へのメール通知は未実装（管理 お問い合わせ管理仕様書 実装注記参照）。

## 3. フォーム項目

| 項目 | 種別 | 必須 | ログイン済み | 未ログイン |
|------|------|:---:|:---:|:---:|
| お問い合わせ種別 | セレクトボックス | ○ | 入力 | 入力 |
| お問い合わせ内容 | テキストエリア | ○ | 入力 | 入力 |
| 関連URL | テキスト入力（最大5件） | × | 入力 | 入力 |
| メールアドレス | テキスト入力 | ○ | 自動入力（編集不可） | 入力 |
| 画像 | ファイル選択（最大3枚） | × | 入力 | 表示しない |

> **メールアドレスの自動入力について**: ログイン済みユーザーはアカウントに登録されているメールアドレスを自動入力し、編集不可とする。返信先を確実に確保するための仕様。

> **画像について**: 不具合の調査に役立つスクリーンショット等を添えてもらうための項目。ログイン済みユーザーだけが添付できる（§9）。

## 4. お問い合わせ種別

| 種別 | フォーム内補足テキスト |
|------|----------------------|
| 不具合・バグ報告 | サービスの動作に関する不具合・バグのご報告 |
| アカウントについて | ログイン・退会・アカウント情報に関するお問い合わせ |
| 掲載内容について | 誤情報・権利侵害・不適切なコンテンツ等に関するご連絡 |
| ご意見・ご要望 | サービスへのご意見・新機能のご要望 |
| その他 | 上記に該当しないお問い合わせ |

種別を選択すると、対応する補足テキストをセレクトボックス直下に表示する。

## 7. 送信フロー

```
フォーム入力
    ↓
バリデーション
    ↓
「送信する」ボタンをクリック
    ↓
送信完了画面を表示
    ├─ ログイン済み：「お問い合わせを受け付けました。
    │                お問い合わせ履歴からやり取りを確認できます。」
    └─ 未ログイン ：「お問い合わせを受け付けました。
                    ご入力のメールアドレスに折り返しご連絡いたします。」
```

送信完了後、ログイン済みユーザーには `/contact/history` へのリンクを表示する。

## 9. 画像の添付

> **2026-10-27 追加**（計画: お問い合わせ画像添付 実装計画、2026-10-25 ユーザー決定）。不具合の原因を調べやすくするため、画像に限って添付を認める。
> ファイル添付で増える危険（不正なファイル・個人情報の漏れ・容量の乱用）を、§9.2〜§9.6 の制限と処理でまとめて抑える。
> スレッドの返信での添付（ページ お問い合わせ履歴 仕様書 §4）と、管理画面での表示（管理 お問い合わせ管理仕様書 §4.6）も本章の定めに従う。

### 9.1 添付できる人・場面

| 項目 | 仕様 |
|------|------|
| 添付できる人 | ログイン済みユーザーのみ。未ログインのフォームには添付欄を表示せず、API もゲストの添付を 400 で拒否する（匿名でファイルを置ける入口を作らないため。ゲストの追加資料はメールで受け取る） |
| 添付できる場面 | お問い合わせフォームの送信と、お問い合わせ履歴のスレッドへの返信（ユーザー側）。管理者の返信には添付できない |
| お問い合わせ種別 | 種別では制限しない（どの種別でも添付できる） |

### 9.2 制限

| 項目 | 上限 |
|------|------|
| 形式 | PNG・JPEG・WebP のみ（SVG・GIF・HEIC 等は不可） |
| 1回の送信あたりの枚数 | 3枚 |
| 1枚のファイルサイズ | 5MB |
| 1枚の画素数 | 4,000万画素（解凍爆弾対策。超えると読み込まない） |
| 1日の枚数 | ユーザーごとに20枚（フォームの送信とスレッドの返信の合計。日付は日本時間で区切る） |

### 9.3 入力欄

- 「画像を追加する」ボタンでファイルを選ぶ（複数選択可）。選んだ画像はサムネイルで並べ、各サムネイルの「×」で外せる。3枚に達したらボタンを隠す。
- 入力欄の下に「PNG・JPEG・WebP、1枚5MBまで・3枚まで」と「スクリーンショットにメールアドレスなどの個人情報が写っていないかご確認ください」を常に表示する（エラーはその上に出す）。
- 画像だけの送信はできない（お問い合わせ内容・返信の本文は従来どおり必須）。

### 9.4 バリデーション

ブラウザで選んだ時点に確認し、サーバーでも必ず同じ確認をする（ブラウザの確認は省略できる前提で扱う）。

| チェック内容 | エラーメッセージ |
|------------|----------------|
| 形式が PNG・JPEG・WebP 以外 | 「PNG・JPEG・WebP の画像を選択してください」 |
| 1枚が5MBを超える | 「1枚5MB以内の画像を選択してください」 |
| 4枚目以降を選んだ | 「画像は3枚まで添付できます」 |
| 画像として読み込めない・画素数の上限を超える（サーバーのみ） | 「画像を読み込めませんでした。別の画像を選択してください」 |
| 1日の上限を超える（サーバーのみ） | 「本日添付できる画像の上限（20枚）に達しました。明日以降に送信してください」 |

1枚でも不合格なら、お問い合わせ（返信）自体を保存せずにエラーを返す（一部の画像だけが付いた状態を作らない）。

### 9.5 サーバーでの処理

| 危険 | 処理 |
|------|------|
| 画像に見せかけた不正なファイル | 拡張子・ブラウザが申告する MIME は使わず、ファイル先頭のバイト列で形式を判定する。さらに画像を描き直して（再エンコード）保存するため、元ファイルのバイト列は保存されない（このためウイルススキャンは行わない） |
| 写真の位置情報（EXIF 等）の残存 | 再エンコード時にメタデータを全て除く。向き（Orientation）は画素に反映してから除く |
| 巨大な画像 | 画素数の上限（§9.2）で読み込みを止める。保存時は長辺4,096pxまで縮小する |
| ファイル名の悪用 | 元のファイル名は使わず、保存名はランダムなIDにする |

再エンコード後の形式は元と同じ（PNG→PNG、JPEG→JPEG、WebP→WebP。アニメーションは1枚目のみ）。

### 9.6 保存と閲覧

| 項目 | 仕様 |
|------|------|
| 保存先 | Cloud Storage（Firebase のデフォルトバケット）の `inquiries/{inquiryId}/{id}.{png｜jpg｜webp}`。`storage.rules` でクライアントからの読み書きを全て拒否し、サーバー（Admin SDK）だけが扱う |
| 閲覧できる人 | 送信者本人（お問い合わせ履歴）と管理者（オーナー・運営者）のみ。API 経由で配信し、Firestore に未削除の添付として記録がある画像だけを返す。本人用 API は本人以外・削除済みに 404、管理者用 API は一般ユーザーに 403（他の管理 API と同じ）、未ログインはどちらも 401。公開URL・期限付きURLは発行しない |
| 配信時のヘッダー | `Content-Type` を保存形式に固定し、`X-Content-Type-Options: nosniff`・`Content-Security-Policy: default-src 'none'`・`Cache-Control: private, no-store` を付ける |
| 表示 | サムネイルで並べ、クリックで拡大表示する。ダウンロードボタンは付けない（管理者の手元にコピーが残り、保存期間の決まりが効かなくなるため） |
| 保存期間 | お問い合わせが「対応済み」になってから180日で画像だけを削除する（本文・やり取りは残す）。再オープンすると期限は数え直し。削除は毎日1回の自動処理（Cloud Scheduler）で行い、削除済みの画像の場所には「保存期間を過ぎたため削除しました」と表示する（管理 お問い合わせ管理仕様書 §6） |
