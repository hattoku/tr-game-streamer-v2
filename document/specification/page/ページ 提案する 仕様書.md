## 1. 目的

これまで「再生リストを提案する」（`/playlists/new`）と「チャンネルを申請する」（`/channels/apply`）が別ページで、次の迷いがあった。

- 再生リストを提案しに来たが、チャンネルごと推薦したい
- チャンネルを推薦しようとしたら掲載済みで、本当は再生リストを提案したい
- 一般ユーザーは YouTube の「再生リストのページ」「チャンネルのページ」の URL をコピーするのが難しい（手元にあるのは「見ていた動画」）

このため、提案ページを1つにまとめ、上部で「再生リスト｜チャンネル」を選ぶ形にする。あわせて、**掲載中のチャンネルの再生リストは URL を使わず一覧から選ぶ**形にする（掲載中のチャンネルの再生リストは巡回で全件 `playlists` に取り込み済みのため）。

## 2. ページURL・アクセス条件

| 項目 | 内容 |
|---|---|

| クエリ | `type=playlist`（既定）／`type=channel`、`channelId=<プレミテのチャンネルID>`（再生リストの提案でチャンネル固定）、`gameId=`（ゲーム選択済み）、`channel=<YouTubeのURL・ID>`（チャンネル側の入力欄に入れて開く）、`as=creator`（実況者向けページから来た。チャンネル側の送信ボタンを「申請する」にする。区分は記録しない。§6.1）、`url=`（再生リストのURL入力に入れて開く。管理画面からの導線用） |

| アクセス | ログイン済みユーザー。未ログインは `/login?next=<今のパスとクエリ>` へ送り、ログイン後に戻す（今と同じ） |
| 見出し | 一般ユーザー「提案する」／管理者「追加する」 |

## 3. 画面の構成

```
┌──────────────────────────────────────────────┐
│ 提案する                                        │
│ [ 再生リスト ] [ チャンネル ]   ← 切り替え（§4）    │
│ ① 提案する → ② 運営が確認 → ③ 公開              │  ← 一般ユーザーのみ。③の文言は側ごと（§5.5・§6.4）
│                                               │
│ （選んだ側のフォーム：§5 再生リスト／§6 チャンネル）  │
└──────────────────────────────────────────────┘
```

- 切り替えはページ内のタブ（`role="tablist"`）。切り替えると `type` をアドレスに反映する（戻る・共有で同じ側が開く）。
- 入力した内容は側ごとに保持し、タブで切り替えても消さない（§7 のボタンで移ったときは、引き継いだ内容で移った先を入れ直す）。
- 「実況者・事務所の方へ」の案内カード（再生リストを追加する §10.6）は廃止する。実況者向けページの「掲載を申請する」（`as=creator`）で受ける。

## 5. 再生リスト側

### 5.1 チャンネルを選ぶ

```
どのチャンネルの再生リストですか
[ 🔍 チャンネル名で探す                      ]
  ┌───────────────────────────────┐
  │ (icon) チャンネルA                │
  │ (icon) チャンネルB                │
  └───────────────────────────────┘
探しているチャンネルが無いとき → チャンネルを推薦する   ← チャンネル側へ切り替え（§7）
```

- 掲載中のチャンネル（`exploration_channels.status == active`。同じチャンネルに掲載停止の記録があれば除く）だけを、チャンネル名の部分一致で探す（ハンドルは持っていないので対象外）。プレミテ内の検索で、YouTube の検索は使わない（API を消費しない）。
- 1文字以上入れると候補を最大10件出す。候補はアイコン・チャンネル名。
- `channelId` 付きで来たときはこの手順を飛ばし、選択済みのチャンネルを上部に表示する（変更不可）。

### 5.2 再生リストを選ぶ

```
(icon) チャンネルA                        [チャンネルを変える]
[ 🔍 再生リスト名で絞り込む               ]

まだ公開していない再生リスト（提案できます）
 ( ) [thumb] 【ゲームX】初見実況          動画 32本
 ( ) [thumb] 【ゲームY】縛りプレイ        動画 18本
 ▸ 公開の対象外になっている再生リスト（8件）   ← 折りたたみ
公開中の再生リスト
     [thumb] 【ゲームZ】全クリまで  公開中 → 詳細へ
一覧に無いときは → URLで入力する                    ← §5.3
```

| 再生リストの状態 | 表示 | 選べるか |
|---|---|---|
| 公開中（`listed`） | 「公開中」のラベルと再生リスト詳細へのリンク。一覧の最後にまとめる | 選べない |
| 未確認（`unconfirmed`） | 「まだ公開していない再生リスト」 | 選べる |
| 自動判定で対象外（`non_game`・`too_short`・`excluded`、どれも `listingSetBy: auto`） | 折りたたみの「公開の対象外になっている再生リスト」。開くと理由の短い表示（`non_game`「ゲーム以外と判定」、`too_short`「動画が10本未満」、`excluded` は `listingReason` が `word:` で始まれば「除外のことばに該当」、それ以外は「公開の対象外」） | 選べる。選ぶと「公開してほしい理由（任意・200文字まで）」欄を出す |
| 運営が手で外したもの（`listingSetBy: admin` で `listed` 以外） | 出さない | — |
| `channel_off` | 出さない | — |
| 同じ再生リストの提案が審査中（自分・他の人を問わない） | 「提案済み（確認待ち）」。自分の提案なら「あなたが提案済み（確認待ち）」（行全体がボタンのためリンクは置かない） | 選べない |

- 並び順は YouTube の再生リストの作成日の新しい順（巡回で持っている値。無ければ取り込み日）。
- 一覧の API はそのチャンネルの全件を返し、画面で最初に30件出して「もっと見る」で続きを出す。再生リスト名での絞り込み欄を置く。
- 選ぶと一覧を閉じて「選んだ再生リスト」として表示し（「選び直す」で一覧に戻る）、その下にゲームタイトル（§5.4）と送信を出す。
- 一覧は新しい API（ログイン必須）で返す（§10）。運営メモなど内部向けの項目は返さない。

### 5.3 一覧に無いときの URL 入力

巡回より後に作られた再生リストなど、一覧に無いときのための入力。今の「再生リストURL」入力と確認エリア（再生リストを追加する §4.1）をそのまま使う。

- 受け付ける入力: 再生リストのURL、再生リストの中の動画を再生中のURL（`watch?v=…&list=…`）。
- 確認エリアの判定は今どおり（公開状態・チャンネル一致・登録済み・掲載チャンネルか）。掲載していないチャンネルなら「このチャンネルはまだ掲載していません」とし、ボタン「このチャンネルを推薦する」でチャンネル側へ切り替える（§7）。
- 入力欄の下に「URLのコピーのしかた」（§8）を出す。

### 5.4 ゲームタイトル

- 再生リストを選ぶと、巡回で推定したゲーム（`playlists.gameId`）を**初期値として選んだ状態**でゲームタイトル欄を出す。推定できていなければ空欄。
- **任意**。変更も空欄のまま提案もできる。欄の下に「ゲームが分からない場合は空欄のままで大丈夫です」。
- 選び方（登録済みの検索・楽天ブックスの候補・新しいゲームタイトルの入力・似た名前の案内）は今と同じ（再生リストを追加する §4.2・§9.2）。
- 空欄で送った提案は `noGame: true`（データモデル設計書 §3.15）。承認時に運営がゲームを決めるか、ゲーム未設定のまま公開する（審査ワークフロー仕様書 §4.2）。

### 5.5 送信と完了

- 送信ボタン「提案する」。上に「送信後、運営の確認が済むまで公開されません」。
- 一覧から選んだもの: `workflows`（`type: playlist_register`）に、既存の再生リストのID、提案時点の掲載状態（`existingListingStatus`）、ゲーム（または `noGame`）、理由（対象外を選んだとき。URL 入力ですでにある `unconfirmed` 以外の再生リストのときも）を保存する。
- URL 入力のもの: 今の提案と同じ（`playlists` に無ければ新規の提案）。
- ステップ表示 ③ は「さがすに公開」。完了画面・提案履歴・審査結果の通知は今と同じ（再生リストを追加する §6.2・§9.1・§9.4）。

## 6. チャンネル側

### 6.1 入力

```
推薦・申請するチャンネル
[ YouTubeのチャンネルや動画のURL             ]
 ▸ URLのコピーのしかた（パソコン／スマホ）        ← §8
┌ チャンネルの確認 ─────────────┐
│ (icon) チャンネル名  登録者 12万人      │
└─────────────────────────┘
推薦・申請の理由（任意・200文字まで）
                                  [推薦する]   ← 実況者向けページから来たときは「申請する」
```

- 今のチャンネル申請のフォーム（チャンネルを申請する §4）をそのまま使う。
- 受け付ける入力に**動画のURL**を加える（`watch?v=…`・`youtu.be/…`・`/shorts/…`・`/live/…`）。動画の投稿チャンネルとして扱う（`videos.list` 1ユニット＋`channels.list` 1ユニット）。今受け付けているもの（チャンネルURL・@ハンドル・UC…・再生リストURL）はそのまま。
- **申請の区分（自分・事務所／推薦）は画面で聞かず、記録もしない**（2026-11-16 ユーザー決定。区分は審査画面・掲載チャンネル一覧に出す参考情報で、審査の動きには使っていなかったため）。審査画面の「申請の種別」も出さない。承認したチャンネルの掲載の入口（`authorizedVia`）は `channel_application`。実況者向けページから来たとき（`as=creator`）は送信ボタンを「申請する」、それ以外は「推薦する」にする（文言だけ）。

### 6.2 受け付けないチャンネル

今と同じ（チャンネルを申請する §4）。ただし「既に掲載中」のときの案内を変える。

| 状態 | 表示 |
|---|---|
| 既に掲載中（`active`） | 「このチャンネルはすでに掲載しています」＋ボタン「**このチャンネルの再生リストを提案する**」（再生リスト側へ切り替え、そのチャンネルを選んだ状態で §5.2 から。§7）＋チャンネル詳細へのリンク |

上限（1人1日5件）・重複申請の扱い（審査中の申請があれば受け付けない）も今と同じ。

### 6.3 送信と完了

今と同じ（`workflows`、`type: channel_application`）。完了画面・提案履歴・通知も今と同じ。

### 6.4 ステップ表示

③ は「チャンネルに公開」（今と同じ）。

## 8. URLのコピーのしかた（チャンネル側・再生リスト側のURL入力）

入力欄の下に折りたたみで出す（初めは閉じる）。パソコン／スマホの切り替え付き。図はイラスト（YouTube のロゴ・画面写真は使わない）。

| | パソコン | スマホ（YouTubeアプリ） |
|---|---|---|
| チャンネル側 | そのチャンネルの動画かチャンネルのページを開き、ブラウザ上部のアドレス欄をコピー | 動画の下の「共有」→「リンクをコピー」（チャンネルのページなら右上の︙→「共有」→「リンクをコピー」） |
| 再生リスト側（URL入力） | 再生リストのページ、または再生リストの中の動画を開き、アドレス欄をコピー | 再生リストを開き「共有」→「リンクをコピー」 |

## 9. 管理者

同じページを使い、その場で登録・公開する。

| 側 | 動き |
|---|---|
| 再生リスト（一覧から選ぶ） | 一覧に運営が手で外したものも出す（「運営が非表示」ラベル）。ボタン「公開する」で、その場で `listed`（`listingSetBy: admin`）にし、まだ取っていなければ動画一覧を取る。掲載の既定のタグ（チャンネル単位・タイトル由来）も付ける。ゲームタイトルは任意（選べばそのゲームに付け替え、空欄なら今のゲームのまま）。ステップ表示は出さない |
| 再生リスト（URL入力） | 今の直接登録と同じ。掲載していないチャンネルの再生リストなら、チェックボックス「このチャンネルを掲載するチャンネルに加える」（既定オン、掲載方法「確認してから掲載」）を出し、オンで登録するとチャンネルも掲載チャンネルに加える。オフでは登録できない。`opted_out` のチャンネルは登録できない（再生リストを追加する §10.4） |
| チャンネル | フォームは出さず、「管理者は掲載チャンネル画面から直接登録できます」と `/admin/collection/channels` へのリンクを出す（今と同じ） |

## 10. API

| API | 内容 |
|---|---|
| `GET /api/propose/channels?q=`・`?id=` | 掲載中のチャンネルを名前で探す（最大10件）、または1件引く。ログイン必須。名前での検索は掲載チャンネルの一覧をサーバーで1分キャッシュする（1件引くとき・提案や承認の確認ではキャッシュを使わない） |
| `GET /api/propose/channels/{channelId}/playlists` | §5.2 の一覧（全件）。状態ごとの並び・審査中の提案の有無を返す。ログイン必須。管理者には手で外したものも返す |
| `POST /api/playlists/propose` | 既存の再生リストの提案（`playlistId` 指定）を受け付けるよう拡張。理由（任意）を追加 |
| `POST /api/playlists/register`（管理者） | 既存の再生リストの「公開する」（`playlistId` 指定）と、§9 のチャンネル同時掲載を追加 |
| `POST /api/channels/apply/preview`・`/apply` | 動画のURLを受け付けるよう拡張 |

提案・承認時のチェック（掲載チャンネルか、審査中の重複、運営が外したものでないか）はサーバー側で必ず確かめ直す。

## 11. 審査側への影響

- 審査ワークフロー仕様書 §4.2 の未実装の行（ゲーム任意、掲載していない再生リストの提案）を実装する。
- 審査詳細に「提案時点の掲載状態」と、対象外を選んだときの「公開してほしい理由」を出す。
- 承認のとき運営が手で外したものになっていたら承認できない（「運営が非表示にしたため承認できません」）。
- ゲームが分からない提案（`noGame`）は、ゲームを選ばずに承認できる（新しい再生リストはゲーム未設定、すでにある再生リストは今のゲームのまま）。新しいゲームタイトル付きの提案は今どおり、ゲームを決めてから承認する。
