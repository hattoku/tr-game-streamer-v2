## 1. 概要

プレミテは、実況者本人・公式のチャンネル（社内では「掲載チャンネル」と呼ぶ。**この言葉は画面には出さない**）の再生リストを掲載する（プレミテ企画書 §0.0）。本ページは、まだ掲載していないチャンネルを掲載してほしいときに申請するページである。

| 申請する人 | 画面での呼び方 |
|---|---|
| 実況者本人・所属事務所 | 「自分（または所属事務所）のチャンネルを申請する」 |
| 視聴者 | 「好きなチャンネルを推薦する」 |

どちらも同じ審査（管理 審査ワークフロー仕様書 §15.2）を通り、掲載するかは運営が決める。基準は「実況者本人、または公式のチャンネルであること」（切り抜き・転載・まとめチャンネルは掲載しない）。

---

## 2. ページURL・アクセス条件

| 項目 | 内容 |
|------|------|
| URL | `/channels/apply`（任意で `?channel=<チャンネルID・URL>` を受け、入力欄に入れた状態で開く） |
| アクセス条件 | ログイン済みユーザー（一般ユーザー）。未ログインは `/login?next=/channels/apply…` へ送り、ログイン後に戻す（再生リスト提案と同じ） |
| 管理者 | 申請はできない。管理者が開いたときは「管理者は掲載チャンネル画面から直接登録できます」と案内し、`/admin/collection/channels` へのリンクを出す |

> 会員登録をしたくない実況者・事務所の方は、お問い合わせ（ゲストも送れる）からも申請を受ける（ページ 実況者・事務所の方へ 仕様書 §4）。

---

## 3. 流入導線

| 流入元 | 導線 |
|---|---|
| 再生リストを追加する（一般ユーザー） | 提案しようとした再生リストのチャンネルが未掲載のとき、「先にチャンネルの申請をお願いします」のボタン（`?channel=` 付き。ページ 再生リストを追加する 仕様書 §10） |
| チャンネルから探す | 一覧の下（空状態を含む）に「探しているチャンネルが無いときは → チャンネルを申請する」 |
| 実況者・事務所の方へ | 「掲載を申請する」ボタン |

## 4. フォーム

```
┌─────────────────────────────────────────────┐
│ チャンネルを申請する                            │
│ ① 申請する → ② 運営が確認 → ③ チャンネルに公開   │  ← 提案のステップ表示と同じ部品（UIコンポーネント §2.11）
│                                             │
│ チャンネルのURL                                │
│ [ https://www.youtube.com/@...            ] │
│ ┌ チャンネルの確認 ────────────────┐          │
│ │ [icon] チャンネル名  登録者 12万人        │   │
│ └──────────────────────────────┘          │
│                                             │
│ どちらで申請しますか                            │
│ ( ) 自分（または所属事務所）のチャンネル          │
│ ( ) 好きなチャンネルを推薦する                   │
│                                             │
│ 申請の理由（任意・200文字まで）                  │
│ [                                         ] │
│ 送信後、運営の確認が済むまで公開されません         │
│                              [申請する]       │
└─────────────────────────────────────────────┘
```

| 項目 | 仕様 |
|---|---|
| チャンネルのURL | `https://www.youtube.com/@handle`・`/channel/UC…`・`@handle`・`UC…` を受け付ける。入力から少し待つ（またはフォーカスを外す）と YouTube から取得してチャンネルの確認を出す（`channels.list`、1ユニット。名前での検索はしない） |
| 再生リストのURLを入れた場合 | 再生リストの所属チャンネルを取り、そのチャンネルとして扱う |
| チャンネルの確認 | アイコン・チャンネル名・登録者数（非公開なら出さない）と、YouTube でチャンネルを開くリンク |
| 申請の種別 | 必須。「自分（または所属事務所）のチャンネル」／「好きなチャンネルを推薦する」 |
| 申請の理由 | 任意、200文字まで |

**受け付けないチャンネル**（チャンネルの確認の下に出し、「申請する」を押せなくする）

| 状態 | 表示 |
|---|---|
| 既に掲載中（`active`） | 「このチャンネルはすでに掲載しています」＋チャンネル詳細へのリンク |
| 掲載を止めている（`opted_out`） | 「このチャンネルは掲載していません」（理由は出さない） |
| 自分の審査中の申請がある | 「このチャンネルは申請済みです（確認待ち）」＋提案履歴へのリンク |
| チャンネルが見つからない | 「チャンネルが見つかりませんでした。URLをご確認ください」 |

- 掲載しない（`excluded`）にしたチャンネルも申請は受け付ける（運営が改めて判断する）。
- 1日あたりの申請数の上限（仮: 5件）を超えたら「本日の申請の上限に達しました」と出す（上限の値は実装時に決める）。

## 5. 送信と完了画面

- 「申請する」で審査ワークフロー（`workflows`、`type: "channel_application"`。データモデル設計書 §3.15）を作る。作成は API Route（Admin SDK）経由。YouTube の情報はサーバー側で取り直して保存する。
- 完了画面: 見出し「申請を送りました（確認待ち）」、ステップ表示で②に「いまここ」。説明「運営が確認し、掲載が決まるとお知らせでお伝えします。掲載が決まったチャンネルの再生リストは、運営の確認のあと順に公開します」。ボタン「提案履歴を見る」「TOPへ戻る」。

---

## 6. 申請後

- 申請は「提案履歴」（`/playlists/proposals`）に、再生リストの提案と並べて出す（種別「チャンネル申請」、チャンネルのアイコン・名前、状態）。
- 審査結果はサイト内通知（`review_result`）で届く（管理 審査ワークフロー仕様書 §15.2）。見送りは定型の理由（同 §15.4）を出す。
