## 1. 概要

### 1.1 機能概要

「再生リストを追加する」は、プレミテにゲーム実況の再生リストを登録するための機能である。YouTubeの再生リストURLとゲームタイトルを入力することで、プレミテ上に新しい実況シリーズを追加できる。

ユーザー種別によって操作の結果が異なる。

| ユーザー種別 | 操作の結果 |
|------------|-----------|
| 管理者（オーナー・運営者） | 入力内容がそのまま本番DBに登録される |
| 一般ユーザー | 入力内容が「提案」としてFirestoreの専用提案コレクションに保存される。管理者が承認するまでサイト上には公開されない |

### 1.2 アクセス条件

| 条件 | 内容 |
|------|------|
| 管理者アカウント（Firebase Auth）でログイン済み | ✅ アクセス可能（登録フロー） |
| 一般ユーザーでログイン済み | ✅ アクセス可能（提案フロー） |
| 未ログインユーザー | ❌ アクセス不可（ログインページへリダイレクト） |

> **補足**: アクセス制御はFirebase Authのロール判定による。未ログインユーザーがURLに直接アクセスした場合もリダイレクトする。

### 1.3 ページURL

| 項目 | 内容 |
|------|------|
| URL | `/playlists/new` |
| ヘッダーナビゲーション | 表示する |

### 1.4 流入元

本ページへの導線は以下の3箇所から提供される。管理者・一般ユーザーともに同じ導線を使用する。

| 流入元 | 導線 | 備考 |
|--------|------|------|
| ゲームタイトル詳細ページ | 「再生リストを追加する」ボタン | ゲームタイトルがデフォルト指定された状態で遷移 |
| チャンネル詳細ページ | 「再生リストを追加する」ボタン | チャンネルが固定指定された状態で遷移 |
| 再生リストを探すページ | 「再生リストを追加する」ボタン | 特になし |

## 3. 流入元による表示の違い

### 3.1 通常流入（再生リストを探すページから）

案内エリアは表示しない。フォームのみ表示する。

### 3.2 ゲームタイトル詳細ページから流入した場合

ページ上部にゲームタイトルを示す案内エリアを表示する。ゲームタイトル選択フォームはデフォルトで選択済みの状態になる（変更可能）。

```
┌───────────────────────────────────────────────────────┐
│ 🎮  「ゼルダの伝説 ブレス オブ ザ ワイルド」の          │
│      再生リストを追加する                               │
└───────────────────────────────────────────────────────┘
```

| 要素 | 内容 |
|------|------|
| アイコン | 🎮（ゲームコントローラー） |
| テキスト | 「{ゲームタイトル名}」の再生リストを追加する |
| ゲームタイトル選択フォーム | 対象ゲームタイトルがデフォルト選択済み（変更可能） |

### 3.3 チャンネル詳細ページから流入した場合

ページ上部にチャンネルを示す案内エリアを表示する。フォームはチャンネルに関する項目を持たないが、登録・提案処理時にチャンネルの一致確認を行う（第5章参照）。

```
┌───────────────────────────────────────────────────────┐
│ ⚬ チャンネルアイコン  「◯◯ゲームズ」の                 │
│                       再生リストを追加する              │
└───────────────────────────────────────────────────────┘
```

| 要素 | 内容 |
|------|------|
| チャンネルアイコン | 円形のチャンネルサムネイル |
| テキスト | 「{チャンネル名}」の再生リストを追加する |
| フォームへの影響 | フォーム自体の変更なし。ただし処理時にチャンネル一致確認を実施 |

> **実装注記（2026-09-22、フェーズ6ステップ1）**: `/playlists/new?channelId={youtubeChannelId}` で流入し、`channels/{id}` を
> クライアントSDKで取得して案内エリアを表示する。チャンネル一致確認はURLプレビュー時（`/api/playlists/preview` の
> `channel.youtubeChannelId` と流入元IDの比較）に確認エリアへNG行＋インラインエラー＋トーストで示し、本登録API
> （`/api/playlists/register`）にも `sourceChannelId` を渡して不一致なら `422 channel_mismatch` で拒否する（二重チェック）。

## 4. フォーム仕様

### 4.1 再生リストURL入力

| 項目 | 仕様 |
|------|------|
| 入力形式 | テキスト入力フィールド |
| プレースホルダー | 「https://www.youtube.com/playlist?list=...」 |
| 取得タイミング | フォーカスが外れた（blur）タイミングで自動的にYouTube APIへ情報取得リクエストを送信 |
| 有効なURL形式 | YouTubeの再生リストURL（`playlist?list=` を含むURL）のみ |

#### 4.1.1 再生リスト確認エリア

URLが有効な場合、入力フィールドの下に再生リストの情報を自動表示する。同時に、登録可否に関わる制約チェック（公開状態・チャンネル一致）の結果もあわせて表示する。

**正常時（登録可能な状態）**

```
┌───────────────────────────────────────────────────────────┐
│ ┌──────────────┐  再生リストタイトル                       │
│ │              │                                          │
│ │ 再生リスト   │  ⚬ チャンネルアイコン  チャンネル名       │
│ │ サムネイル   │                                          │
│ │ （16:9）     │  動画数: 42本                            │
│ │              │                                          │
│ └──────────────┘                                          │
│                                                           │
│ ✅ 公開されている再生リストです                            │
│ ✅ チャンネルが作成した再生リストです                      │
└───────────────────────────────────────────────────────────┘
```

**エラー時（登録不可な状態）**

```
┌───────────────────────────────────────────────────────────┐
│ ┌──────────────┐  再生リストタイトル                       │
│ │              │                                          │
│ │ 再生リスト   │  ⚬ チャンネルアイコン  チャンネル名       │
│ │ サムネイル   │                                          │
│ │ （16:9）     │  動画数: 42本                            │
│ │              │                                          │
│ └──────────────┘                                          │
│                                                           │
│ ❌ この再生リストは非公開または限定公開のため登録できません │
└───────────────────────────────────────────────────────────┘
```

| 表示要素 | 詳細 |
|---------|------|
| 再生リストのサムネイル | YouTube APIから取得したサムネイル画像（アスペクト比 16:9） |
| 再生リストのタイトル | YouTube APIから取得した再生リストのタイトル |
| チャンネルアイコン | 小さな円形のチャンネルサムネイル |
| チャンネル名 | YouTubeチャンネル名 |
| 動画数 | 再生リストに登録されている動画数（例：「動画数: 42本」） |
| 公開状態チェック結果 | 公開（public）の場合は ✅、それ以外は ❌ とメッセージを表示 |
| チャンネル一致チェック結果 | 再生リストのchannelIdとチャンネルのIDが一致する場合は ✅、不一致の場合は ❌ とメッセージを表示。公開状態チェックがエラーの場合は省略可 |

> **チェック順序**: 公開状態チェックを先に行い、NGの場合はチャンネル一致チェックの表示を省略してよい。両チェックがNGの場合は公開状態のエラーのみ表示する。

#### 4.1.2 取得中の表示

YouTube APIへのリクエスト中は、確認エリアにローディングインジケーターを表示する。

#### 4.1.3 取得後のチャンネル状態表示

YouTube APIからチャンネル情報を取得した後、そのチャンネルがプレミテに登録済みかどうかを確認し、確認エリア内に状態を表示する。なお、本表示は制約チェック（4.1.1節）が両方クリアされた場合にのみ表示する。

| 状態 | 表示内容 |
|------|---------|
| 登録済みチャンネル | 「✅ プレミテ登録済みチャンネルです。再生リストと紐づけます。」 |
| 未登録チャンネル | 「ℹ️ 未登録のチャンネルです。再生リスト登録と同時に新規チャンネルとして登録します。」 |

#### 4.1.4 未登録チャンネルの説明文自動生成（管理者のみ）

チャンネルが未登録の場合、チャンネル状態表示の直後にAIによるチャンネル説明文의 自動生成を開始する。生成テキストは確認エリア内にリアルタイムでストリーミング表示する。

**生成タイミング**

YouTube APIからのチャンネル情報取得が完了し、かつそのチャンネルがプレミテ未登録と判定された直後に自動生成を開始する。登録済みチャンネルの場合は生成しない。

**AIへのインプット**

| 項目 | 内容 |
|------|------|
| チャンネル名 | YouTube APIから取得したチャンネル名 |
| チャンネルの説明文 | YouTube APIから取得したチャンネル説明文（YouTubeに登録されているもの） |

> **インプット方針**: 取得できた情報をすべてAIに渡し、AI側でゲームコメンタリーチャンネルとして適切な紹介文に整形させる。

**生成テキストの仕様**

| 項目 | 仕様 |
|------|------|
| 目標文字数 | 200文字程度 |
| 言語 | 日本語 |
| 内容方針 | チャンネルの特徴・実況スタイル・扱うゲームジャンル等をもとにした紹介文。YouTubeの説明文から読み取れる範囲で記述し、断定的な誤情報を避ける |

**確認エリアへの表示レイアウト（未登録チャンネル時）**

```
┌───────────────────────────────────────────────────────────┐
│ ┌──────────────┐  再生リストタイトル                       │
│ │              │                                          │
│ │ 再生リスト   │  ⚬ チャンネルアイコン  チャンネル名       │
│ │ サムネイル   │                                          │
│ │ （16:9）     │  動画数: 42本                            │
│ │              │                                          │
│ └──────────────┘                                          │
│                                                           │
│ ✅ 公開されている再生リストです                            │
│ ✅ チャンネルが作成した再生リストです                      │
│                                                           │
│ ℹ️ 未登録のチャンネルです。再生リスト登録と同時に新規      │
│    チャンネルとして登録します。                            │
│                                                           │
│ チャンネルの説明文                                         │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ （ストリーミングで生成テキストが表示される）             │ │
│ └───────────────────────────────────────────────────────┘ │
│ [AIによる生成]  AI生成バッジ表示: [ ON / OFF ]             │
└───────────────────────────────────────────────────────────┘
```

**生成後の操作**

管理者は生成されたテキストをそのまま登録するか、テキストエリアを直接編集して修正・上書きできる。手動で編集した場合もAI生成フラグの状態（ON/OFF）は変わらないため、管理者が必要に応じて手動でトグルを切り替える。

**AI生成バッジ表示トグルの仕様**

| 項目 | 仕様 |
|------|------|
| 表示条件 | 管理者ユーザーの確認エリアにのみ表示。一般ユーザーには表示しない |
| デフォルト状態 | AI生成直後はON（バッジ表示） |
| トグルON | チャンネル詳細ページに「AIによる生成」バッジを表示する |
| トグルOFF | バッジを非表示にする（説明文自体は引き続き表示される） |

#### 4.1.5 再生リストの制約

以下の制約を満たさない再生リストは登録・提案できない。

| 制約項目 | 内容 | 判定タイミング | 備考 |
|---|---|---|---|
| 公開状態 | YouTube上の設定が「公開（public）」であること | 情報取得完了時 (blur) | プレミテ上で誰でも視聴可能であることを担保するため |
| チャンネル一致 | 再生リストのchannelIdと、チャンネル情報を取得した際のチャンネルIDが一致すること | 情報取得完了時 (blur) | 一般の視聴者が作成したまとめリスト等を排除するため |

> [!IMPORTANT]
> これらの制約は、管理者が登録する場合であっても、一般ユーザーが提案する場合であっても等しく適用される。

### 4.2 ゲームタイトル選択

| 項目 | 仕様 |
|------|------|
| 入力形式 | ボタンクリックでモーダルを開く |
| ボタン文言（未選択時） | 「ゲームタイトルを選択する」 |
| ボタン文言（選択済み時） | 選択したゲームタイトル名を表示（例：「ゼルダの伝説 ブレス オブ ザ ワイルド」） |
| 選択解除 | 選択済み状態のボタン横に「×」を表示。クリックで選択を解除 |

| 項目 | 仕様 |

| フッター | 「お探しのゲームタイトルが見つかりませんか？」＋「新しいゲームタイトルとして入力する」を固定表示（§4.2.2、v3.15）。**管理者の場合はこの文言・遷移先が異なる（下記注記参照）** |

> **2026-09-20実装（フェーズ4.5ステップ2）**: 管理者ユーザーがこのフッターリンクをクリックした場合は、4.2.2節の提案モーダルではなく、`GameCreateModal`（管理者専用のゲームタイトル直接登録モーダル）を開く。フッターは案内文「お探しのゲームタイトルが見つかりませんか？」（muted）＋ secondary ボタン（先頭にプラスアイコン、ラベル「新しいゲームタイトルを登録する」）の構成（2026-09-22更新。当初は1行のテキストリンクだったが、アクションと分かりにくいためボタン化。モバイルは縦積み・ボタン全幅、`sm`以上は左右配置）。審査を経ずその場で`games`コレクションへ直接書き込む点が4.2.2との違い。入力項目はゲームタイトル名（必須）、ジャンル（単一選択・任意）、テーマ（複数選択・任意）、プラットフォーム（複数選択・任意、固定候補。当初は Nintendo Switch / Nintendo Switch 2 / PS5 / PS4 / Steam の5機種→2026-09-22更新で18機種に拡充、下記の同日注記参照）、パッケージ画像URL・楽天ブックス商品ページURL・説明文（いずれも手入力・任意。楽天ブックスAPI連携は未実装のため）。同名タイトルは登録不可（完全一致判定）。詳細は`管理 マスタ管理仕様書`§7.1を参照。

> **2026-09-21更新（フェーズ4.5ステップ8・フェーズ5）**: `GameCreateModal`のパッケージ画像欄は、楽天ブックスゲーム検索APIでのタイトル検索→候補選択がデフォルト（ステップ8）。「URLを直接入力する」で切り替える手入力モード（→このモード切替は2026-09-22更新で廃止し、常時表示に変更。下記の同日注記参照）では、楽天ブックス商品ページURL（`https://books.rakuten.co.jp/rb/<商品番号>/`）を貼って「取得」するとパッケージ画像URL・商品名が自動でセットされる（`/api/admin/games/rakuten-item`。商品ページからJANコードを読み取りAPIで検索する）。パッケージ画像URLの直接入力は楽天に無いタイトル向けに残す。保存する`rakutenUrl`は計測パラメータを除いた正規形。検索モードの候補選択・手入力モードの取得のいずれでも、楽天の商品情報からゲームタイトル名（商品名から特典表記を除いた簡易正規化。未入力時のみ）・ジャンル（未選択時のみ）・テーマ・プラットフォームも分かる範囲で自動セットする（ジャンル/テーマは楽天ブックスのカテゴリ名とマスタ名の一致で照合。詳細は`管理 マスタ管理仕様書`§7.1の注記参照）。

> **2026-09-22更新（フォーム再構成）**: `GameCreateModal`は入力欄の並びをフォーム先頭が楽天ブックスのタイトル名検索欄（テキスト入力＋「検索」ボタン、候補を選ぶと上記の自動セットが行われる。フォーカス初期位置）、その次に楽天ブックス商品ページURL欄（URLが分かっている場合の代替経路。フォーカス初期位置ではない）という構成に改めた（検索モード／URL手入力モードの切り替えは廃止し、両方を常時表示）。この検索欄とURL欄は1つの枠（カード）にまとめ、枠の先頭に「検索して候補を選ぶか、商品ページURLを貼って「取得」すると…自動セットします」という共通の説明文を1つだけ表示する（2026-09-22追記。従来はURL欄の`hint`にのみこの説明文を出しており、検索欄にもかかる内容であることが伝わりにくかったため、枠でグルーピングして説明文を共有する形に修正。URL欄の`hint`はURL形式が不正なときの警告のみに使う）。取得結果のプレビュー（サムネイル＋商品名、「変更する」で紐付け解除）はどちらの欄で取得しても共通表示する。検索キーワード欄はゲームタイトル名欄と連動しない独立した自由入力で、新規登録・編集のいずれでもモーダルを開いた時点では常に空欄（旧版はタイトル入力に自動追従していたが、検索が主導線になったため廃止）。パッケージ画像URLの直接入力欄（楽天に無いタイトル向け）はテーマ・プラットフォーム欄の下に独立した欄として残す。テーマ・プラットフォームは複数選択プルダウン（共通UI `MultiSelectMenu`）＋選択済みチップの表示にし、プラットフォームの固定候補は楽天ブックスの機種一覧＋Steamの18機種（Nintendo Switch / Nintendo Switch 2 / Wii U / Wii / ニンテンドー3DS / ニンテンドーDS / PS5 / PS4 / PS3 / PS2 / PS Vita / PSP / Xbox Series X / Xbox One / Xbox 360 / Steam / おもちゃ / その他）に拡充した。詳細は`管理 マスタ管理仕様書`§7.1の2026-09-22注記を参照。

#### 4.2.2 新しいゲームタイトルとして入力する（一般ユーザー）

> **v3.15 改訂（2026-10-25 ユーザー決定）**: 旧版の「ゲームタイトル追加提案モーダル」（ゲームタイトルだけを別ウィンドウで提案し、登録後に再生リストを
> 提案し直す）は廃止した。ゲームタイトルも再生リストも新規、というケースが最も多いのに、別ウィンドウでは再生リストの「提案する」が押せないままで
> 導線が分かりにくかったため。ゲームタイトルが候補に無い場合は、同じフォーム内で新しいゲームタイトル名を入力し、再生リストと**1件の提案として同時に送る**。

ゲームタイトル選択モーダルのフッターに「お探しのゲームタイトルが見つかりませんか？」＋ボタン「新しいゲームタイトルとして入力する」を表示する。
クリックするとモーダルを閉じ、フォームのゲームタイトル欄が「新しいゲームタイトル」の入力に切り替わる。

```
│ ゲームタイトル                                         │
│ 新しいゲームタイトルとして提案します  [一覧から選び直す] │
│ ┌───────────────────────────────────────────────────┐ │
│ │ ゲームタイトル名 *                                │ │
│ └───────────────────────────────────────────────────┘ │
│ ┌───────────────────────────────────────────────────┐ │
│ │ 備考（発売機種・シリーズ情報など）                 │ │
│ └───────────────────────────────────────────────────┘ │
│                                                       │
│ [ 提案する ]                                           │
```

| 項目 | 必須 | 種別 | 備考 |
|------|:---:|------|------|
| ゲームタイトル名 | ✅ | テキスト入力 | 最大100文字。選択モーダルの検索欄に入力していた文字を初期値にする |
| 備考 | — | テキストエリア | 最大500文字。発売機種・シリーズ情報など補足があれば記入 |

**バリデーション**

| チェック内容 | エラーメッセージ |
|------------|--------------|
| ゲームタイトル名が未入力 | 「ゲームタイトル名を入力してください」 |
| ゲームタイトル名が文字数超過 | 「100文字以内で入力してください」 |
| 備考が文字数超過 | 「500文字以内で入力してください」 |
| 同名（完全一致）のゲームタイトルがすでに登録されている | 「このゲームタイトルはすでに登録されています。一覧から選んでください」 |

- 「一覧から選び直す」でゲームタイトル選択モーダルを開く。一覧から選んだ時点で入力を破棄して選択に切り替わり、選ばずに閉じた場合は入力が残る。
  モーダルで再び「新しいゲームタイトルとして入力する」を押した場合は検索欄の文字でタイトル名を置き換える（検索欄が空なら入力中のまま）。
- 同じ新しいゲームタイトル名の審査中の提案が別にあっても重複扱いにはしない（再生リストが違えば別の提案。同名のゲームタイトルの登録は管理画面で1回にまとまる。管理 審査ワークフロー仕様書 §14.3）。
- 送信ボタン（§4.3）は、確認エリアの制約チェックがクリア済み、かつ「ゲームタイトルを選択済み」または「新しいゲームタイトル名を入力済み」の場合に活性。
- 送信後は §6.2 の完了画面を出す（ゲームタイトル欄には入力した新しいゲームタイトル名を表示する）。

> **対象ユーザー**: 本機能は一般ユーザーのみ対象。管理者ユーザーはこのフッターから管理者専用の直接登録モーダル（`GameCreateModal`）を開く（下記 4.2.1 の注記）。

> **実装注記（2026-10-25、フェーズ7ステップ7-4）**: 提案は再生リスト登録提案（`workflows` の `type: "playlist_register"`）1件として保存し、
> `proposalData.gameId` を null、`proposalData.newGameTitle`・`newGameNote` に入力値を入れる（Firestore データモデル設計書 §3.15）。
> 管理画面では「ゲームタイトルを登録して承認」でゲームタイトルの登録（タイトル名入り）と再生リストの登録を続けて行う（管理 審査ワークフロー仕様書 §14.3）。
> 提案者には結果を通知しない（同仕様書 §3）。旧版のゲームタイトル追加提案（`type: "game_title_register"`）は新規には作らないが、作成済みの
> 記録は管理画面で引き続き表示・審査できる。

### 4.3 送信ボタン

ユーザー種別によってボタン文言が異なる。

| ユーザー種別 | ボタン文言 |
|------------|----------|
| 管理者ユーザー | 「登録する」 |

## 5. 登録・提案処理

### 5.1 処理フローの分岐

送信ボタンクリック後の処理は、ユーザー種別によって分岐する。

```
送信ボタンをクリック
    ↓
バリデーション（5.2参照）
    ↓
    ├─ 管理者の場合 ──────────────────────────────┐
    │   チャンネルの処理（5.3参照）                       │
    │       ↓                                           │
    │   再生リストをFirestoreに登録（本番コレクション）    │
    │       ↓                                           │
    │   動画リストをFirestoreに登録                       │
    │       ↓                                           │
    │   管理者向け完了画面へ遷移（6.1参照）               │
    │                                                   │
    └─ 一般ユーザーの場合 ──────────────────────────────┐
        提案データをFirestoreに保存（提案コレクション）   │
            ↓                                          │
        一般ユーザー向け完了画面へ遷移（6.2参照）        │
```

### 5.2 バリデーション

管理者・一般ユーザー共通のバリデーション。

| チェック内容 | エラー時の動作 |
|------------|-------------|
| 再生リストURLがYouTube再生リストURLの形式であること | インラインエラー＋トースト通知を表示 |
| YouTube APIからの情報取得が成功していること | インラインエラー＋トースト通知を表示 |
| 再生リストの公開状態が「公開（public）」であること | インラインエラー＋トースト通知を表示 |
| 再生リストのchannelIdが、YouTube APIで取得したチャンネルのIDと一致すること | インラインエラー＋トースト通知を表示 |
| ゲームタイトルが選択されていること | インラインエラーを表示 |
| チャンネル詳細ページ流入時：入力された再生リストURLのチャンネルが、流入元チャンネルと一致すること | インラインエラー＋トースト通知を表示 |

> **チェック順序**: URL形式 → API取得 → 公開状態 → チャンネル一致 → ゲームタイトル選択 → （チャンネル詳細流入時のみ）流入元チャンネル一致 の順に実行する。

### 5.3 チャンネルの処理（管理者のみ）

| チャンネルの状態 | 処理内容 |
|---------------|--------|
| プレミテ登録済みチャンネル | 既存チャンネルドキュメントと再生リストを紐づける |
| プレミテ未登録チャンネル | YouTube APIから取得したチャンネル情報（チャンネル名・アイコン等）およびAI生成済みの説明文・AI生成バッジフラグを含めて新規チャンネルをFirestoreに登録し、再生リストと紐づける |

### 5.4 提案データの保存仕様（一般ユーザーのみ）

一般ユーザーが「提案する」をクリックした場合、再生リストの情報は本番の再生リストコレクションには保存されず、Firestoreの専用提案コレクションに保存される。

| 項目 | 内容 |
|------|------|
| 保存先 | Firestoreの専用提案コレクション（コレクション名は実装者に委ねる） |
| 保存内容 | 再生リストURL・YouTube APIから取得した再生リスト情報・選択したゲームタイトル・提案ユーザーID・提案日時・ステータス（「審査中」） |
| 公開状態 | 管理者が承認するまでサイト上には公開されない |
| 承認フロー | 管理者向けの審査UI・承認処理は別途定義する |

> **実装注記（2026-10-25、フェーズ7ステップ7-4）**: 専用提案コレクションは `workflows`（`type: "playlist_register"`、ステータス `reviewing_lv1`）とした
> （Firestore データモデル設計書 §3.15）。送信は `POST /api/playlists/propose`（Admin SDK）で、制約チェック（§4.1.5・§5.2）と「提案済み、または登録済み」（§7.2）を
> サーバー側でも同じ順序で行う。クライアントから `workflows` に提案を直接作ることは rules で禁止している（通報のみ可）。
> 保存内容は再生リストURL・YouTube API の再生リスト情報（ID・タイトル・サムネイル・動画数・チャンネルID/名/アイコン）・ゲームタイトル（ID・名前、または新しいゲームタイトル名・備考。§4.2.2）。
> 承認・却下は管理画面の審査ワークフロー（単一ステップ、管理 審査ワークフロー仕様書 §14.3）で行い、承認時に管理者の登録と同じ処理（`lib/playlist-registration.ts`）で
> 本登録する。承認で登録した再生リストには `playlists.proposedBy`（提案者）を記録する。
> 一般ユーザーには未登録チャンネルの説明文欄を出さない（承認時に管理者が書く）。URL入力時のプレビュー（`/api/playlists/preview`）はログインユーザー全員が使える。
> 審査中の提案がある再生リストは、一般ユーザーには「提案済み、または登録済み」として送信不可、管理者には案内（ℹ️）のみ出して直接登録はできる。
> 導線（§1.4）はゲームタイトル詳細・チャンネル詳細に加え、再生リストを探すページの見出し右（PCのみ）とフッター（ログイン時）に置いた。
> モバイルは「さがす」の4ページ（再生リスト・ゲームタイトル・チャンネル名・まとめ）の右下に「＋」の浮きボタン（ボトムタブバーの上）を出す（2026-10-25 ユーザー決定。stg のテストモード中はウィジェットと重ならないよう左下）。
> 管理者向けの流入として `?url=`（管理画面でゲームタイトル登録提案を承認した後の「この再生リストも登録する」。`?gameId=` と併用）を追加した。
> 再生リストURLを入れた状態で開き、blur を待たずにプレビューする。

## 9. 提案フローの作り込み（一般ユーザー、v4.0）

2026-10-25 の深掘りで決めた内容（計画: /mnt/project-files/plans/再生リスト提案-深掘り-提案する側.md）。1〜7章の記述と食い違う場合は本章を優先する。

### 9.1 審査があることを見せる

- 一般ユーザーにはページ見出しを「再生リストを提案する」とし、直下に3段のステップ表示「① 提案する → ② 運営が確認 → ③ さがすに公開」を出す（①を強調）。
  ステップ表示の下に「運営が確認してから公開します」と一文を添える。管理者は従来どおり「再生リストを追加する」でステップ表示なし。
- 送信ボタンの上に「送信後、運営の確認が済むまで公開されません」と出す。確認ダイアログは挟まない。
- 完了画面（§6.2）は見出しを「提案を送りました（確認待ち）」とし、同じステップ表示で②に「いまここ」を付ける。説明文は「今は運営の確認待ちです。確認が済むとさがすに表示されます」。
  ボタンに「提案履歴を見る」（§9.4）を加える。

### 9.2 ゲームタイトルの探しやすさ

- ゲームタイトル選択モーダルの検索は、タイトル名に加えて別名（`games.aliases`、管理者がマスタで登録。マスタ管理仕様書 §7.1）も対象にする。
  照合は大文字小文字・全角半角・ひらがなカタカナ・空白と記号の違いを無視した部分一致。
- 一般ユーザーには、登録済みの候補の下に「楽天ブックスの候補」を出す（検索欄に2文字以上入力して少し待つと検索。楽天ブックスゲーム検索API）。
  楽天の候補を選ぶと、フォームは新しいゲームタイトルの入力（§4.2.2）に切り替わり、タイトル名には特典・版・機種の表記を削った名前が入る（編集可）。
  選んだ商品はフォームに「楽天ブックスの商品」として表示し、提案に商品情報（商品ページURL・商品名・画像URL・機種・楽天ジャンルID）を残す。外すこともできる。
- 楽天に出てこないゲームは従来どおり「新しいゲームタイトルとして入力する」で自由入力できる。
- 新しいゲームタイトル名を入力しているとき、似た名前の登録済みゲームタイトルがあれば入力欄の下に「登録済みのこちらではありませんか？」として最大3件出す。押すとそのゲームタイトルを選んだ状態に切り替わる。
- 新しいゲームタイトルの入力欄に「機種（任意・複数）」を加える。候補は管理者の登録と同じ18機種（マスタ管理仕様書 §7.1）。楽天の候補を選んだ場合はその機種が入った状態になる。

### 9.3 ログイン後に戻る

- 未ログインで提案画面を開いた場合は `/login?next=<提案画面のパスとクエリ>` へ送り、ログイン（アカウント作成を含む）後にその画面へ戻す（ログイン仕様書 §5.4）。

### 9.4 提案後（提案履歴と通知）

- 自分の提案の一覧「提案履歴」（`/playlists/proposals`）を設ける。ユーザーメニューに「提案履歴」を置き、完了画面と審査結果の通知からもリンクする。
  各提案に、再生リスト（サムネ・タイトル・チャンネル）、ゲームタイトル、提案日時、ステップ表示（確認待ち＝②いまここ／公開済み＝③／見送り＝②で止めて「見送り」）を出す。
  公開済みは再生リストへのリンク、見送りは定型の理由（審査ワークフロー仕様書 §14.4）を表示する。運営メモと内部向けの自由記述は出さない（API 経由で返す）。
- 承認・見送りのときにサイト内通知（種別「審査結果」）を届ける（ユーザー通知機能仕様書 §2.1）。
