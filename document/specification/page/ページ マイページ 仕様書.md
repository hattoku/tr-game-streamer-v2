## 1. 概要

自分専用のページ（視聴履歴・通知・提案履歴・お問い合わせ履歴・設定など）への入口を、押せる項目の一覧で並べるページ。スマホのボトムタブ「マイページ」の遷移先。

- それまでボトムタブ「マイページ」は暫定で視聴履歴（`/history`）に飛んでいた。視聴履歴が出るのは不自然で、プロフィール・提案履歴・お問い合わせ履歴・設定へはスマホだと右上のアイコンのメニューからしか行けなかった（2026-11-14 ユーザー指摘）。
- プロフィール（`/profile/[userId]`）は他の人にも見える公開ページなので、自分専用の入口とは分ける（2026-11-14 ユーザー決定）。
- マイリストはボトムタブ、サポート・規約は左上のハンバーガーメニューにあるため、ここには重ねて置かない（2026-11-14 ユーザー決定）。
- PC はヘッダーのユーザードロップダウン（UI仕様書 §2.6）が同じ役割を担うため、PC のナビからは `/mypage` へのリンクを置かない。URL を直接開けば PC でも表示できる（1カラムの同じ表示）。

## 2. ページURL・アクセス条件

| 項目 | 内容 |
|------|------|
| URL | `/mypage` |
| アクセス条件 | ログイン済みユーザーのみ。未ログインで開いたときはログインページ（`/login`）へ移す |
| 流入元 | スマホのボトムタブ「マイページ」（ログイン中）。未ログインのときのタブはアカウント作成（§4） |

## 3. ページ構成

上から順に縦に積む。見出しは「マイページ」。

| # | 区分 | 内容 | 遷移先 |
|---|------|------|--------|
| ① | 自分 | アイコン（48px、未設定はイニシャル）・表示名・メールアドレス・「プロフィールを見る」。カード全体が押せる | `/profile/[自分のuid]`（表示名・自己紹介の編集もここ） |
| ② | 見る | 視聴履歴 | `/history` |
|   |      | 通知。再生リスト新着の未読があれば右側に赤丸と「未読 N」（ベルと同じ数） | `/notifications` |
| ③ | 自分の投稿・やりとり | 提案履歴（チャンネル申請も含む）。未読の審査結果があれば右側に赤丸と「未読 N」 | `/playlists/proposals` |
|   |      | お問い合わせ履歴。未読の返信があれば右側に赤丸と「未読 N」 | `/contact/history` |
| ④ | アカウント | 設定 | `/settings` |
| ⑤ | 運営（管理者のみ） | 管理画面。審査中のワークフローがあれば右側に「未処理 N」（UI仕様書 §2.10 と同じ件数） | `/admin` |
| ⑥ | —（見出しなしの単独カード） | ログアウト。確認なしですぐログアウトし、TOP へ移す（設定ページ・ユーザードロップダウンと同じ） | `/` |

- 区分ごとに小さな見出し（muted）とカードを置き、カードの中に行を並べる。行はアイコン（20px）＋項目名＋右矢印。行の高さは 56px 以上（指で押しやすい高さ）。行の間はカード内セパレーター。
- 管理者（オーナー・運営者）以外には ⑤ を出さない。
- 未読件数（お問い合わせの返信・審査結果・通知）は、項目名の右・矢印の手前に置く（v1.1。ユーザードロップダウンと同じ表示・同じ数。ページ ユーザー通知機能仕様書 §4.3）。

## 4. ボトムタブとの関係

- ボトムタブ「マイページ」の遷移先は `/mypage`。未ログインのときは従来どおりアカウント作成（`/login?mode=signup`）。
- ログイン状態を読み込んでいる間は、ログイン済みの遷移先（`/mypage`）にしておく。読み込み前に押すと、ログイン中なのにアカウント作成へ飛んでしまうため（stg の E2E で発覚）。未ログインの人が読み込み中に押した場合は `/mypage` からログインページへ移る。マイリストタブも同じ。
- 「マイページ」タブをアクティブにするページ: `/mypage`・`/history`・`/notifications`・`/playlists/proposals`・`/contact/history`・`/settings`・`/profile` 配下。
- `/playlists/proposals` は「さがす」タブの `/playlists` にも前方一致するため、アクティブ判定は**一番長く一致したプレフィクス**のタブにする（提案履歴は「マイページ」、再生リスト一覧・詳細は「さがす」）。
