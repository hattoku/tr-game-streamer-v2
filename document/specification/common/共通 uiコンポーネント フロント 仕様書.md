## 1. 概要

本仕様書は、プレミテのフロント（一般ユーザー向け画面）において複数のページをまたいで共通的に使用するUIコンポーネントの仕様を定義する。

対象コンポーネントは以下のとおり。

| コンポーネント | 概要 |
|-------------|------|
| グローバルヘッダー | 全ページ共通のヘッダー。ロゴ・ナビゲーション・ユーザーメニューを含む |
| グローバルフッター | 全ページ共通のフッター。サービス案内リンク・法的リンクを含む |
| インフォメーションバー | ヘッダー直下に表示するお知らせバナー帯 |
| ログイン要求モーダル | 未ログインユーザーがログイン必須操作を行った際に表示するモーダル |
| トースト通知 | 操作結果をユーザーに通知する一時的なポップアップ |
| テストモードウィジェット | 開発者がログイン状態を即座に切り替えるための画面右下固定ウィジェット |
| 空状態 (Empty States) | 検索結果なしやデータ未登録時に表示するプレースホルダー表示 |
| ローディング | データ取得中のSkeleton Screenおよびアクション実行中のSpinner |

### 適用範囲

本仕様は `/` 配下のフロント全ページに適用する。ただし以下のページはヘッダー・フッターの表示形式が異なる（各仕様書を参照）。

| ページ | 備考 |
|--------|------|
| `/login` / `/signup` / `/password-reset` | 認証フロー用の簡易レイアウト（ロゴのみ）を使用 |
| 初期設定フロー | ロゴ＋ステップインジケーターのみのレイアウトを使用 |
| エラーページ | 404/403/500/503 ごとに表示形式が異なる（詳細は「共通 エラーページ 仕様書」を参照） |

## 2. グローバルヘッダー

### 2.1 概要

フロント全ページの最上部に固定表示されるコンポーネント。ロゴ・グローバルナビゲーション・ユーザーメニューで構成される。

### 2.2 全体レイアウト

#### PC版

```
┌────────────────────────────────────────────────────────────────┐
│  [プレミテ ロゴ]   再生リストを探す  ゲームから探す  チャンネルから探す  まとめ    [ログインボタン]  │
└────────────────────────────────────────────────────────────────┘
```

**ログイン済み時（右端部分）**

```
[マイリスト]  [視聴履歴]  [ ⚬ ユーザーアイコン ▼ ]
```

#### モバイル版

モバイルではアプリ風の操作性を優先し、**画面下部に固定のボトムタブバー**で主要導線を切り替える。
上段ヘッダーはロゴとユーザーエリアのみで、ナビゲーションは置かない。「さがす」セクションを
表示しているときだけ、ヘッダー直下に探す系4ページを切り替えるタブ列を出す。

```
┌────────────────────────────────────────────────┐
│  ☰  [プレミテ ロゴ]                 [ログイン]      │  ← 上段（未ログイン時）／ログイン済みは [⚬ ユーザー名 ▾]。☰ はハンバーガーメニュー
├────────────────────────────────────────────────┤
│  再生リストを探す  ゲームタイトルから探す  チャンネル名から探す  まとめを探す │  ← 「さがす」セクション表示中のみ（横スクロール可）
├────────────────────────────────────────────────┤
│                                                │
│              ページコンテンツ                     │
│                                                │
├────────────────────────────────────────────────┤
│   🏠ホーム    ♡マイリスト    🔍さがす    👤マイページ   │  ← ボトムタブバー（固定）
└────────────────────────────────────────────────┘
```

### 2.3 ロゴ

| 項目 | 仕様 |
|------|------|
| 表示内容 | サービスロゴ（テキストまたは画像） |
| クリック時の動作 | TOPページ（`/`）へ遷移 |
| 表示位置 | ヘッダー左端 |

### 2.4 グローバルナビゲーション（PC）

PC版ではヘッダー中央〜左寄りに水平並びで表示する。

| ナビ項目 | 遷移先 | 表示条件 |
|---------|--------|---------|
| 再生リストを探す | `/playlists` | 常時表示 |
| ゲームから探す | `/games` | 常時表示 |
| チャンネルから探す | `/channels` | 常時表示 |
| まとめ | `/collections` | 常時表示 |

- 現在表示中のページに対応するナビ項目をアクティブ状態（下線または色変化）で表示する。
- アクティブ判定はURLのプレフィクスで行う（例：`/games/[id]` 表示中は「ゲームから探す」がアクティブ）。

### 2.5 ユーザーエリア（PC・未ログイン時）

| 要素 | 仕様 |
|------|------|
| ログインボタン | 「ログイン」テキストボタン。クリックで `/login` へ遷移 |
| アカウント作成ボタン | 「アカウント作成」をブランドカラーのボタンで表示。クリックで `/signup` へ遷移 |

```
【PC・未ログイン時のヘッダー右端】

[ログイン]  [アカウント作成]
```

### 2.6 ユーザーエリア（PC・ログイン済み時）

| 要素 | 仕様 |
|------|------|
| マイリストリンク | 「マイリスト」テキストリンク。クリックで `/mylist` へ遷移 |
| 視聴履歴リンク | 「視聴履歴」テキストリンク。クリックで `/history` へ遷移 |
| ユーザーアイコン | プロフィール画像を円形で表示（未設定時はデフォルトアイコン）＋ユーザー名＋▾。クリックでユーザードロップダウンを展開 |

```
【PC・ログイン済み時のヘッダー右端】

マイリスト   視聴履歴   [ ⚬ アイコン ▼ ]
```

#### ユーザードロップダウン

ユーザーアイコンをクリックすると以下のドロップダウンを表示する。

```
┌──────────────────────┐
│  ユーザー名            │
│  example@email.com   │
├──────────────────────┤
│  プロフィール          │
│  設定                 │
├──────────────────────┤
│  ログアウト            │
└──────────────────────┘
```

| メニュー項目 | 動作 |
|------------|------|
| プロフィール | `/profile/[userId]`（自分のプロフィールページ）へ遷移 |
| 設定 | `/settings` へ遷移 |
| ログアウト | ログアウト処理を実行後、TOPページへ遷移 |

- ドロップダウン外をクリックするとドロップダウンを閉じる。
- 「ユーザー名」「メールアドレス」はクリック不可の表示専用。

### 2.7 モバイル版ナビゲーション（ボトムタブバー＋さがすタブ）

#### ボトムタブバー

画面下部に固定表示し、アイコン＋ラベルの4タブを等幅で並べる。

| タブ | 遷移先 | アクティブ判定（URLプレフィクス） | 備考 |
|------|--------|------------------------------|------|
| ホーム | `/` | `/` のみ | TOPページ |
| マイリスト | `/mylist` | `/mylist` 配下 | 視聴中・見たいの管理と「続きから再生」の導線。**未ログイン時はログインページへ**（`/login`） |
| さがす | `/playlists` | `/playlists` `/games` `/channels` `/collections` 配下 | 再生リスト詳細（`/playlists/[id]`）もこのセクションに含む |
| マイページ | `/history`（暫定） | `/history` `/profile` `/settings` 配下 | **未ログイン時はアカウント作成フローへ遷移する**（`/signup`。専用ページ実装までは `/login?mode=signup`）。遷移先はプロフィール／設定ページの実装後に見直す（当面は視聴履歴の準備中ページ） |

| 項目 | 仕様 |
|------|------|
| 高さ | 56px ＋ 端末のセーフエリア（`env(safe-area-inset-bottom)`） |
| 背景・境界 | デザイントークン仕様書 §14「ボトムタブバー」に準ずる（面のグラデーション・上ボーダー・影） |
| アクティブ表示 | アイコン・ラベルを `color-text-primary`。非アクティブは `color-text-muted` |
| ラベル | `font-size: 10px`（アイコン 22px の下） |
| 表示条件 | フロント通常ページで表示。認証ページ・初期設定フロー・シアターモード中は非表示 |
| コンテンツとの関係 | ページ本文とフッターがタブバーに隠れないよう、下端にタブバー分の余白を確保する |

#### さがすタブ（ヘッダー直下）

「さがす」セクションの一覧ページ（`/playlists` `/games` `/channels` `/collections`）を表示中のみ、
ヘッダー直下にタブ列を表示する。再生リスト詳細などの下層ページでは表示しない。

| タブ（上段: 大きめ／下段: 小さめ） | 遷移先 |
|------|--------|
| 再生リスト／を探す | `/playlists` |
| ゲームタイトル／から探す | `/games` |
| チャンネル名／から探す | `/channels` |
| まとめ／を探す | `/collections` |

- アクティブ表示は PC 版ナビと同じ（下線＋文字色）。
- 4タブを等幅（画面幅の1/4ずつ）で並べ、横スクロールはしない。横幅に収めるためラベルは2行にし、上段に対象（「再生リスト」「ゲームタイトル」「チャンネル名」「まとめ」）を大きめ、下段に「を探す」「から探す」を小さく表示する。
- ホーム・マイリスト・マイページの各セクションでは、ヘッダー直下にメニューを表示しない。

#### ハンバーガーメニュー（モバイル）

上段ヘッダー左端の ☰ を押すと、左からスライドインするドロワーを開く。**主要導線（ボトムタブ）と
アカウント操作（ユーザードロップダウン）は含めず**、フッター相当の情報だけをまとめる。
モバイルではフッターを表示しないため（§3.5）、その代替となる。

```
┌──────────────────────────────┐
│ [プレミテ ロゴ]          [×] │
│                              │
│ サポート                      │
│   初めての方へ                │
│   お問い合わせ                │
│   このサイトについて           │
│ ─────────────────────────    │
│ 規約・ポリシー                 │
│   利用規約                    │
│   プライバシーポリシー         │
│                              │
│ © 2026 発見&納得コミュニケーションズ │
└──────────────────────────────┘
```

| 項目 | 仕様 |
|------|------|
| 開く | ☰ のクリック |
| 閉じる | ドロワー内「×」、オーバーレイクリック、Esc、リンクのクリック（遷移と同時に閉じる） |
| オーバーレイ | 右側に半透明の暗色オーバーレイ |
| スクロール | 展開中はボディのスクロールを無効化 |
| アニメーション | 左端からスライドイン（200ms程度） |
| 見た目 | 共通 デザイントークン仕様書 §13.2 |

#### 上段ヘッダー（モバイル）

| 状態 | 表示 |
|------|------|
| 未ログイン | 右端に「ログイン」ボタン**1つだけ**（セカンダリボタン小型版。ヘッダーの UI は目立たせない方針）。クリックで `/login` へ。「アカウント作成」ボタンはヘッダーには置かず、ボトムタブ「マイページ」とログインページ内の導線が担う。同じ見た目のボタンを2つ並べない |
| ログイン済み | 右端に「通知ベル（未読件数バッジ付き、ユーザー通知機能仕様書 §4.1）」＋「ユーザーアイコン＋ユーザー名＋▾」。クリックで §2.6 のユーザードロップダウン（プロフィール／設定／ログアウト）。ベルは通知一覧 `/notifications` への唯一の導線なので PC・モバイル共に表示する |

> **設計判断（2026-09-12）**: モバイルナビは「ハンバーガー＋ドロワー」→「ヘッダー下の常時表示ナビバー」→
> 「ボトムタブバー＋さがすタブ」と見直した。主要導線を常に見せつつ片手で届く位置に置くため、
> アプリ風の構成（参考: メニアック https://meniac.jp/app/ ）を採用した。
> ドロワーの見た目定義（デザイントークン仕様書 §13.2）は将来の絞り込みパネル等のために残す。

### 2.8 ヘッダー共通仕様

| 項目 | 仕様 |
|------|------|
| 高さ（PC） | 60px（共通 デザイントークン仕様書 §14）。全ページで統一する |
| 最大幅（PC） | 1400px（共通 ページレイアウト 仕様書 §3 に準ずる） |
| 高さ（モバイル） | 上段 52px。「さがす」一覧ページではさらにタブ列 52px（2行ラベル）（共通 デザイントークン仕様書 §14）。シアターモード時は上段 30px・タブ列とボトムタブバーは非表示 |
| 背景色 | シネマダーク背景（`color-bg-base`: `#0f0f0f`） | 全ページで統一する |
| 固定表示 | スクロール時もヘッダーを最上部に固定表示する（`position: sticky` または `fixed`） |
| z-index | ページコンテンツより前面に表示する |

### 2.9 ブレークポイント

| ブレークポイント | 表示形式 |
|--------------|---------|
| 768px以上（PC） | グローバルナビゲーションを水平表示、ユーザーエリアを右端に表示 |
| 767px以下（モバイル） | 上段はロゴ＋ユーザーエリアのみ。主要導線は画面下部のボトムタブバー（ホーム／タイムライン／さがす／マイページ）、探す系4ページの切り替えは「さがす」時のヘッダー直下タブ |

## 4. インフォメーションバー（お知らせバナー）

### 4.1 概要

管理者（オーナー・運営者）が設定した「一般ユーザー向けお知らせ」（メンテナンス告知・キャンペーン情報等）を、ヘッダー直下に帯状のバナーとして表示するコンポーネント。詳細仕様は「/document/specification/management/管理 お知らせ管理仕様書.md」第5章に従う。

### 4.2 表示位置

ヘッダーとページコンテンツの間に挿入する。

```
┌──────────────────────────────────────────────────┐
│  ヘッダー                                          │
├──────────────────────────────────────────────────┤
│  ■ メンテナンスのお知らせ  詳細を見る  [1/2] ＜ ＞ [×] │  ← インフォメーションバー
├──────────────────────────────────────────────────┤
│  ページコンテンツ                                   │
```

### 4.3 表示条件

- ステータスが「掲載中」のお知らせが1件以上あり、かつ対象ページが現在のページを含む場合に表示する。
- ログイン・未ログイン問わず全ユーザーに表示する。

### 4.4 表示要素

| 要素 | 内容 |
|------|------|
| タイトルテキスト | お知らせのタイトル（最大1行、超過時は省略記号で切り詰め） |
| 「詳細を見る」リンク | 本文が設定されている場合のみ表示。クリックで詳細モーダルを展開 |
| 件数インジケーター | 複数件の場合に「1/3」のように表示 |
| 切り替えボタン（＜＞） | 複数件の場合に前後に切り替える |
| 閉じるボタン（×） | クリックでバナー帯を非表示にする |

### 4.5 閉じた後の挙動

- LocalStorageに閉じたお知らせのIDを保存し、同一端末・同一ブラウザでは再表示しない。
- 複数件ある場合、「×」で閉じるのは表示中の1件のみ。他の件は引き続き表示される。

### 4.6 詳細モーダル

「詳細を見る」クリック時に表示するモーダル。

| 要素 | 内容 |
|------|------|
| タイトル | お知らせのタイトル |
| 本文 | お知らせの全文 |
| 掲載期間 | 掲載開始日〜掲載終了日 |
| 閉じるボタン | モーダル右上の「×」ボタン |

- モーダル外クリックまたは「×」ボタンで閉じる。

## 6. トースト通知

### 6.1 概要

ユーザー操作の結果（成功・失敗・警告・情報）を短時間表示するポップアップ通知コンポーネント。

### 6.2 表示位置・動作

| 項目 | 仕様 |
|------|------|
| 表示位置 | 画面上部中央・ヘッダー直下（PC・モバイル共通。スタイルは共通 デザイントークン仕様書 §12） |
| 自動消去 | 表示から3秒後に自動で消える |
| 手動消去 | トースト上の「×」ボタンで即時消去 |
| 複数表示 | 複数のトーストが発生した場合は縦方向に積み上げて表示する |
| アニメーション | フェードイン・フェードアウト（duration: 200ms程度） |

### 6.3 種別とスタイル

| 種別 | 用途 | 色イメージ |
|------|------|----------|

## 7. テストモードウィジェット

### 7.1 概要

開発・動作確認時に、フロント画面上でログイン状態とログアウト状態を1ボタンで即座に切り替えるためのウィジェット。画面右下にスクロール追従で固定表示される。

**表示条件**: テストモードが有効な場合のみ表示する。本番環境では表示しない。

有効化はビルド時の環境変数 `NEXT_PUBLIC_TEST_MODE=true` で行う（ローカルは `.env.local`、Cloud Build は `_TEST_MODE=true` の substitution。既定は無効）。この変数が無いビルドではウィジェットも切り替え用 API（`/api/test/sign-in`）も無効になる。

### 7.2 外観・レイアウト

画面右下に常駐する小さなフローティングウィンドウ。

```
┌─────────────────────────────┐
│ 🧪 テストモード               │
│                             │
│  [  ログアウト中に切替  ]     │  ← ログイン中の場合
│                             │
│  現在: ログイン中             │
└─────────────────────────────┘
```

```
┌─────────────────────────────┐
│ 🧪 テストモード               │
│                             │
│  [  ログイン中に切替  ]       │  ← ログアウト中の場合
│                             │
│  現在: ログアウト中           │
└─────────────────────────────┘
```

### 7.3 表示要素

| 要素 | 内容 |
|------|------|
| ラベル | 「🧪 テストモード」。テストモード有効中であることを常に明示する |
| 切り替えボタン | 「一般ユーザーでログイン」「管理者でログイン」の2ボタン（ブランドカラー `color-brand-logo`: `#e03030`。現在ログイン中の種別は無効表示）と、ログイン中のみ「ログアウト」ボタン |
| 現在の状態表示 | 「現在: 一般ユーザーでログイン中」「現在: 管理者でログイン中」「現在: ログアウト中」をテキストで表示 |

### 7.4 動作仕様

| 項目 | 仕様 |
|------|------|
| 表示位置 | 画面右下に固定（`position: fixed; bottom: 右下;`）。スクロールに追従する |
| ウィジェットのサイズ | コンパクト（実装時に決定）。ページコンテンツを過度に隠さないよう配慮する |
| 枠線 | ブランドカラー（`color-brand-logo`: `#e03030`）の枠線でウィジェットであることを視覚的に識別できるようにする |
| z-index | ページコンテンツの最前面に表示する |

#### ログイン状態への切り替え

「ログイン中に切替」ボタンをクリックすると、テストモード用会員の権限でログインした状態に切り替わる。

| 項目 | 仕様 |
|------|------|
| ログイン対象 | テストモード用会員（詳細は/document/specification/management/管理 ユーザー管理仕様書.md参照） |
| 切り替え後の動作 | ヘッダーのユーザーエリアがログイン済み表示に切り替わる。ページのリロードは行わない（状態のみ更新） |
| 現在の状態表示 | 「現在: ログイン中」に更新 |
| ボタンラベル | 「ログアウト中に切替」に更新 |

#### ログアウト状態への切り替え

「ログアウト中に切替」ボタンをクリックすると、ログアウト状態に切り替わる。

| 項目 | 仕様 |
|------|------|
| 切り替え後の動作 | ヘッダーのユーザーエリアが未ログイン表示に切り替わる。ページのリロードは行わない（状態のみ更新） |
| 現在の状態表示 | 「現在: ログアウト中」に更新 |
| ボタンラベル | 「ログイン中に切替」に更新 |

### 7.5 テストモード用会員

テストモードでログインする際に使用するテスト専用のユーザーアカウント。

| 項目 | 内容 |
|------|------|
| 種別 | **一般ユーザー**と**管理者**の2種類を用意する |
| メールアドレス | 一般ユーザー: `test-user@puremite.test`（`TEST_USER_EMAIL` で変更可）／管理者: `test-admin@puremite.test`（`TEST_ADMIN_EMAIL` で変更可） |
| 表示名 | テストユーザー／テスト管理者 |
| role | 一般ユーザー: `user`／管理者: `owner`（再生リスト登録・新着再取得など管理者操作の確認用）。切替のたびにサーバーが種別どおりの role を保証する |
| users ドキュメント | `isTestUser: true`。その他は通常のアカウント作成時と同じ初期値 |
| 作成方法 | 初回の「ログイン中に切替」時に `/api/test/sign-in` が Firebase Auth に自動作成する |
| ログイン方式 | 切替のたびにサーバー（Admin SDK）が使い捨てのランダムパスワードを設定し直し、メール＋パスワードを返す。クライアントはそれでログインする。パスワードは保存しないため、ウィジェット以外からはログインできない |

管理画面からの扱い（一覧での識別・削除等）は「/document/specification/management/管理 ユーザー管理仕様書.md」側で定義する（未作成）。

## 8. 空状態 (Empty States)

### 8.1 概要

検索結果が0件の場合、マイリストが空の場合、あるいはデータが1件も登録されていないコンテンツエリアにおいて、ユーザーに状況を伝え、次のアクションを促すための共通コンポーネント。

### 8.2 基本構造

```
┌───────────────────────────────────────────┐
│                                           │
│               [ イメージ ]                 │
│                                           │
│            [ メインメッセージ ]             │
│                                           │
│            [ サブメッセージ ]               │
│                                           │
│           [ アクションボタン ]              │
│                                           │
└───────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| イメージ | 状態を象徴するイラスト、SVGアイコン、またはプレースホルダー画像。 |
| メインメッセージ | 現在の状況を簡潔に伝えるテキスト（例：「結果が見つかりませんでした」）。 |
| サブメッセージ | 理由や解決策を提示する補足テキスト（任意）。 |
| アクションボタン | 次のステップへ誘導するボタン（例：「検索条件をクリア」「動画を探す」）（任意）。 |

### 8.3 共通パターン

| パターン | メインメッセージ | サブメッセージ | アイコン等の推奨 |
|---------|----------------|---------------|----------------|
| 検索結果なし | お探しの再生リストは<br>見つかりませんでした | キーワードやフィルターを<br>変えてみてください | 虫眼鏡 (`search`) |
| マイリスト空 | マイリストは空です | 気になる再生リストを<br>保存して自分だけのリストを作ろう | ハート (`favorite`) |
| 視聴履歴なし | 視聴履歴はありません | 気になる動画を視聴して<br>記録を残しましょう | 時計 (`history`) |
| 該当データなし | 表示できるデータが<br>ありません | - | ボックス (`inventory_2`) |

### 8.4 レイアウト仕様

| 項目 | 仕様 |
|------|------|
| 配置 | コンテンツエリア内（`main` コンテナ内）で中央揃え（垂直・水平）。 |
| 余白 | 上下 60px 以上のパディングを確保し、ページ全体が寂しく見えないように調整する。 |
| テキスト位置 | 中央揃え（`text-align: center`）。 |
| アクションボタン | ブランドカラーのボタンを使用し、UIのプライマリな導線として機能させる。 |

## 9. ローディング (Loading)

### 9.1 概要
ユーザーにシステムの動作状況を伝え、ストレスを軽減するために「Skeleton Screen」と「Spinner」を使い分ける。

### 9.2 Skeleton Screen（スケルトン領域）
データ読み込み中に、実コンテンツのレイアウトを模したグレースケールな矩形を表示する手法。

#### 用途
- ページ全体の初回読み込み時
- リスト・カード等、構造が明確な大型コンポーネントの読み込み時
- ページ遷移時（Next.js `loading.tsx`）

#### 設計方針
- 実コンテンツと同じサイズ、角丸、余白を維持する。
- 静止させず、左から右へ流れるようなハイライト（シマーアニメーション）を付与する。
- テキスト行のスケルトンは、実コンテンツよりもやや短く（例：タイトルなら幅 60〜80%）設定し、複数行の場合は末尾を揃えないことで「テキストらしさ」を演出する。

### 9.3 Spinner（スピナー）
円形の回転アニメーション。

#### 用途
- ボタン内のアクション実行中（「保存中」など）
- 無限スクロールの次ページ読み込み時
- 設定変更後の微細なデータ更新時

#### 設計方針
- `color-spinner`（`#aaaaaa`）を使用する。
- 派手な色は使わず、UIに馴染む適度な線幅とする。

### 9.4 Next.js での使用イメージ

App Router の機能を活用し、一貫したローディング体験を提供する。

#### 1. 地点別 loading.tsx の役割
- **グローバル (`/app/loading.tsx`)**: 共通レイアウトに基づき、全ページ共通のスケルトンを表示。ヘッダー（ロゴ・ナビ）は表示されたまま、メインコンテンツ領域に汎用的なカードプレースホルダー等を表示する。
- **ルート単位 (`/app/[route]/loading.tsx`)**: ページ特有の構造に最適化したスケルトンを表示。
    - 例：`/playlists` なら再生リストカードのグリッドスケルトン。
    - 例：`/profile` ならプロフィール情報のヘッダーと各セクションのスケルトン。

#### 2. Streaming と Suspense
- 遅延の大きい特定のコンポーネント（サイドバーの「おすすめ」や「コメント一覧」等）のみを `Suspense` で囲い、ページ本体が表示された後に部分的にスケルトンを表示する。
