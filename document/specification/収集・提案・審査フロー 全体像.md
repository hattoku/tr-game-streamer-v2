# 収集・提案・審査フロー 全体像

**バージョン**: v1.0
**作成日**: 2026年11月17日（リファクタリング③）
**役割**: 再生リストがプレミテに入ってくる2つの流れ（運営の収集・一般ユーザーの提案）と、その審査の**入口**。細部は各仕様書に書き、ここには地図だけを書く。

---

## 1. 2つの流れ

```
                     ┌──────────────────────────── 運営の収集（収集のフロー） ────────────────────────────┐
  掲載チャンネル ──毎日の巡回──▶ playlists（全再生リスト）──掲載状態の判定──▶ listed（公開）
  （exploration_channels）                                     └▶ unconfirmed（確認待ち）──管理者が確認──▶ listed
                                                               └▶ non_game／excluded／too_short（公開しない）
                     └──────────────────────────────────────────────────────────────────────────┘
                     ┌──────────────────────── 一般ユーザーの提案（提案・審査のフロー） ────────────────────┐
  /propose ──▶ workflows（審査中）──管理者が承認──▶ 掲載チャンネルに加える／再生リストを掲載する／ゲームを付ける
  詳細ページの「⋯」──▶ workflows（審査中）──管理者が承認──▶ ゲームの情報を直す／掲載状態を変える
                     └──────────────────────────────────────────────────────────────────────────┘
```

- **掲載するかの判断はチャンネル単位**（掲載チャンネルにするか）。再生リストは掲載チャンネルの中で、ルール（除外語・非ゲーム語・本数）と掲載方法（自動で掲載／確認してから掲載）で決まる。
- 一般ユーザーは直接は何も公開できない。提案はすべて `workflows` に入り、管理者が審査する（審査は1段）。

## 2. どこに書いてあるか

| 知りたいこと | 仕様書 | 実装 |
|---|---|---|
| 掲載チャンネルの巡回・掲載状態の判定・30日ルール | 管理_Ai運営者 コンテンツ収集機能仕様書 第2章・第10章 | `lib/channel-sweep.ts`・`lib/channel-sweep-run.ts`・`lib/new-videos-refresh.ts` |
| 掲載状態の切り替え（掲載する・ゲームではない・対象外） | 同 §10.11、管理 AI運営者向け収集候補レビューUI仕様書 第8章 | `lib/listing-server.ts`・`/api/admin/collection/listing` |
| 判定の言葉（除外語・非ゲーム語・最小本数） | 同 §10.5 | `lib/listing-rules.ts`・`/api/admin/collection/listing-rules` |
| 掲載チャンネルの管理画面 | 管理 AI運営者向け収集候補レビューUI仕様書 第9章（§6 が土台） | `app/admin/collection/channels` |
| ゲームの推定・ゲーム未設定への自動の紐づけ | 管理_Ai運営者 コンテンツ収集機能仕様書 §3.4、収集候補レビューUI仕様書 §6.5 | `lib/playlist-game-linking.ts` |
| 件数（ゲーム・チャンネル・タグの再生リスト数） | 管理_Ai運営者 コンテンツ収集機能仕様書 §10.11 | `lib/listing-counts.ts`（計算）・`lib/listing-counts-server.ts`（書き込み） |
| 一般ユーザーの提案ページ（再生リスト／チャンネル） | ページ 提案する 仕様書（フォームの細部は ページ 再生リストを追加する 仕様書・ページ チャンネルを申請する 仕様書） | `/api/playlists/propose`・`/api/channels/apply`・`/api/propose/channels*`・`lib/propose-server.ts` |
| ゲーム未設定の再生リストへのゲームの提案 | ページ 再生リスト詳細 仕様書、管理 審査ワークフロー仕様書 §4.3 | `/api/playlists/[playlistId]/game-proposal` |
| 詳細ページからの変更の提案 | ページ 詳細ページからの変更提案 仕様書 | `/api/change-proposals`・`lib/change-proposal-server.ts` |
| 審査（状態・承認・却下・通知・運営メモ・種別ごとの処理） | 管理 審査ワークフロー仕様書 §3・§4 | `app/api/admin/workflows/[workflowId]/route.ts` → `lib/workflow-decisions.ts` → 種別ごとのファイル（§6.2） |
| 管理者の直接登録 | ページ 提案する 仕様書 §9 | `lib/playlist-registration.ts`・`lib/propose-server.ts` |
| データの形 | Firestore データモデル設計書（`playlists`・`exploration_channels`・`workflows`） | |

## 3. 今の仕組みではないもの

| フォルダ | 中身 |
|---|---|
| `構想/` | 未実装の構想。二段階の審査とAI運営者（`審査ワークフロー 二段階審査とAI運営者 構想.md`・`管理 Ai運営者 審査機能仕様書.md`）、新作タイトル検知・ゲーム起点の補助収集・品質スクリーニング（`コンテンツ収集 これから足すかもしれない収集 構想.md`） |
| `取り下げ/` | 取り下げた機能。収集候補による収集（段階3まで、`収集候補による収集（段階3まで）.md`）、まとめ機能（`ページ 再生リスト まとめ機能仕様書.md`） |

構想を作るときは、構想の文書をそのまま実装の根拠にせず、今の仕様書に章を足してから作る。
