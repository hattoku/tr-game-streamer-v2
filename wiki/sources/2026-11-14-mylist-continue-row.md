# マイリストの「続きから再生」を行全体のリンクにする

Notion「ユーザビリティ改善」の子タスク「マイリストページの再生ページへボタンが大きすぎる」。仕様は ページ マイリスト機能仕様書 v1.14 §5.3。

## 変更

- `components/mylist/MylistCard.tsx`: 子エリア（最後に再生した動画）の下にあった幅いっぱいのプライマリボタン（赤）をやめ、
  サムネイル・タイトル・残り時間を含む**行全体を1つの `Link`** にした。右端に押せることを示す丸い再生アイコン
  （36px／PC 40px、セカンダリボタンの面・枠・影）を置く。ホバーで行に `bg-bg-hover`、タイトルが `text-text-primary` になる
- 自動再生できない環境（`useCanAutoplayAfterNavigation()` が false = iOS / Safari）では、丸い再生アイコンの代わりに右矢印、
  読み上げ名を「再生ページへ: 動画タイトル」にし、`?autoplay=1` を付けない（従来のボタンのラベル切り替えと同じ判定）
- アイコン自体は `aria-hidden` の飾りで、リンクは行の1つだけ（リンクの中にリンク・ボタンを入れない）
- `LinkButton` の import は不要になったので外した
- E2E: `e2e/mylist-continue-row.spec.ts`（行がリンクで `?autoplay=1` 付き・赤いボタンが無い・アイコンが右端で 40px 以下・横スクロールなし／iPhone の UA では右矢印と「再生ページへ」）

## ユーザー決定

- 「小さい灰色ボタンを右寄せ」案と比べて、「行全体をタップ＋右端に丸い再生アイコン（iPhone は右矢印）」案を選んだ（2026-11-14）

## 判断メモ

- プライマリボタンは「1ページにつき原則1つ」（共通 デザイントークン仕様書 §4.1）。一覧の各カードに置くと赤い帯が縦に並ぶため、カードの中の操作には使わない
- iOS では「再生ページへ」は親エリアのサムネイル・タイトルのクリックと同じ遷移で、大きなボタンにする理由が無かった
- 丸アイコンに赤い面（サムネイル上の再生ボタン、デザイントークン §6.5）を使わなかったのは、あれは「押すとその場で再生が始まる要素」用のため
