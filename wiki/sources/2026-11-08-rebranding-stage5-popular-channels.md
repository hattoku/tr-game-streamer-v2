# リブランディング段階5 — 人気のチャンネルと人気順

PR #26（`1525320`、2026-11-08）。仕様は 共通 人気のチャンネル 集計 仕様書（新規）、TOP v2.2、チャンネル 探す v2.2、チャンネル 詳細 v1.10、一覧のサーバー側検索 v1.2、データモデル v2.8、収集候補レビューUI v3.4、UIコンポーネント v2.1。

## 人気の並び順（ユーザー決定 2026-11-08）

- 掲載中の再生リストについて、マイリストに入れた人・レビューを書いた人・視聴を始めた人を数える。**同じ人はチャンネルごとに1人**、直近30日の人は加点
- 毎日集計して `channels.popularity` に人数を保存し、点数は読むたびに計算する（`lib/popularity-shared.ts` の `popularityScore`）。重みは仮で全部1、`RECENT_BONUS = 1`。重みを変えても再集計は要らない
- 視聴を始めた人は、`watch_history` の増えた分から `playlist_viewers` を作って数える。視聴履歴を消しても残る（退会処理ができたら消すこと、データモデル §7.1）
- 運営のピン留め（`exploration_channels.featuredOrder`、小さいほど先頭）→ 人気の点数 → 再生リスト数 → チャンネル名の順。並びは [[catalog-server]] の索引で作る。人気の点数は一般画面に出さない
- 集計 API は `POST /api/admin/popularity/recompute`（管理者か `X-Cron-Secret`）。Cloud Scheduler `channel-popularity-daily`（毎日4:00）。管理画面の掲載チャンネルに「今すぐ集計する」と内訳

## 画面

TOP に「人気のチャンネル」、キャッチコピー「人気のゲーム実況者のシリーズを、最初から・続きから。」。チャンネル一覧の既定を人気順にしてカードにレビューの合計、チャンネル詳細にレビューとマイリストの合計。
ナビ・さがすタブ・フッターはチャンネルを先頭に。ボトムタブ「さがす」は `/channels` へ。

## Claude が決めた解釈（ユーザー未確認）

「同じ人は1人」をチャンネル単位にしたこと、視聴を始めた＝`watch_history` がある人、チャンネル詳細に新しいソートを足さないこと。変えたいと言われたら見直す。
