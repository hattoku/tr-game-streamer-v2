# フェーズ3 ステップ5 — 仕上げ（3幅確認・キーボード/aria・本番E2E確認）

[[2026-09-15-phase3-step4-playlists-search]] に続くフェーズ3最終ステップ。[[2026-09-13-phase2.5-finish]] と同内容
（3幅目視確認・キーボード操作/aria・`npm run lint`/`tsc`/`build`・本番E2E確認）を、フェーズ3ステップ1〜4
（レビュー・ゲームタイトル探す/詳細・タグシステム・再生リストを探す）全体に対して実施した。これで
フェーズ3（全フェーズ共通機能）が完了。

## 1. 3幅での確認（767/768/1600px）

`scripts/dev/screenshot.mjs`で`/games` `/games/[gameId]` `/playlists` `/playlists/[playlistId]`を撮影。

| 幅 | 結果 |
|---|---|
| 767px | 問題なし |
| 768px | **再生リスト詳細ページで右カラムが横方向にオーバーフローする不具合を発見**（下記§2） |
| 1600px | 問題なし |

`/games`・`/playlists`検索ページ（`md:grid-cols-[68fr_32fr]`）は768pxでも問題なし。`/games/[gameId]`は
そもそも1カラム構成のため対象外。

## 2. 768pxのグリッド崩れ（修正）

`app/(main)/playlists/[playlistId]/page.tsx`の2カラムグリッド（`md:grid-cols-[62fr_38fr]`）で、768px時に
動画リストのタイトルが折り返さず右カラムごと画面外へはみ出していた。767px（1カラム）・1600px（62fr側が
十分広い）では発生しない、768px特有の不具合。

**原因**: CSS Gridの仕様上、`fr`単位のトラックでもグリッドアイテムの`min-width`初期値は`auto`
（内容の最小コンテンツ幅）になる。直下の子要素（動画リストの`VideoList`コンポーネント内、
`line-clamp-2`を効かせているテキスト）にどれだけラップ制約を書いても、**グリッドアイテム自体**に
`min-width: 0`が無いと、そのコンテンツの最小幅がトラック幅を押し広げてしまう。768pxのような
「38fr側の割当が動画サムネイル＋テキストの最小幅に近い」境界的な幅でだけ顕在化した。

**対応**: グリッドの直下の子div（通常時2箇所、シアターモード時のネストしたグリッドの子div1箇所）に
`min-w-0`を追加（`app/(main)/playlists/[playlistId]/page.tsx`）。768px再撮影で解消を確認。

過去のフェーズ2.5ステップ8（[[2026-09-13-phase2.5-finish]]）でも同じ`/playlists/[id]`ページを768pxで
確認済みだったが、その時点では見つからなかった。フェーズ3ステップ1（レビュー）・ステップ3（タグ）で
右カラムのコンテンツ量が増えたか、あるいは実データ（本番の実際のYouTube動画タイトル長）で初めて
顕在化した可能性が高い（当時のテストデータとの違いは未調査）。

## 3. キーボード操作・aria

フェーズ3で新規追加したUIはいずれも[[2026-09-13-phase2.5-finish]]で確認済みの共通部品を再利用しており、
新規の確認事項は限定的だった。

| 部品 | 確認結果 |
|---|---|
| タグ編集モーダル（`TagEditModal`、Radix Dialog経由の`Modal`） | 既存の`Modal`をそのまま使用。フェーズ2.5で確認済みのaria-modal・フォーカストラップ・Esc動作から変更なし |
| ソート（`SelectMenu`/`DropdownMenu`、レビュー一覧・ゲーム探す・再生リスト探す） | 既存の`DropdownMenu`共通部品を再利用。フェーズ2.5で確認済みの`aria-haspopup`/`aria-expanded`/Escから変更なし |
| 星評価（`StarRating`、フェーズ3ステップ1で新規追加） | Radix未使用の独自実装。各半星がフォーカス可能な`<button>`で構成され、コードレベルでグローバルな`:focus-visible`スタイル（`app/globals.css` §11.2）がそのまま適用されることを確認。`role="radiogroup"`だが子要素は`role="radio"`ではなく素の`button`のため、スクリーンリーダーへの現在値の伝達はaria-labelの静的文言止まり（フェーズ3ステップ1で導入済みの既存設計。今回のステップでは現状維持とし、深追いしなかった） |
| ログイン要求モーダル（未ログインで星評価クリック時） | 実ブラウザで、未ログイン状態で星をクリックすると正しくログイン要求モーダル（共通`Modal`）が表示され、評価が確定しないことを確認 |

## 4. 静的解析・ビルド

グリッド修正後に`npm run lint` / `npx tsc --noEmit` / `npm run build`をすべて再実行し成功を確認。

## 5. 本番E2E確認（一時テスト管理者アカウント使用、確認後に削除）

タグ絞り込みパネル（[[2026-09-15-phase3-step4-playlists-search]]で「本番にタグ付き再生リストが無く
未確認」としていた項目）を中心に確認した。

1. 実在の公開再生リスト（Monster Hunter Rise実況）の詳細ページで、管理者アカウントからタグ編集モーダルを開き、
   新規タグ「QA検証用テストタグ」を追加して保存
2. `/playlists`の検索条件パネルに当該タグがトグルボタンとして出現することを確認
3. トグルボタンをクリックして選択 → 該当再生リストのみに絞り込まれる（3件→1件）ことを確認
4. 絞り込み中の再生リストのカード自身にもタグピルが表示されることを確認
5. 同じ再生リストからタグを削除して保存 → `/playlists`のタグパネルから消えることを確認

確認後、本番Firestoreの`playlists`ドキュメントへの影響（`playlistTagIds`）は元の状態（空配列）に戻した。
タグ自体（`tags`コレクションの「QA検証用テストタグ」ドキュメント）は使用件数0のまま残置している
（[[2026-09-15-phase3-step3-tags]]で決定済みの「使用件数0のユーザータグは自動削除しない」方針に
準ずる、意図した状態）。
