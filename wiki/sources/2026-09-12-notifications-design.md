# フェーズ2.5 ステップ6 — 通知一覧とヘッダーベル、「タイムライン」の廃止

[[2026-09-11-phase2.5-design-plan]] のステップ5（HANDOFF の番号では6）。同じセッションでナビの
「タイムライン」を「マイリスト」に置き換えた（ユーザー決定）。

## 1. ナビの変更（UI仕様書 v1.16）

「タイムライン」は専用ページの仕様が無く暫定で通知一覧を指していた（[[2026-09-11-layout-and-system-pages]]）。
ユーザーの指示で廃止し、次のとおりにした。

| 場所 | 変更前 | 変更後 |
|---|---|---|
| ボトムタブ（モバイル） | ホーム／タイムライン／さがす／マイページ | ホーム／**マイリスト**（未ログインは `/login`）／さがす／マイページ |
| マイページタブの遷移先 | `/mylist` | `/history`（暫定。マイリストと重複するため。準備中ページ `app/(main)/history/page.tsx` を追加。プロフィール／設定ページ実装後に見直す） |
| PC グローバルナビ | 4項目＋タイムライン | 4項目に戻す（マイリストは従来どおりユーザーエリアに） |
| 通知一覧への導線 | タイムラインタブ／PCナビ／ベル | **ヘッダーのベルのみ**。そのためベルをモバイル上段ヘッダーにも表示 |

`components/layout/nav.ts` の `BottomTabKey` は `'timeline'` → `'mylist'`。HANDOFF 未解決事項7（タイムラインの仕様化）は解消。

## 2. ヘッダーベル（`components/layout/NotificationBell.tsx`）

- `notifications`（`userId == 自分 && isRead == false`）を `onSnapshot` で監視し、件数を赤いバッジで表示（99件超は「99+」）。
  通知一覧で既読にすると即座に減る。既存の複合索引（userId, isRead, createdAt）で足りる。
- 未ログインは非表示（通知仕様書 §3）。クリックで `/notifications`。通知ドロップダウン（§4.2）は見送り。
- シアターモード（compact）では 14px に縮小。

## 3. 通知一覧（`app/(main)/notifications/page.tsx`）

- 見出し＋「すべて既読にする」（セカンダリ、未読0で無効。`writeBatch` を 450 件ずつ分割）。
- タブは実装済み種別のみ: すべて／未読／シリーズ新着（件数ピル）。お知らせ・審査結果・お問い合わせ返信は依拠する機能が無いため出さない
  （`TYPE_LABEL` には将来の種別を用意済み）。
- カード: 未読ドット（7px）・種別ラベル（`Tag`。未読は強調色）・本文・相対時刻（`title` に絶対時刻、`<time dateTime>`）。
  クリックで個別既読→シリーズ新着は再生リスト詳細へ。
- ページネーション 20件（§5.5）。本人の通知は件数が小さいのでクライアント側で分割。ページ番号はゴースト／トグルONのボタン。
- 空状態2種: 「通知はまだありません」（`EmptyState`、ベルアイコン）／「該当する通知はありません」（タブ内）。
- 管理者向け「新着動画を再取得」は下部の破線枠カード「管理者用（暫定）」に隔離。
- 未ログインは `/login` へ。読み込み中はスケルトン。

## 動作確認

- `npx tsc --noEmit` / `npm run build` 成功。
- 実ブラウザ（テスト管理者、1440px / 390px）: ヘッダーのベル（PC・モバイル）、ボトムタブ「マイリスト」、
  通知一覧の見出し・空状態・管理者用カードを確認。
- **通知カードと未読バッジは未確認**: テスト管理者に通知が0件。「新着動画を再取得」は本番の全登録ユーザーに通知を生成する
  副作用があるため押していない。次に本番で新着が出たとき、または管理画面で確認する。
