# チャンネル一覧のカードで再生リストが多いことを伝える

PR #45（2026-11-15）。Notion チケット「チャンネル名から探すの一覧に再生リストが大量の場合の表示について」。仕様は ページ チャンネル 探す v2.4 §9.6。

## 何が困っていたか

人気の実況者は再生リストが数十本あるのに、カードのピックアップが3行だけなので「3本しかないチャンネル」に見えていた（ユーザー指摘。チケットには「どうあるべきか計画して」とあり、見せ方は Claude が決めた案。ユーザーは stg で確認して「マージ」）。

## 変更

- `components/channels/ChannelListCard.tsx`
  - ピックアップの上に小さく「評価の高い再生リスト」。ピックアップがすべて評価なしのときは「主な再生リスト」（「評価の高い」が不自然なため）
  - 掲載中の再生リストがピックアップより多いときは、下に `MorePlaylistsRow`「ほか N 本の再生リスト　すべて見る ›」。行全体がチャンネル詳細へのリンク（`data-testid="channel-card-more"`）
  - その行のサムネイル欄に、次にスコアが高い再生リストのサムネイルを残りの本数ぶん（最大3枚）重ねる。奥の層ほど上へずらし（`-translate-y`）、横幅を詰め（`scale-x`）、暗くする（`brightness`）。幅はピックアップ行と同じ 64px（640px 以上 80px）
  - カードに `data-testid="channel-card"`（E2E でカード単位に絞るため）
- `lib/catalog-server.ts` の `channelAggregates`: スコア順に見て、ピックアップの次からサムネイルのある再生リストを最大3枚 `moreThumbnailUrls` に集める。`lib/catalog-shared.ts` の `ChannelListItem` に追加。索引にある値を返すだけで、YouTube API・Firestore の読み取りは増えない
- E2E: `e2e/channel-card-more.spec.ts`（多いとき／3本以下のとき）

## 進め方

- 同じカードの各行の中身（マイリスト数・話数・最新話の日付）は並行の PR #46（[[2026-11-15-channel-list-pickup-rows]]、§9.5）。こちらは行の外側だけを担当し、ul を div で包んだ分の衝突をマージ時に両方残して解消した

## メモ

- stg の E2E で、絞り込みの反映前に表示されている他のチャンネルのカードの見出しまで拾って strict mode 違反になった。カード（`channel-card`）を `filter({ hasText: チャンネル名 })` で絞ってから中を見る
