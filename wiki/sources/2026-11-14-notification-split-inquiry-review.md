# お問い合わせ返信と審査結果を通知一覧から分ける

PR #39（2026-11-14）。Notion「ユーザビリティ改善」の子タスク「通知ページからお問い合わせ返信と審査結果を独立させる」。
仕様は ページ ユーザー通知機能 v1.7（§1.2・§2・§4.1・§4.3・§5.3）、共通 uiコンポーネント フロント v2.3 §2.12、ページ 再生リストを追加する v5.3 §9.4、ページ お問い合わせ履歴 v1.4 §2。

## 背景

- スマホで通知一覧のタブ（すべて・未読・再生リスト新着・審査結果・お問い合わせ返信）が2行に回り込んでいた
- 審査結果・お問い合わせ返信は大多数の一般ユーザーは使わない。お問い合わせが「再生リストの通知」と同じ場所にあるのは不自然。ただし取りこぼしは避けたい（Notion のタスク本文）

## 変更

- 知らせる場所を種別で分けた。データ（`notifications` の `type`）は変えず、出す場所だけ変える
  - 再生リスト新着（将来はお知らせ）: ベル＋通知一覧（今まで通り）
  - お問い合わせ返信・審査結果: ヘッダー右上のユーザーアイコンの件数バッジ＋メニューの「お問い合わせ履歴」「提案履歴」の「未読 N」
- `lib/notification-format.ts`: `ACCOUNT_NOTIFICATION_TYPES`・`isFeedNotification()`（通知一覧・ベルに出す種別か）
- `components/layout/useUnreadNotificationCounts.ts`（新規）: 未読を onSnapshot で購読し `feed`・`inquiry`・`review` に振り分ける。ベルとユーザーメニューの両方が呼ぶ（同じクエリの購読は SDK がまとめる）
- `NotificationBell.tsx`: `feed` だけ数える
- `UserDropdown.tsx`: 件数バッジ＝管理者の未処理の審査件数＋お問い合わせ返信＋審査結果の未読。aria-label に内訳。メニュー項目に赤丸と「未読 N」
- `app/(main)/notifications/page.tsx`: 読み込み時にお問い合わせ返信・審査結果を除き、そのタブを廃止（すべて・未読・再生リスト新着の3つで1行に収まる）
- `app/(main)/playlists/proposals/page.tsx`: 未読の審査結果を上部「新しい審査結果」に並べ（承認で再生リストがあればリンク）、該当する提案・チャンネル申請のカードに赤丸。開いた時点で既読にする。再生リストに付けたゲームタイトルの提案は履歴に並ばないので上部の一覧だけに出る
- お問い合わせ返信は今まで通り、スレッドを開くと既読（`/api/inquiries/[inquiryId]`）
- マイページ（`/mypage`、PR #40）の「通知」「提案履歴」「お問い合わせ履歴」の行にも同じ未読数（`UnreadCountLabel` を UserDropdown から export して共用）。PR #40 が先にマージされたので、こちらで main を取り込んで足した。UIコンポーネント仕様書は #40 が v2.2 を使ったため v2.3 に、ユーザー通知機能仕様書は #38 が v1.6 を使ったため v1.7 にした
- E2E: `e2e/notification-split.spec.ts`（新規）。`inquiry-history.spec.ts`・`channel-application.spec.ts` の通知一覧での確認を、ユーザーメニュー・提案履歴での確認に置き換えた

## ユーザー決定

- 知らせる場所の案（ユーザーアイコン／＋マイページタブ／通知一覧に残してタブだけ減らす）を決定カードで確認し、2026-11-14 にユーザーが「ユーザーアイコンに件数」を選んだ

## メモ

- モバイルのボトムタブ「マイページ」は今は視聴履歴へ飛ぶだけで、提案履歴・お問い合わせ履歴への入口がないため、件数はヘッダーのユーザーアイコン（モバイルでも常に表示）に出した
- 同じ通知一覧ページを「通知ページの未読の赤印の位置調整」のスレッドも触っている
