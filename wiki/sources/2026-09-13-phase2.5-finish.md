# フェーズ2.5 ステップ8 — 仕上げ（3幅確認・キーボード/aria・ESLint 導入）

[[2026-09-11-phase2.5-design-plan]] の最終ステップ（HANDOFF の番号では8）。これでフェーズ2.5（デザイン適用）が完了。

## 1. 3幅での全ページ確認

`scripts/dev/screenshot.mjs` で 767px（モバイル、タッチ）／768px（PC 境界）／1600px（最大幅 1400px 超）の3幅で
`/login` `/login?mode=signup` `/`（未ログイン・管理者）`/playlists` `/playlists/[id]`（未ログイン・管理者）`/mylist`
`/notifications` `/playlists/new` `/games`（準備中）`/no-such-page`（404）を撮影して確認した。

| 幅 | 結果 |
|---|---|
| 767px | 問題なし（モバイルレイアウト。ボトムタブ・さがすタブ・1カラム） |
| 768px | **ヘッダーが折り返す不具合**（下記 §2）。それ以外は問題なし。マイリストのタブが2段になるのは flex-wrap の想定どおり |
| 1600px | 問題なし（1400px で中央寄せ） |

細かい所見: 再生リスト詳細のヒーロー下「再生する」ボタンは `sm:max-w-[320px]` のため 640〜767px では幅 320px の左寄せになる。
390px では全幅。仕様（動画プレーヤー仕様書）に幅の指定は無く、据え置き。

## 2. 768〜1023px のヘッダー（修正）

PC レイアウトになる 768px で、ロゴ「プレミテ」・ナビ4項目・ユーザーエリア（マイリスト／視聴履歴／ベル／名前入りピル）が
1段に収まらず縦に折り返していた。1600px での実測はロゴ 94px＋ナビ 422px＋ユーザーエリア 359px（ログイン時）＋余白で
約 955px 必要で、768px には 187px 足りない。

対応（UI仕様書 v1.17 §2.6・§2.9）:

| 変更 | 効果 |
|---|---|
| ナビ・セクション間の gap を `md` で詰める（`md:gap-4 lg:gap-6`、`md:gap-6 lg:gap-8`）、ロゴ・ナビ・リンクに `whitespace-nowrap` | 折り返しを禁止して隙間を縮める |
| ユーザーエリアの「マイリスト」「視聴履歴」文字リンクを `hidden lg:flex`（1024px 未満で非表示） | −149px |
| ユーザーピルの表示名を `hidden lg:inline`（1024px 未満はアイコン＋▾だけ） | −96px |
| ユーザードロップダウンに「マイリスト」「視聴履歴」を追加（幅に関係なく常に表示） | 非表示にした導線の代替 |

768px で未ログイン（ログイン＋アカウント作成）・ログイン済み（ベル＋ピル）とも1段に収まることを確認。1000px も同様。
`components/layout/Header.tsx`・`UserDropdown.tsx`（`USER_NAV` を import）・`components/ui/Logo.tsx`。

## 3. キーボード操作・aria（実ブラウザで確認）

撮影スクリプトの `eval` で属性と `document.activeElement` を読み、`document.dispatchEvent(new KeyboardEvent('keydown', {key: 'Escape'}))`
で Esc を送って確認した。

| 部品 | 確認結果 |
|---|---|
| ログイン要求モーダル・ゲーム選択モーダル（Radix Dialog） | `role=dialog`、`aria-labelledby`/`aria-describedby` あり、開くとフォーカスが中に入る（ゲーム選択は検索欄）、`body` が `overflow: hidden`、外側は `aria-hidden`、Esc で閉じてトリガーにフォーカスが戻る |
| モバイルのドロワー（Radix Dialog） | トリガーに `aria-haspopup=dialog`・`aria-expanded`、開くと閉じるボタンにフォーカス、Esc で閉じて `aria-expanded=false`・スクロール固定解除・トリガーにフォーカス復帰 |
| ソート・ユーザーメニュー・ステータス変更（Radix DropdownMenu） | トリガーに `aria-haspopup=menu`・`aria-expanded`、開くと `role=menu` にフォーカス、ラジオ項目に `aria-checked`、Esc で閉じてフォーカス復帰 |
| タブ（Radix Tabs） | `role=tablist`、選択中に `aria-selected=true` |
| ボトムタブ・PC ナビ | `nav[aria-label]`、現在地に `aria-current=page` |

**`aria-modal` だけは Radix が付けない**（外側を `aria-hidden` にする方式のため）。計画書の確認項目に挙げていたので、
`Modal`（`components/ui/Modal.tsx`）と `MobileMenu` の `Dialog.Content` に `aria-modal="true"` を明示した。

## 4. ESLint の導入

### 4.1 経緯

`package.json` の `lint` は `next lint` だったが、Next.js 16 では廃止されていて動かない（`next lint` は
「Invalid project directory provided, no such directory: .../lint」になる）。公式手順
（`node_modules/next/dist/docs/01-app/03-api-reference/05-config/03-eslint.md`）は `eslint` ＋ `eslint-config-next` の
フラット設定だが、**`eslint-config-next` は読み込み時に typescript-eslint を require し、typescript-eslint は
TypeScript 7.0 未対応で例外を投げる**（`typescript-eslint does not support TS 7.0.`、
typescript-eslint/typescript-eslint#10940）。`@typescript-eslint/parser` 単体も同じチェックで落ちる。

TypeScript 7.0 の公式ブログ「Running Side-by-Side with TypeScript 6.0」の回避策は、`typescript` パッケージ名を
TS 6 互換パッケージ `@typescript/typescript6` に別名解決させ（`"typescript": "npm:@typescript/typescript6@^6.0.2"`）、
TS 7 の `tsc` は `"@typescript/native": "npm:typescript@^7.0.2"` で別名にする方法。これは `next build` の型チェックや
[[2026-09-09-tech-stack-upgrade]] の TS 7 固定にも関わるため、このステップでは採らなかった（HANDOFF 未解決事項 10）。

**2026-09-13 ユーザー決定**: 3案（①暫定構成を維持し typescript-eslint の TS 7 対応後に `eslint-config-next` へ戻す／
②公式回避策の別名解決で今すぐ戻す／③oxlint へ切替）を比較し、ビルド・型チェック・IDE の TS 7 環境に触れない①を採用。
戻す手順は HANDOFF 未解決事項 10。

### 4.2 採った構成（`eslint.config.mjs`）

TypeScript に依存しない `@babel/eslint-parser` で構文解析し、公式設定と同じ構成要素を直接組む。

| 依存（devDependencies、固定版） | 役割 |
|---|---|
| `eslint` 10.10.0 | 本体 |
| `@babel/core` 8.0.5・`@babel/eslint-parser` 8.0.5 | パーサー。`babelOptions.parserOpts.plugins` で `.js/.mjs`=`['jsx']`、`.ts`=`['typescript']`、`.tsx`=`['typescript','jsx']`（`.ts` で jsx を有効にするとジェネリクス `<T>` が JSX と衝突する） |
| `@next/eslint-plugin-next` 16.3.4 | `configs['core-web-vitals'].rules` |
| `eslint-plugin-react-hooks` 7.1.1 | `configs.flat.recommended.rules`（React Compiler 由来のルールを含む） |

`@babel/preset-typescript` は Babel 8 で `isTSX`/`allExtensions` が廃止されており、拡張子判定に頼ると `.tsx` が
TS として解析されなかったため使わず、`parserOpts.plugins` で拡張子ごとに明示した。型情報を使うルールは無い。
`lint` スクリプトは `eslint .`。

### 4.3 指摘と修正

| 指摘 | 対応 |
|---|---|
| `react-hooks/set-state-in-effect` × 3（`/mylist`・`/notifications` の `useEffect` で `loadEntries(uid)`/`load(uid)` を直接呼ぶ、`NotificationBell` の `if (!user) setUnread(0)`） | ページ側は非同期 IIFE（`(async () => { try { await load(uid) } catch {...} })()`）に変更（再生リスト詳細と同じ形）。ベルはログアウト時の `setUnread(0)` を effect のクリーンアップに移動 |
| 未使用の `eslint-disable react-hooks/exhaustive-deps`（再生リスト詳細） | 削除 |
