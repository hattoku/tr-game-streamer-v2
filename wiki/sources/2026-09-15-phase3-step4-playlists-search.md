# フェーズ3 ステップ4 — 再生リストを探す本実装

[[2026-09-15-phase3-step3-tags]] に続くフェーズ3ステップ4。`ページ 再生リストを探す 仕様書.md`準拠で
`/playlists`を最小版（新着順一覧のみ）から本実装へ差し替えた。

## 実装方針

`/games`（[[2026-09-14-phase3-step2-games]]）と同じ簡易実装方針: カタログ規模が小さい前提で、全件を
クライアント取得し、キーワード・タグでのフィルタ、ソート、ページングをすべてクライアント側で行う。

## 変更点

- `app/(main)/playlists/page.tsx`: 最小版（`PlaylistGrid`をそのまま表示するだけ）から、キーワード検索・
  タグ絞り込み(AND)・ソート3種（スコア/マイリスト数/新着順）・20件ページネーション・モバイルの
  アコーディオン検索パネルを備えた本実装に差し替え。`/games`のページ構造（2カラムグリッド、
  モバイルアコーディオン、フィルターチップ、トグルボタン）をほぼそのまま踏襲。
  - キーワード検索の対象は**ゲームタイトル・チャンネル名**（仕様書§4.2）で、再生リスト自身のタイトルは
    対象外。これは`/games`のキーワード検索（ゲームタイトルのみ）と異なる点。
  - タグ絞り込みの表示件数「実況スタイル系は全件、その他は上位5件」（§4.3）は、`tags`スキーマに
    カテゴリ情報が無いため`/games`と同じくフラット一覧+「もっと見る」に簡略化（既存のスコープ外方針を踏襲）。
- `components/playlists/PlaylistGrid.tsx`:
  - `fetchPublicPlaylists`を新規追加（`/playlists`本実装向けの全件取得関数）
  - `PlaylistSummary`に`tags: ResolvedTag[]`を追加し、`toSummary`が`tagsMap`を受け取って
    `playlistTagIds`/`playlistTagsFixed`を解決するように変更
  - `PlaylistCardGrid`のタグ表示を、フェーズ3ステップ3までの「ゲームタイトルを仮タグとして表示」
    （`<Tag emphasis>{p.gameName}</Tag>`）から、実際のタグ（`§3.5`の表示優先順位: 固定→登録日順、
    最大3件+「+N」）に置き換え。`highlightTagIds`propで絞り込み中タグを太字強調（`/games`の`GameCard`と
    同じパターン）
  - `fetchPlaylistsByGame`（ゲームタイトル詳細の関連再生リスト節が使用）・`PlaylistGrid`（TOP最小版が使用）
    も同様に`tagsMap`を取得してタグを解決するよう変更。両者とも呼び出し側のコードは無変更（内部実装のみ変更）

## 確認

`npx tsc --noEmit` / `npm run lint` / `npm run build`成功。実ブラウザ（1440px/390px）でキーワード検索
（「ゼルダ」で1件に絞り込み）・フィルターチップの表示と個別解除・リセットボタンの活性化とクリア動作を
`scripts/dev/screenshot.mjs`で確認。タグ絞り込みパネル自体は、確認時点で本番にタグ付き再生リストが
無かったため未確認のまま次ステップ（[[2026-09-15-phase3-step5-finish]]）に持ち越し、そちらで
一時タグを付与して確認済み。
