# リブランディング段階7 — 一覧をサーバー側検索に作り直す

PR #25（`d480506`、2026-11-08）。仕様は 共通 一覧のサーバー側検索 仕様書（新規）、再生リストを探す v2.2、チャンネル 探す v2.1、ゲームタイトル 探す v1.6、top v2.1、ゲーム詳細 v2.7、チャンネル詳細 v1.9、技術スタック v2.18、データモデル v2.7。

## 変更

- 掲載中の全件をブラウザに読み込む形から、**サーバーで絞り込み・並べ替え・ページングして1ページ（20件）だけ返す**形へ。80チャンネル（約5,300再生リスト）でも軽く、Firestore の読み取りが表示回数に比例しない
- 仕組みは [[catalog-server]]（`lib/catalog-server.ts`）。API は `/api/catalog/playlists`・`channels`・`games`・`top`（ログイン不要の GET）
- キーワードは部分一致。NFKC・大小・カタカナ/ひらがなを無視し、空白区切りは AND。入力が止まって300ms後に検索
- TOP の各カルーセルは最大20件（以前は上限なし）。注目はサーバーが40件返し、画面で完走済みを除く
- ページ番号は7ページを超えると「1 … 49 50 51 … 265」と省略
- 回数制限 `lib/rate-limit.ts`: 接続元ごと1分240回、インスタンス全体3,000回
- まとめ（取り下げ中）は全件取得のまま。`lib/playlist-aggregates.ts` は削除

- 設計（メモリ索引＋onSnapshot など）はユーザー確認前に Claude が決めたもの。変えたいと言われたら見直す
