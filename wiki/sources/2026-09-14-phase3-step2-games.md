# フェーズ3 ステップ2 — ゲームタイトル探す・詳細ページ

[[2026-09-13-phase3-step1-reviews]]に続くフェーズ3の2番目のステップ。`/games`（探す）と
`/games/[gameId]`（詳細）を新規実装した。フェーズ2.5では`/games`は`ComingSoon`のプレースホルダーの
ままで、コード内コメントに「本実装はフェーズ3以降」と明記されていた。

## 実装

- `/games`: キーワード検索・ジャンル絞り込み（OR）・タグ絞り込み（AND）・3種のソート
  （再生リスト登録数順・タイトル名順・動画数順）・20件ページネーション・モバイル用アコーディオン
  検索パネル、`?tag=`での深いリンク流入（ゲームタイトル詳細のタグクリック等）に対応。
- `/games/[gameId]`: パッケージ画像・楽天リンク・ジャンル/テーマ・再生リスト数/総動画数・タグ・
  説明文（AI生成バッジ）・関連する再生リスト一覧（`components/games/GamePlaylistSection.tsx`）。
- 既存の`components/playlists/PlaylistGrid.tsx`を`PlaylistCardGrid`（データを外部から渡す版）・
  `fetchPlaylistsByGame`・`sortPlaylists`に分解し、「再生リストを探す」仕様書と同一のカードを
  関連再生リストセクションで再利用した（`isPublic`+`gameId`の等価条件のみのクエリのため新規の
  Firestore複合indexは不要。並び替え・ページングは取得後にJS側で行う）。
- `lib/tags.ts`（`fetchTagsMap`・`resolveTags`）・`lib/playlist-aggregates.ts`
  （`fetchGameVideoCounts`。`games`に総動画数の集計フィールドが無いため、公開再生リストから
  都度集計する）を新設。以降のタグシステム（ステップ3）でも共用する設計。
- `/playlists/new`に`?gameId=`プレフィル対応を追加（ゲームタイトル詳細の「再生リストを追加する」
  ボタンから遷移した際、ゲームタイトルを事前選択する）。

## スコープ外にした点

- 「情報を編集ボタン」（第7章の管理者編集フロー・一般ユーザーの提案フロー）は審査ワークフロー
  自体が未実装のため非表示。フェーズ2.5でパスワード再発行リンク等を「未実装機能は置かない」方針で
  省略した前例に合わせた（ユーザー合意）。
- タグ絞り込みのカテゴリ分け（§4.4「遊び方系・IP系などのカテゴリごとに上位5件」）は、`tags`
  スキーマにカテゴリを表す情報が無いため未実装。フラットな一覧として全件表示する。

## 実機確認で見つかった修正（いずれもユーザーフィードバック起点）

ブラウザでの確認を経て、以下の指摘を受けてその場で修正した。

1. **キーワード検索欄の×ボタンが二重表示される**: `<Input type="search">`はブラウザ標準の
   クリアボタンを持つため、自前で追加した×ボタンと重複していた。`type="text"`に変更して解消。
2. **PC版で「どの絞り込みが有効か分からない」**: 右カラムのバッジのハイライトだけでは選択状態が
   分かりにくいという指摘。当初モバイルのアコーディオン折りたたみ時にのみあった「適用中フィルター
   チップ」表示を、PC・モバイル共通で左カラム（カード一覧の最上部）に常時表示するよう変更した。
   仕様書に無かった挙動だったため、「ページ ゲームタイトル 探す仕様書」をv1.3に更新し、
   §4.7「適用中の検索条件の表示（左カラム）」を新設、§7.3（モバイルのアコーディオン）も
   この共通仕様に合わせて改訂した。
3. **ジャンル・タグ絞り込みバッジの選択状態が分かりにくい**: `Tag`コンポーネントの淡いハイライト
   （背景色の変化のみ）では不十分という指摘。マイリストのステータス変更等で使っている
   「境界線＋塗りつぶし＋チェックアイコン」のトグルボタン（`Button variant="secondary" active`）に
   差し替えた（`FilterToggle`ヘルパー）。
4. **カード上のタグにホバー効果があるのにクリックしても何も起きない**: ゲームタイトル一覧のカード
   （`GameCard`）は、クリック不可（`href`/`onClick`未指定）の読み取り専用タグとして`Tag`を使っていたが、
   `Tag`コンポーネント自体が全ての表示モードで無条件にホバー効果（`hover:bg-white/10`等）を
   適用していたため、押せそうに見えて実際は親カードのリンクへ吸収される紛らわしい挙動になっていた。
   `Tag`コンポーネントを修正し、クリック可能なとき（`href`または`onClick`指定時）のみホバー効果を
   付けるようにした。ゲームカードだけでなく`PlaylistGrid`のゲームタイトルタグ等、同じ`Tag`を
   使う他の箇所にも共通で効く修正。仕様上、一覧ページのカード上のタグはクリックで絞り込む設計には
   なっていない（クリックで絞り込む挙動があるのはゲームタイトル詳細ページのタグのみ）ことを
   仕様書で確認済み。

## react-hooks/set-state-in-effect の修正

`/games`ページ・`GamePlaylistSection`・`/playlists/new`（`?gameId=`プレフィル）で複数件発生。
[[react-hooksのset-state-in-effect対応]]の「propが変わったらstateを調整するパターンは描画中に
直接setStateする」を適用して解消。

## 動作確認

`npm run lint`/`tsc --noEmit`/`npm run build`成功。ブラウザでの実機確認（PC）はユーザーが実施し、
上記4件の指摘を受けて修正済み。モバイル幅での確認は未実施。
