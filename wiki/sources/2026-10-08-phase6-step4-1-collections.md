# フェーズ6 ステップ4-1 — まとめ機能（作成・編集・詳細・まとめに追加）

全体計画の見直し（[[2026-10-08-plan-review-phase6.5]]）で次の作業をフェーズ6ステップ4（まとめ機能）に決定。
仕様書（`ページ 再生リスト まとめ機能仕様書`）が広いため、「一人で使って価値が出る順」に3分割した。

| サブステップ | 範囲 | 状況 |
|---|---|---|
| 4-1 | 作成・編集・削除、まとめ詳細、「まとめに追加する」導線、まとめ自体の並び替え | 今回実装 |
| 4-2 | まとめを探す（§6）、発見導線（§7） | 未着手 |
| 4-3 | 保存機能（§8） | 未着手（他人のまとめが無いと価値が出ないため最後。フェーズ7以降への後ろ倒しも可） |

## ユーザー決定事項（着手時）

- 自分のまとめ一覧は **`/collections/mine` を新設**（プロフィール未実装の間の入口。ユーザーメニュー「自分のまとめ」）
- まとめ内・まとめ自体の並び替えは **↑↓ボタンのみ**（D&Dなし、ライブラリ追加なし）
- 作成者名・アイコンは **`collections` に非正規化**（`reviews.userDisplayName` と同方式）
- 4-1に「まとめに追加する」導線（再生リスト詳細の視聴記録カード＋マイリストカード）と、まとめ自体の並び替えを含める

## 実装内容

- `lib/collections-shared.ts`（定数・型・公開設定ラベル。サーバーとクライアント共通）／`lib/collections.ts`（クライアント取得、
  `callCollectionsApi`）／`lib/collections-server.ts`（入力検証・`readJsonObject`・作成者スナップショット）。
  サーバーからクライアント用Firebase SDKを読まないよう定数ファイルを分けた。
- API: `app/api/collections`（POST作成）・`[collectionId]`（PATCH: フォーム全体の置き換え／`addPlaylistId`・`removePlaylistId`、
  DELETE）・`reorder`（POST、集合不一致は409）。1ユーザー10件・1まとめ10件の判定と書き込みは `runTransaction`。
- `firestore.rules` の `collections` を **`allow write: if false`**（書き込みはAPI Routeのみ）。上限と作成者名の偽装防止のため。
  **stg/本番への反映は次回 `deploy.ps1` 実行時**。
- ページ: `/collections/new`（`?playlistId=` で初期値）・`/collections/[collectionId]`（詳細）・`/collections/[collectionId]/edit`・
  `/collections/mine`。非公開まとめを他人が開く／他人が編集URLを開くと404。詳細ページはログイン状態の確定を待ってから
  `onSnapshot` する（確定前に読むと本人の非公開まとめも拒否され、即404になるため）。
- 部品: `CollectionForm`（公開設定・ネタバレ設定は Chip を択一トグルとして使用）・`PlaylistPickerModal`（公開再生リスト全件、
  マイリスト登録済みを先頭、最大50件表示）・`CollectionCard`（§6.3、4-2・プロフィールでも使う想定）・`AddToCollectionButton`
  （チェックボックスで即時追加・解除、最後の1件は外せない）・`VisibilityBadge`。
- 既存変更: `ReviewForm`（視聴記録カードに「まとめに追加する」）、`MylistCard`（「まとめに追加」、モバイルは削除ボタンをアイコンのみにして1行維持）、
  `UserDropdown`（「自分のまとめ」）。
- 仕様書: まとめ機能 v1.2（§1実装状況を新設、欠落していた§2見出しを補完）、Firestore データモデル v1.16、ページ一覧 v1.8、
  マイリスト機能 v1.11、レビュー投稿機能 v1.7.0、トレーサビリティ・マトリクス v1.9。

## dev-orchestratorレビュー（spec-conformance・design-consistency を並列委任）

重大指摘なし。対応したもの:
- API の `request.json()` が壊れたJSON・`null` で500になる → `readJsonObject` で400 `invalid_body`
- 10件上限が同時リクエストで超えうる → トランザクション化
- 自分のまとめの「編集」「削除」にアクセシブルネームが無い → `「タイトル」を編集/削除` の aria-label
- `CollectionCard` の作成者名 truncate に `min-w-0`、公開設定バッジの重複を `VisibilityBadge` に共通化、コメントの不正確な記述修正
- トレーサビリティ・マトリクスとレビュー投稿機能仕様書への相互参照、§1 への補足（編集保存時に読めない再生リストが外れる等）

見送り: モバイルのアイコンのみ削除ボタンのタップ領域（約29×28px）、ラジオの共通部品化（ReportModal の生radioとあわせて将来）。

## 実機確認後の調整（2026-10-12、ユーザー指摘）

- まとめ詳細のヘッダーカードが縦積みで間延びしていた → タイトル行の右に編集ボタン、作成者・作成日・公開設定を1行に。
  説明文は区切り線の下で、長ければ3行に折りたたみ「続きを読む」。
- 日付が何の日付か分からない → 「YYYY年M月D日 作成」（後日編集なら「（… 更新）」）。
- 件数はヘッダーではなく、一覧の上の見出し「このまとめの再生リスト N件」へ（表示できた件数を数える）。

## ハマりどころ

- `TaskStop` で `npm run dev` を止めても、子の Next dev サーバー（ポート3000）が残ることがある。その状態で `npm run build` すると
  dev サーバー側が「Jest worker encountered child process exceptions」で壊れる。止めるときはポート3000の待ち受けプロセスを確認して止める。
- 既存ファイルは CRLF、新規作成ファイルは LF になる（git の正規化に任せている）。Node スクリプトで文字列置換する場合は改行コードに注意。

## 動作確認

lint / tsc / build 成功。ローカル `npm run dev`（stg）＋Playwright で、作成（バリデーション・選択モーダル・↑↓）→詳細（順序・ネタバレ折りたたみ／表示・
視聴ステータス）→未ログインで非公開=404→「まとめに追加する」（未ログイン時ログイン要求、追加／解除、最後の1件は外せない、新規作成へプリフィル）→
限定公開を他ユーザーで閲覧（編集ボタン無し・編集URLは404）→並び替え（再読み込み後も保持）→編集→削除。390/768/1440px で横スクロール無し。
APIはトークン無しで401。確認用のまとめはすべて削除済み。
