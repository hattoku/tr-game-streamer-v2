# フェーズ6 ステップ4-3 — まとめの保存機能

[[2026-10-12-phase6-step4-2-collections-discovery]] の続き。他人のまとめを保存する機能（まとめ機能仕様書 §8）。これでまとめ機能（4-1〜4-3）は完了。

## ユーザー決定事項（着手時）

- 保存したまとめ一覧 `/collections/saved` の入口は **ユーザーメニュー＋「まとめを探す」の見出し横**（仕様 §8.3 のヘッダーリンクは置かない。ヘッダーが混むため）
- TOP の「保存数の多いまとめ」は**見送り**（保存する人が増えてから）。`/collections` の保存数順ソートは追加
- 保存したまとめが**削除**されたら保存記録も自動で消す。**非公開化**されたら一覧に「閲覧できなくなったまとめ」として残し、解除できる

## 実装内容

- 新コレクション `saved_collections/{uid}_{collectionId}`（`userId`・`collectionId`・`collectionTitle`（保存時点のタイトル）・`savedAt`）。
  Firestore データモデル設計書 v1.17 §3.14.1。
- API（すべて Admin SDK）:
  - `app/api/collections/[collectionId]/save`: GET（保存状態）／POST（保存、公開・限定公開の他人のまとめのみ）／DELETE（解除、非公開化・削除済みでも可）。
    保存記録の作成・削除と `collections.savedCount` の増減を同じトランザクションで行う。二重保存は加算しない、0未満にしない。
  - `app/api/collections/saved`: 保存一覧。非公開化されたまとめは本人でもクライアントから読めないため、サーバーで読んで `collection: null` で返す。
  - まとめ削除 API で `saved_collections` を `collectionId` で引いて同じバッチで削除。
- `firestore.rules`: `saved_collections` は本人・管理者 R、write false（**次回デプロイで反映**）。読み書きを API に寄せたので、ルール未反映の stg でもローカル確認できた。
- `SaveCollectionButton`（まとめ詳細のタイトル行の右、作成者以外のログインユーザー。保存済みは塗りつぶし♡＋トグルON）、
  保存数をメタ行に ♡ N（`onSnapshot` で即反映）。`/collections/saved` ページ（保存日時の降順・20件・「保存を解除」・閲覧不可の案内行）。
- API がまとめを返すため、日時をミリ秒にした `CollectionJson` と変換関数（`toCollectionJson` / `fromCollectionJson`）を追加。

重大指摘なし。対応: 仕様書 §8.3・§8.4 本文への実装注記、トレーサビリティ・マトリクスへの `saved_collections` 追記、データモデルにバッチ上限の注記、

## ハマりどころ

- dev-orchestrator はサブエージェントを並列起動した直後にハンドバックしてしまうことがある（4-1・4-3 で発生）。その場合は各専門エージェントの
  ハンドバックを親が直接受け取って統合すればよい。
- テストモードの利用者切替をログイン必須ページ上で行うと、切替の瞬間に未ログイン扱いになり `/login` 経由で TOP へ飛ぶ。切替は TOP で行ってから目的のページへ。
- スクリーンショットのためにテストモードウィジェットを DOM から消すと、その後の切替ボタン操作が空振りする（同じページ内では復活しない）。
