# フェーズ2.5（デザイン適用）計画

フェーズ2の6ステップ完了を受け、ノースタイルで実装してきたコアループ一式
（登録→視聴→マイリスト管理→新着通知）へ、既存のデザイン仕様書を適用する計画。
HANDOFF.md のフェーズ2.5セクションと対になる詳細版。

## 1. 対象ページと現状

| ページ | 現状 | 根拠仕様書 |
|---|---|---|
| `/` TOP | Firestore接続テスト表示のみ（デバッグ用） | ページ top 仕様書 |
| `/login` | email/password フォーム＋ログイン中表示 | ログイン仕様書 §5, §12.1 |
| `/playlists/new` | 管理者専用の登録フォーム・プレビュー・ゲーム選択モーダル・完了画面 | 再生リストを追加する 仕様書 §2, §4, §6.1 |
| `/playlists/[playlistId]` | プレーヤー・コントローラ・逆順・動画リスト（1カラム、inline style） | 再生リスト詳細 仕様書 / 動画プレーヤー 仕様書 |
| `/mylist` | フィルタ・ソート・カード（親のみ）・暫定の追加フォーム | マイリスト機能仕様書 §2〜5 |
| `/notifications` | 一覧・フィルタ（すべて/未読）・既読操作・管理者用再取得ボタン | ユーザー通知機能仕様書 §5 |
| 共通 | ヘッダー・フッター・エラーページ・loading すべて未実装 | 共通 uiコンポーネント フロント 仕様書 / 共通 ページレイアウト 仕様書 / 共通 エラーページ 仕様書 |

## 2. 前提となる技術決定

### 2.1 スタイリング方式: Tailwind CSS v4 ＋ CSS変数トークン ＋ ヘッドレスUI

**2026-09-11 ユーザー決定**: HeroUI / Mantine のような完成品ライブラリは採用せず、
見た目は Tailwind でトークンどおりに自作し、挙動の難しい部品（モーダル・ドロワー・
ドロップダウン・タブ・トースト）は **Radix UI Primitives**（見た目を持たないヘッドレスUI）
に任せる。理由: デザインはすでに仕様書で決まっており、完成品ライブラリでは既定デザインの
打ち消しが作業の大半になる一方、アクセシビリティ挙動（フォーカス閉じ込め・Esc・キーボード
操作・aria）は自作するとバグが出やすいため。管理画面（フェーズ3以降、14ページ）は
ブランド体験より作業効率が優先されるため、そのときに Mantine 等の完成品を `/admin` の
ルートグループに閉じて使うことを別途検討する。

- `技術スタック仕様書.md` §2 がスタイリングに **Tailwind CSS** を指定しているため、これに従う。
  `package.json` には未導入なので、フェーズ2.5ステップ1で導入する。
- Next.js 16 の公式手順（`node_modules/next/dist/docs/01-app/01-getting-started/11-css.md`）に従い
  `tailwindcss` ＋ `@tailwindcss/postcss` を devDependencies に追加、`postcss.config.mjs` を作成、
  `app/globals.css` に `@import 'tailwindcss';` を置き `app/layout.tsx` から読み込む。
  バージョンは [[依存バージョン固定方針]] に従いキャレット無しで固定する。
- **デザイントークンは `globals.css` の `@theme` ブロックで CSS 変数として定義**し、
  `共通 デザイントークン仕様書.md` のトークン名（`color-bg-base` 等）をそのまま
  `--color-bg-base` として登録する。これにより `bg-bg-base` / `text-text-muted` 等の
  ユーティリティが生成され、仕様書のトークン名とコードが1対1で対応する。
  トークンが CSS 変数として独立しているため、万一 Tailwind をやめる場合も
  変数定義はそのまま流用できる。
- 却下案: CSS Modules ＋ 素の CSS 変数（依存追加なし）。仕様書がTailwindを指定して
  いる点、コンポーネント量が多くユーティリティの方が速い点から不採用。

### 2.2 コンポーネント配置

```
components/
├── ui/        Button / Card / Chip / Badge / Tag / ProgressBar / Skeleton / Spinner /
│              EmptyState / Toast / Modal / Input（仕様書 §4〜§9 の再利用部品）
└── layout/    Header / MobileDrawer / UserDropdown / Footer / PageContainer / AuthLayout
```

- import は既存コードに合わせ相対パスを基本とするが、`tsconfig.json` に `@/*` エイリアスが
  既にあるため、`components/` 配下からの参照は `@/components/...` を使ってよい。
- 各ファイル冒頭に日本語コメントと根拠仕様書の章番号を書く（`.agent/rules/coding_rules.md`）。

### 2.3 ライブラリの追加方針

- アイコン: 追加ライブラリは入れず、必要な数点（再生三角・ベル・ハンバーガー・×・
  YouTubeロゴ・虫眼鏡・ハート）をインライン SVG コンポーネントとして `components/ui/icons.tsx` に置く。
  仕様書が Material Symbols 名（`search`, `favorite` 等）で推奨アイコンを示しているが、
  依存追加を避けるため名前だけ合わせて自作する。
- モーダル（ログイン要求・ゲーム選択）・ドロワー・ドロップダウン（ユーザーメニュー・
  ステータス変更・その他▼）・タブ・トーストは Radix UI Primitives を使う
  （`@radix-ui/react-dialog` / `react-dropdown-menu` / `react-tabs` / `react-toast`。
  ドロワーは Dialog を右寄せスライドで実装）。バージョンはステップ2で `npm view` で確認し
  キャレット無しで固定する。完成品UIライブラリ（HeroUI / Mantine 等）は入れない。

## 4. 実装ステップ

各ステップを1コミット単位とする。ステップ間の依存は上から順。

### ステップ0: 仕様書の穴埋め（§3）— 2026-09-11 完了（[[2026-09-11-design-foundation]]）
- `共通 デザイントークン仕様書.md` v1.2 追記、`共通 uiコンポーネント フロント 仕様書.md` の
  トースト位置確定、`動画プレーヤー 仕様書.md` の進捗バー色をトークン参照に修正。
- コードは触らない。

### ステップ1: スタイリング基盤とUI部品 — 2026-09-11 完了（[[2026-09-11-design-foundation]]）
- Tailwind v4 導入、`app/globals.css`（`@theme` トークン、body 背景 `#0f0f0f`、
  システムフォント 14px / 1.6、スケルトンの keyframes）。
- `components/ui/`: Button（primary/secondary/external）、Card、Chip（視聴ステータス）、
  Badge（注目上昇中・NEW）、Tag、ProgressBar、Skeleton、Spinner、EmptyState、Input、
  Modal、Toast（Provider＋`useToast()`）、icons。
- 確認: `npx tsc --noEmit` と `npm run build`。部品を並べた確認用ページは作らず、
  ステップ2以降で実ページに当てながら確認する。

### ステップ2: 共通レイアウトとシステムページ — 2026-09-11 完了（[[2026-09-11-layout-and-system-pages]]）
- `components/layout/`: Header（PCナビ4項目・未ログイン時のログイン/アカウント作成・
  ログイン済み時のマイリスト/視聴履歴/ベル/ユーザードロップダウン・sticky）、
  MobileDrawer（右からスライド・オーバーレイ・body スクロール固定）、Footer、
  PageContainer（max-width 1400px、モバイル左右16px）、AuthLayout（ロゴのみ）。
- `app/layout.tsx` に Header/Footer/ToastProvider を組み込む。`/login` はルートグループ
  `app/(auth)/login` に移し AuthLayout を適用（URL は変わらない）。
- `app/not-found.tsx`・`app/error.tsx`（エラーページ仕様書 §3, §5）、`app/loading.tsx`
  （グローバルスケルトン）。ナビの遷移先で未実装のもの（`/playlists`・`/games`・
  `/channels`・`/collections`・`/history`・`/profile`・`/settings` 等）は 404 ページに落ちる。
- `/` TOP: デバッグ表示を廃止し、**最小版**として「登録済み再生リスト一覧（新しい順、
  サムネイル＋タイトル＋チャンネル名のカードグリッド）」のみを置く。理由: 現状
  `/playlists/[id]` へ辿り着く導線が無く、ヘッダーのロゴ遷移先も必要なため。
  `ページ top 仕様書.md` の本実装（おすすめ・続きから見る等）はフェーズ3へ。
- ログアウト操作はヘッダーのドロップダウンへ移し、`/login` からログイン中表示を除く。

### ステップ3: 再生リスト詳細（動画プレーヤー）— 最重量
- PC 2カラム（左 62% / 右 38%、ガター 24px）、モバイル1カラム（仕様書のセクション順）。
- 左: ヒーロー（サムネイル→プレーヤー 16:9、再生/続きから再生＋進捗、コントローラ
  セカンダリボタン群）。
- 右: 基本情報カード（タイトル1行省略・スコア/マイリスト数/レビュー数はデータ未整備の
  ため「—」表示・参照元リンク）、動画リスト（サムネ＋タイトル＋尺＋進捗バー＋再生中
  ハイライト＋▶アイコン、「全XX話」）、配信者情報カード（アイコン・名前・YouTubeで見る）。
- シアターモード: 全幅黒背景プレーヤー、コントローラ黒背景、ヘッダー 30px 化
  （Header に `compact` prop）。
- フェーズ2で「見た目の話」として見送った **現在再生中の動画への自動スクロール** を
  ここで実装する。
- **「マイリストに追加」ボタン**を基本情報カード直下に設置（本来の設置場所。
  マイリスト仕様書 §1.3）。未ログイン時はログイン要求モーダル（UI仕様書 §5）を表示。
  成功時はトースト。
- ゲーム情報・レビュー投稿セクションはフェーズ3のまま（枠だけも置かない）。

### ステップ4: マイリスト
- ページ見出し・フィルタタブ（件数バッジ、「その他▼」ドロップダウン）・ソート select。
- カード: 親（サムネ・タイトル2行省略・チャンネル・ステータスチップ＝クリックで
  変更ドロップダウン・逆順トグル）＋子（最後に再生した動画＝`watch_progress` から取得、
  サムネ＋進捗バー＋タイトル。最終話視聴済みなら非表示、新着があれば 🔔 NEW 行）。
  子エリアはフェーズ2で「プレーヤー実装後に対応」として見送ったもので、カードの
  デザインが子エリア前提のためここで実装する。
- 暫定の追加フォームを削除（ステップ3で本来の場所に移設済み）。
- 空状態（ハート・「マイリストは空です」・「動画を探す」→ `/`。`/playlists` は未実装
  のため暫定で TOP へ）。
- 「新着通知のON/OFFトグル」（§5.4）はユーザー設定ページが無いため見送り（常にON）。

### ステップ5: 通知一覧とヘッダーベル
- ヘッダーのベルアイコン＋未読件数（`notifications` を `userId+isRead` で count）。
- 一覧: 見出し＋「すべて既読にする」、タブは実装済み種別のみ（すべて/未読/シリーズ新着）、
  カード（未読ドット・種別ラベル・本文・相対時刻）、空状態2種。
- 管理者向け「新着動画を再取得」は管理画面ができるまで残すが、ページ下部の
  枠線付き「管理者用」カードに隔離して目立たなくする。

### ステップ6: ログインと再生リスト登録
- `/login`: AuthLayout 上に §12.1 のうち email/password 部分（見出し・ラベル付き入力・
  パスワード表示切替・プライマリボタン・「アカウントをお持ちでない方」リンク）。
  新規登録は同ページ内のタブ切替で暫定対応（`/signup` は未実装）。
- `/playlists/new`: 1カラム、URL 入力＋注意文、再生リスト確認エリア（サムネ・タイトル・
  チャンネル・件数・既登録警告）、ゲーム選択ボタン＋検索モーダル、登録ボタン、
  完了画面（§6.1 のカード＋2ボタン）。

### ステップ7: 仕上げ
- 767px / 768px / 1400px 超の3幅で全ページを目視確認（ブラウザ自動化がこの環境に無いため
  ユーザー側で `npm run dev:stg` で確認。確認観点は各ステップの根拠仕様書の項目）。
- キーボード操作: ドロワー・モーダル・ドロップダウンの Esc で閉じる・フォーカストラップ・
  `aria-expanded` / `aria-modal`。
- `npm run lint` / `npm run build`。HANDOFF.md・Wiki 更新。
