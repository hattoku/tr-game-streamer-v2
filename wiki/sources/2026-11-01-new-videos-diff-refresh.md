# 新着動画の取得を差分にしてクォータ消費を減らす

PR #15（`4510ce4`、2026-11-01 main へ）。仕様は YouTube定期取得 v1.7 §7、データモデル v1.26、管理_ダッシュボード v1.9 §9.2。

## 経緯

日次の `/api/admin/refresh-new-videos` は、全公開再生リストの動画一覧を毎日全ページ取り直していた（1件約1.5ユニット）。5,300件規模だと1日約7,700ユニットで上限に届く。

## 変更（ユーザー決定: 登録済みの再生リストを ID 指定でまとめて見る）

- `playlists.list` に ID を50件ずつ渡して YouTube 側の動画数を確認（50件ごとに1ユニット）
- 前回の数（新設 `playlists.youtubeItemCount`）と違うものだけ `playlistItems.list` で取り直す（`lib/new-videos-refresh.ts`）
- 1回4,000ユニットまで。超えた分・クォータ切れ後の分は次の回へ
- YouTube で見つからない再生リストは結果に一覧で出すだけで、自動で非公開にしない
- 登録時にも `youtubeItemCount` を保存
- ダッシュボードの再取得カードに、直近の `batch_logs` から新着のあった再生リスト名と増えた本数・見つからない再生リスト・失敗を出す

試算: 5,300件・1日300件に新着で約7,700/日 → 約860/日。

## 注意

- 導入直後の初回は `youtubeItemCount` が無いので全件取り直しになる。管理画面のボタンからだと約60秒で 502 になるが、処理はサーバーで最後まで続く（Cloud Scheduler からは影響なし）
- 強制的に取り直したいときは `youtubeItemCount` を -1 にしてから再取得する（2026-11-14 に stg の Private video の掃除で使った）
