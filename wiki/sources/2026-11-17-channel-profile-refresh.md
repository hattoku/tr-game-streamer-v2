# 配信者の名前・アイコンを毎日の再取得で取り直す

PR #59（2026-11-17）。Notion チケット「配信者アイコンが古いままになっていないか確認する」。仕様は YouTube定期取得仕様書 v1.11（§4.4・§4.5・§8.4・§8.6）、コンテンツ収集機能仕様書 v4.6 §10.8、Firestore データモデル設計書 v3.1。

## 背景

配信者の名前とアイコンは一度保存すると取り直していなかった。仕様書にあった「週1のチャンネル更新バッチ」は作られておらず、YouTube API 規約の30日ルール（[[YouTubeデータの30日ルール]]）もチャンネル名・アイコンについては満たしていなかった。2026-11-17 時点で stg（17チャンネル）・本番（3チャンネル）とも古いアイコンはまだ無かった。

## 変更

- `lib/channel-profile-refresh.ts`: `refreshNewVideos` の ⓪ として巡回の前に実行
  - 対象は `channels`・`exploration_channels`・`playlists` が持つチャンネルIDすべて（形の崩れたIDは外す）
  - `channels.list` で50件ずつ（50件で1ユニット）。YouTube の値と違う名前・アイコンだけ書き換える
  - 掲載停止で YouTube 由来の項目を消した再生リストは対象外。通知と提案の写しは書き換えない
  - YouTube のエラーはその50件だけ飛ばし、クォータ切れはそこでやめる。取れた分は書き換える
  - 結果は `batch_logs.channelProfiles` と `channelProfileError`
- `components/ui/FallbackImage.tsx`: 配信者アイコンを出す13か所で、URL が読めないときは壊れた画像ではなく、アイコンが無いときの表示（灰色の丸か人のアイコン）。提案フォームのプレビュー（取得したての値を出すだけ）は対象外

## ユーザー決定

- 直し方は「毎日の巡回に組み込む」（週1の別バッチは作らない）

## 実装メモ（Claude の判断）

- 本番ではデータ移行も新しい定期ジョブも要らない
- E2E: `e2e/refresh-new-videos.spec.ts` に1件追加（実在チャンネルの名前とアイコンをずらし、読めないアイコンが代わりの表示になること、再取得で元に戻ることを確かめる）。stg で成功（2026-11-17）。再取得を動かす spec は同時に流さない
